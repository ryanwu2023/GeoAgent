# readiness-monitor — 美军战备表态 × 伊朗革命卫队表态 · 交叉验证监测

围绕**「美军战备到底处于什么状态」**这一问题，采集**美方（中央司令部 / 五角大楼 /
国防部）与伊方（革命卫队 / 官方媒体）的公开表态**，把双方同期说法机械配对，
输出可供大模型直接阅读的结构化 Markdown 日报。

```
readiness_monitor.py   主程序（纯 Python 标准库，零依赖）
config.json            数据源 / 词表 / 信号词典 / 议题锚点 / 发布主体映射
run.bat                一键运行（自检 → 抓取 → 产出）
tools/                 开发辅助探针与诊断工具，日常无需使用
state/seen.json        去重状态
output/                产出（按日期分目录 + LATEST 快照）
```

---

## 一、这份报告监测的是「表态」，不是「事实」

这是理解全部产出的**前提**，也是这个项目与普通爬虫最本质的区别：

| | 监测对象 | 证据地位 |
|---|---|---|
| 本项目 | 各方**公开说了什么** | 该方表态的**一手记录** |
| 不是 | 事情**真相是什么** | 需要独立来源印证 |

由此推出三条不可协商的规则：

1. **美方官方源与伊方官方源地位完全对称**。美国国防部 / 中央司令部与伊朗革命卫队
   通讯社在本系统中**同为 `T1`**。`T1` 的含义只是「这是该方表态的原始出处」，
   **不等于**其内容已获证实。任何涉己战果 / 战损表述都必须有独立来源才可引用。
2. **交叉验证只做机械配对**：同一议题词 + 同一周出现。程序**不做**语义一致性判断。
   `both_mentioned` 只说明双方都在讲这件事，**不等于**说法一致。
   唯一的例外是 `contradiction` —— 它由**明确的否认词**触发（见下）。
3. **每一条结论都能回原文**。每个信号都带 `context` 原文片段与链接，
   报告里的每个数字都标注来源、口径与信源等级。

## 二、快速开始

```bash
python readiness_monitor.py
```

**不要手动指定代理端口。** 程序自动读取系统代理并打印实际出口：

```
实际出口代理: http://127.0.0.1:7897
```

> ⚠️ 代理端口会漂移（实测同一天内 `7897` → `63299`）。写死端口的症状是
> 「所有源突然全挂」，与「被 CDN 风控拦截」**完全一样**，极难排查。

常用参数：

| 参数 | 说明 |
|---|---|
| `--selftest` | 离线自检（200 项，不联网）。改完词表**必须**先跑这个 |
| `--sources dod-news,dvids-centcom` | 只跑指定源 |
| `--days 30` | 覆盖回溯天数（默认取配置 `lookback_hours`） |
| `--backfill` | 时间窗拉到 `config.history.start`，建立更长历史 |
| `--show-all` | 不做折叠，附录列出全部记录（含被闸门挡掉的） |
| `--from-file feeds/` | 完全离线：读 `feeds/<源id>.xml` 或 `.json` |
| `--recompute` | **离线**按当前词表重算累积总档后退出（改完词表/解析器后必跑） |
| `--strict-tls` | 拒绝任何需要关闭证书校验的源（用于审计链路安全性） |
| `--as-of 2026-09-19 --out-dir /tmp/x` | 把本次当作某日、写入隔离目录（跨天落盘验证专用） |

## 三、产出

```
output/
├── LATEST.md                    主报告（人读 / 大模型读，10 节 + 附录）
├── LATEST-crosscheck.md         交叉验证明细（含「判定依据」）
├── index.md                     日期索引
├── ALL-records.jsonl            累积总档（按 id 去重、永不淘汰、带 first_seen）
├── _source_status.json          每源状态：HTTP、Server、解析条目/产出、源内最新距今天数、TLS 降级
├── _gate_audit.json             被闸门折叠的逐条留档 + **全量**折叠分类计数
├── _verify_last.json            最近一次回源对账结果（数字级门禁留痕）
└── <YYYY-MM-DD>/
    ├── readiness-digest-<day>.md   当日主报告
    ├── crosscheck-<day>.md/.json   交叉验证
    ├── weekly-<day>.json           按周 × 当事方信号矩阵
    └── records-<day>.jsonl/.json   当日窗口快照（**窗口内全部**，非仅新增）
```

### 工具（`tools/`）

| 工具 | 作用 | 何时用 |
|---|---|---|
| `verify_report.py` | **回源对账**：报告里每个数字从落盘数据独立复算并逐项比对；`--save` 落盘留痕 | 每次交付前（**唯一的数字级门禁**） |
| `audit_claims.py` | 词表**漏检**审计：按概念族回扫真实语料，找「该命中却没命中」 | 改词表后 |
| `audit_lexicon_fp.py` | 词表**假阳性**审计：列出每条实际匹配到的完整词形，揪出词形族造出的非词；`--suspicious` 只看可疑项 | 改形态族规则后 |
| `diag_crosscheck.py` | 交叉验证离线诊断（默认读**最新日期目录快照**并打印路径） | 交叉验证结果异常时 |
| `probe_*.py` | 分轮信源可达性探测（历史上用于发现 DVIDS 单位 feed） | 新增源时 |

主报告结构：`0 阅读须知` → `1 一页速览` → `2 数据源状态` → `3 美方表态` →
`4 伊方表态` → `5 交叉验证矩阵（议题 × 周）` → `6 同期对照：双方原文并列` →
`7 公开战备信号活跃度（按周）` → `8 声明类型分布` → `9 数据源与合规` → `10 已知偏差与误读边界`。

> §7 用「活跃度」而非「强度」是刻意的：该表衡量的是**公开表态的发声热度**，
> 不是任何一方真实战备水平的强弱。真实战备（战备等级、弹药库存实数、损失明细）
> 大多不公开，所以这个分值对「真实强度」是零信息。
> 表内「加权分」= 该周该方命中的各信号桶权重之和（权重在 config 的 `signals` 里人工设定），
> 仍属启发式参数，**不是可比的度量单位**。

## 四、交叉验证怎么判

议题锚点（13 个：`warship` / `tanker` / `hormuz` / `mq9` / `missile` / `airdefense` /
`carrier` / `exercise` / `fighter` / `submarine` …）× ISO 周归组，只用**通过展示闸门**的记录：

| 分类 | 触发条件 |
|---|---|
| `contradiction` 🔴 | 一方有 `action_claim`，另一方（或第三方转述其立场）在同周有 `denial` |
| `mutual_assert` 🟠 | 双方同周均宣称有行动效果（**不等于**说的是同一件事） |
| `mutual_denial` 🟠 | 双方同周均是否认 |
| `both_mentioned` 🟡 | 双方同周都提到该议题（**不等于**说法一致） |
| `us_only` / `iran_only` | 仅单方提及 —— 单方声明在获印证前不可作为事实 |

`contradiction` 是唯一带语义判断的分类，因此**必须给出触发它的具体条目**。
报告里每条 `contradiction` 都带一段「**判定依据**」，列出是哪几条记录、各自命中了
哪个词，供人逐条回原文核对。第三方转述的否认也算数 —— 实测这正是最典型的一类：

> `CENTCOM rejects Iranian claim that IRGC struck two US Navy destroyers`
> 这条既不是美方自己发的、也不是伊方发的，但它是标准的口径对撞。

## 五、数据源（v1.4.0：40 条登记，29 条启用）

**美方（T1）**：`dod-releases`（新闻稿）、`dod-transcripts`（简报逐字稿）、
`dod-news`、`whitehouse-actions`、`gao-reports`(T2)、`crs-reports`(T2)、
`dvids-centcom` / `dvids-afcent` / `dvids-marcent`（DVIDS 官方单位 feed）

**伊方（T1/T2）**：`sepahnews`（革命卫队官方通讯社）、`defapress`、`mashreghnews`、
`parstoday`、`irna-en`、`kayhan`、`mehr-en`、`isna-en`、`tehrantimes`

**第三方（T3）**：`centcom-gnews`、`farsnews-gnews`、`tasnim-gnews`、`irgc-gnews`（聚合器）、
`usni-news`、`defensenews-pentagon`、`breakingdefense`、`airspaceforces`、
`bbc-me`、`aljazeera`、`france24-me`

**T4（自媒体/社交平台）一律不采用。** 理由不是「不可信」，而是**不可核验** ——
没有可回溯的原始文件，一旦进证据表就会把整张表的可信度拉平。

### 5.1 信源等级 T1–T4

| 等级 | 含义 | 本项目 |
|---|---|---|
| `T1` | 官方一手（原始记录 / 法律文件 / 官方通稿） | dod-*、dvids-*、sepahnews、defapress、parstoday… |
| `T2` | 官方分析 / 审计（机构**估算**） | gao-reports、crs-reports |
| `T3` | 专业 / 商业媒体（**二手转述**） | usni-news、defensenews、bbc-me、各聚合器源 |
| `T4` | 自媒体 / 社交平台 | **不设采集器** |

两条最容易搞错的判定原则：

- **「官方机构」≠ T1**。GAO / CRS 发布的是**分析估算**，不是原始记录 → T2。
- **转述官方结论的媒体仍是 T3**。等级看的是**你手上这份材料由谁加工**，
  不是它引用了谁。要升到 T2，必须实际取到原始报告本身。
  例：`centcom-gnews` 只能拿到 CENTCOM 官网标题层 → 计 **T3**，
  而 `dvids-centcom` 能拿到 CENTCOM 公共事务办公室的完整 description → 计 **T1**。

### 5.2 被 CDN 或网络层挡住的源（停用留档，不删除）

| 源 | 状态 | 原因与替代方案 |
|---|---|---|
| `centcom-press-direct` | ⛔ 停用（**理由已更正**） | ~~centcom.mil 整站 403 `AkamaiGHost`~~ ← **误判，见下方更正框**。实测在存活出口 + 完整浏览器头下 PRESS-RELEASES 页返回 **200 / `text/html` / 293KB**，但该页是 **JS 渲染**、静态 HTML 里不含条目链接，故仍不能静态解析。改用 `centcom-gnews` 取标题层 + `dvids-centcom` 取一手内容。**不做风控绕过**（不引入无头浏览器） |

| `navy-rss` / `jcs-rss` | ⛔ 停用 | AFPIMS 的 `RSS.ashx` 在 Site id 不匹配时返回 **HTTP 200 空体**（不报错）。真实 Site id 未公开，反查失败 |
| `army-rss` | ⛔ 停用（**理由已更正**） | 原记「证书自签名」。**换存活出口复测后为 HTTP 404**（不再报证书错）→ 原结论很可能也是过期出口造成的假象；现按「**该路径 `army.mil/rss/` 本身不存在**（端点已变更）」停用。★ 本机经本地代理出网，**代理的 TLS 中间人会造成同样的『自签名』报错**，故不据此关闭校验 |

| `tasnim-direct` | ⛔ 停用 | DNS 无法解析（`gaierror 11001`）→ 用 `tasnim-gnews` |
| `farsnews-direct` / `presstv` / `khamenei-en` | ⛔ 停用 | 证书链不完整 / 缺中间证书 → 用 `farsnews-gnews` |
| `reuters-world` | ⛔ 停用 | 旧 RSS 通道已下线 |
| `dod-contracts-rss` | ⚪ 可达但不启用 | 合同公告是采购/授标（obligation 层），**口径**上不是战备表态，混入会污染信号统计 |

> ★★ **重要更正（2026-09-18 实测）**：上表部分标为「⛔ 被 CDN 拦截」的源，
> **并非站点风控，而是本地代理指向了一个过期端口**。换到存活端口后复测，
> `dod-releases` / `dod-transcripts` / `dod-news` / `usni-news` / `centcom-gnews` /
> `irgc-gnews` / `breakingdefense` / `tehrantimes` / `farsnews-gnews` / `tasnim-gnews` /
> `bbc-me` / `aljazeera` **共 12 个源全部返回 HTTP 200 + 真实 RSS**（25–100 条/源）。
>
> 修正后的口径：这些源应记为「**受本地出口影响（工程性）**」，**不是**「被站点拦截」。
> 「被该站拦截」是站点属性，需要在**多个不同出口**上都复现才能下结论。
> 详见 §6.13。

## 六、工程纪律（这些坑都踩过）

### 6.1 词表必须写**基础形**，既不能写屈折形，也不能写半截词根 ★★

匹配规则按**末词词尾**派生形态族（v1.5.0 起）：

| 词尾 | 派生 | 覆盖 |
|---|---|---|
| `-e` | `stem(?:e\|es\|ed\|ing\|ion\|ions\|ation\|ations)` | deplete → depleted / depleting / **depletion**；neutralize → **neutralization** |
| 辅音+`y` | `stem(?:y\|ies\|ied\|ying)` | casualty → **casualties**；supply → supplied |
| 其余 | `w(?:s\|es\|ed\|ing\|d)?` | destroy → destroys / destroyed |

**后缀必选**（`-e` 与 `+y` 分支）是刻意的：若允许空后缀，`site`→`sit`、`mine`→`min`、
`note`→`not` 会把普通词匹配成信号词。必选后原形由 `e` / `y` 分支覆盖，`sit` 独立出现不会命中。

**两类错误必须同时防**（它们是同一个问题的两个方向）：

1. **写屈折形**：写 `destroyed` 命不中 `Destroys` → 美方 `action_claim` 恒为空集
   → **交叉验证的 contradiction 恒为 0**（最该报的口径对撞一条都报不出来）。
2. **写半截词根**：为规避第 1 类而写 `deplet` / `casualt` / `attrit` / `neutraliz`
   / `annihilat` / `refut` / `deni` → 代价是**原形与 `-ion/-ation` 名词形全漏**。
   实测这三类词干长期躺在 `signals` 与 `relevance` 桶里，漏掉的恰恰是核心信号：
   `the depletion of key weapons stockpiles`（弹药耗尽）、`US casualties`（战损）、
   `Unable to Annihilate …`（打击声明）。而检查当时**只扫 claims 不扫 signals**，
   所以一直没报出来。

→ 自检里有 **13 条形态族覆盖** + **14 条派生规则行为断言**（合成样本，规则退化必红）
+ **2 条半截词根断言**（**扫全部词表**：signals / claims / relevance）
+ **1 条已知陷阱词根**断言。
→ 改完词表用真实语料回扫：`python tools/audit_claims.py`（覆盖缺口）
与 `python tools/audit_lexicon_fp.py --suspicious`（假阳性 / 词形族造出的非词）。

### 6.2 聚合器会伪造「当事方」

同一个聚合器源 id 下混着不同立场的媒体。实测未登记媒体（Janes / AzerNews / KTVN /
navalnews）会**继承源的默认当事方**，于是英国防务媒体、美国地方台都成了「伊朗官方表态」。
→ 未登记媒体一律归 `third` 并打 `outlet_unclassified` 标记。见 `config.outlet_map`。

### 6.3 展示闸门 = 信号命中 **且** 主题锚定

只有「信号」不够：`targeted` 会命中「住房补贴**定向**发放给原住民社区」。
闸门要求再落到当事方/地区词（anchor）或军事领域词（domain），或该源本身是国防主题源。
→ 展示与统计**共用同一个函数**，避免「正文看不到、却进了计数」。

### 6.4 落盘合并源必须是「窗口内全部」，不是「仅新增」

跨天时 `output/<今天>/` 不存在，读回旧记录读到空，而旧记录又已被划为「非新增」
→ 两头都不在，快照从 22 条塌成 2 条。头部**同时**标注「本次新增 N 条」与「当前快照 M 条」。

### 6.5 词表 / 解析器改动必须**全量回填**累积档 ★

累积档里掉出时间窗的记录不会再次被抓取。若不在落盘时用**当前**词表重算，
档案里会同时存在「旧词表算的」和「新词表算的」两种派生字段，趋势与交叉验证
拿两套口径混着算，而输出**看起来完全正常**。

→ 每条记录带 `cfg_ver`（词表 + 解析器版本的指纹）；`write_all_accumulated` 落盘前
对全档回填；`--recompute` 可离线修复。**改解析逻辑时必须递增 `PARSE_VER`。**
（实测：`strip_tags` 的 HTML 反转义顺序修复后，靠这个机制才把 232 条历史记录
里残留的 `&lt;a href=…&gt;` 清干净。）

### 6.6 图片素材序号会把一条报道变成五条 ★

DVIDS 等官方影像源把一条报道拆成「标题 `[Image 1 of 5]` … `[Image 5 of 5]`」，
描述几乎相同、链接不同。不处理的话一条演习新闻变 5 条记录，
**虚增美方条数** —— 而美方偏少正是本项目最需要警惕的偏差方向。

→ `title_key()` 抹掉素材序号后缀，抓取期与合并期各做一次去重，
跨源同题（聚合器转述 DVIDS）也会在此归并，并保留**信源等级较高**的一条。

### 6.7 验证工具自身也必须被验证

诊断工具默认取**最新日期目录的快照**，不是累积总档 —— 两者不是一回事
（累积档永不淘汰、含历次遗留），拿错文件会得到与正式产出不一致的结论。
任何核对工具都**必须把实际读取的路径打印在输出首行**。

### 6.8 抽样截断只能截「明细」，绝不能截「计数」 ★

报告 §1 会报「折叠 N 条，其中 A/B/C 三类各多少」。曾经的实现是：先把折叠记录取
**前 400 条**做明细留档，然后**从这个 400 条明细里现算分类**，再把结果当全量印出来 ——
于是「864 条折叠」被拆成 `252 + 142 + 6 = 400`，**加总都不自洽**；
真实的「有战备信号但未锚定」是 **9 条**，报告写 **6 条**。
而这一类恰恰是「词表/锚点收紧过头」的唯一线索，被压在抽样外就等于消失。

→ `classify_folded()` 在**全量**上计数（写进 `_folded_breakdown`），明细才受
`FOLD_SAMPLE_LIMIT` 限制；且 `no-topic-anchor` 类**不受抽样上限约束**。
→ `verify_report.py` 会校验「分类加总 == 折叠总数」，不自洽直接判失败。

### 6.9 对撞的方向必须配对：谁的主张被谁否认 ★

`contradiction` 的判定条件是**配对**的，不是「有宣称有否认就算」：

- 美方主张 `au` ← 被伊方否认 `di` 或第三方否认美方 `td_us`
- 伊方主张 `ai` ← 被美方否认 `du` 或第三方否认伊朗 `td_iran`

曾经的实现把两个第三方变量**挂反了**（`au` 配 `td_iran`），于是
「美方宣称 + 第三方否认**伊朗**的说法」这种并不矛盾的组合被判成对撞（假阳性）。

同时 `denial_target()` 判「被否认的是谁」必须看**否认动词之后**的实体、
且窗口内取**最早出现**的一方 —— 用「伊朗优先」的整句匹配时，
`Iran denies US claims that …` 会被判成「否认伊朗」，方向整个反了。
两侧实体词表也必须**等宽**（美方侧曾漏掉 `US`，只认 `US Navy`/`US military`，
而伊朗侧一个 `iran` 词根就覆盖 Iran/Iranian/Iran's，一宽一窄必然偏向判成伊朗）。

### 6.10 配置项与实现必须对得上（`per_source_max` 曾完全失效）

代码曾写成 `items[:max(PER_SOURCE_MAX, len(items))]` —— 而 `max(60, len)` 恒等于
`len`，于是 **`per_source_max: 60` 是个从没生效过的承诺**（实测 `centcom-gnews`
解析 300 条全采）。这类「配置撒谎」不会报错，只会让排查者按错误前提推理。

现改为真正生效的截断，但默认值取 **0（不限）**：截断按 feed 顺序取前 N 条，
会**静默丢弃窗口内记录**，与「合并源 = 窗口内全部」直接冲突。
启用后 §2 会在该源标注「⚠️截断」。

### 6.11 「解析条目」≠「产出」：日志与报告的口径必须同源

§2 的条数曾是 feed **解析出**的条目数（`entries`），而读者会当成「该源贡献了几条」。
现拆成两列：**解析条目** 与 **产出**（窗口过滤后实际产出）。

同理，日志里的「被折叠 N 条」曾用 `len(本轮抓取) - len(全快照的展示数)` 计算 ——
两个数字不同源，日志报「84 进入 / 611 折叠」，而报告 §1 写「折叠 1019 条」，
**日志与报告互相打脸**。现统一在 `merged` 快照上统计，并打印
`displayed + folded = merged` 的自洽等式。

### 6.12 验证清单

交付前跑完这六步：

1. `python readiness_monitor.py --selftest` → **234 项全绿**
2. `python tools/audit_claims.py` → 词形族无漏检（或有意识的排除项）
3. `python tools/audit_lexicon_fp.py --suspicious` → 无词形族造出的非词（`ward`/`aired` 之类）
4. **同日重跑** → 快照条数不塌
5. **换日期 + 换全新输出目录**再跑 → 跨天不丢窗口内历史

   只测 ④ 会完全掩盖 ⑤ —— 两者在「同日」场景下等价。
6. `python tools/verify_report.py --save` → **回源对账**：报告里每个数字都能由落盘数据

### 6.13 代理出口：端口会漂移，而「代理坏了」会伪装成「被风控拦截」★★

本项目**默认自动探测系统代理**（Windows 下 `getproxies()` 读注册表），
每次运行都打印实际出口。为什么不能写死端口：

本机代理端口会**漂移**（代理客户端重启后 `7897` → `51681` 之类），
而**旧端口常常仍在 listen** —— TCP 可连接，但无法转发：

```
51681: accept() 成功 → CONNECT 上游失败 → Tunnel connection failed: 502
7897 : 正常 → HTTP 200 + 真实 RSS
```

于是 `--source-status` 里出现两种「像风控」的报错，**实际都是代理问题**：

| 报错 | 误判为 | 真实原因 |
|---|---|---|
| `Tunnel connection failed: 502 Bad Gateway` | 站点不可达 | 代理不通 |
| `403 AkamaiGHost` / `403 cloudflare` | 被 CDN 拦截 | **出口 IP 被拦**（换出口即 200） |

> 两种成因的报错**肉眼无法区分**。本次实测 12 个源失败，其中 6 个报 502、6 个报 403，
> 换端口后**12 个全部 200**。若不查出口，就会把本地网络故障写进报告，
> 变成「美方官网被 CDN 整站拦截」这种**归因错误**。

**归因三步（顺序不能反）：**
1. 打印 `getproxies()` 实际出口，与上次成功抓取时的出口比对；
2. 用一个**已知可通的第三方 URL** 对照探测 → 区分「全线不通」与「单站不通」；
3. **换出口复现一次**再写结论：换出口仍 403 → 站点侧；换出口就通 → 出口侧。

排障时可用 `--proxy` 显式覆盖（**仅供排障**，不要写进脚本/快捷方式）：
```bash
python readiness_monitor.py --proxy http://127.0.0.1:7897
```
自检里已加断言：未覆盖时 opener 必须跟随系统探测结果，覆盖时注入指定出口。

## 七、阅读报告时的硬约束

- **不要跨方比条数**。两侧的**可采集性不对等**（见 §10 偏差 9）：CENTCOM 官网被 CDN
  拦住只能取标题层、海军与参联会两条线缺失，而伊方有多个可直接抓取的官方源。
  比条数会**系统性高估伊方表态量**。
- **`—` 不是 `0`**。未收录的周一律渲染 `—`，表示「这段我们没在收」，不是「没有发生」。
- **信号分值是启发式**（§7 称「加权分」），衡量的是**公开发声活跃度**；
  不可跨周直接比大小，更不可当作任何一方的**真实战备强度**或战力对比。
- **周粒度粗于事件**：同一周内相隔数天的两次事件会被并入同一行。

## 八、合规底线（不可协商）

只抓**公开**内容：政府机构 RSS/API、官方通讯社 RSS、公共媒体 RSS。
遵守 robots.txt；不抓需登录内容；**不做任何风控绕过**
（不模拟浏览器指纹、不绕 Cloudflare/Akamai 挑战）。
被拦截的源**停用留档**并标注原因，不用绕过手段强行取数。
`--from-file` 提供完全离线的退路：用浏览器另存内容即可合法完成解析。
