# taco-monitor —— TACO 压力指数每日监测

把「地缘政治风险 → 资产配置压力」这件事，做成**每天自动跑一次、可回源对账**的爬虫。

口径来自东吴宏观《TACO 压力指数》数据底稿，公式已逐格反解并验证到浮点极限
（S 列 `max_abs_diff = 1.22e-09`，T 列 `1.75e-10`）。**指数输入全部换成公开数据源**。

**当前口径 = 东吴原始的 5 因子**（2026-09-23 起）。霍尔木兹通行量降级为
**观察指标**：抓取、落盘、在看板与报告里单独展示，但**不加权、不取 z、不进 S、不进 T**。
汇率（里亚尔）因子已按用户要求**整体移除**。

> **为什么不做成因子**：底稿 F 列虽有该序列，但**反解确认 0 个公式引用它** ——
> 东吴的 TACO 只用 5 个因子；而且该序列 2026-03 起处于**结构性水位断裂**（§1b），
> 任何「N 日变动」类变换都会退化成断点噪声，甚至给出与水位相反的方向。
> **能看，不能算。**

两者可以随时切换（`config.json` 的 `extended_factor.mode`）：

| mode | 行为 | 指数 |
|---|---|---|
| **`observe`（当前）** | 只抓取 / 落盘 / 展示霍尔木兹水位 | **5 因子**，与东吴原版逐格对账 |
| `composite` | 作为第 6 因子并入，两套口径并列 | 5 因子 + TACO-6 / TACO-6L |
| `extended_factor_2.enabled=true` | 再把里亚尔并入 | 再 + TACO-7 / TACO-7L |

```
python run.bat                              # 一键三步：自检 → 抓取算指数 → 完成
python taco_monitor.py --selftest           # 离线自检（不联网，176 项）
python taco_monitor.py                      # 真实抓取 + 算指数 + 出产物
python taco_monitor.py --from-file output/2026-09-21/raw    # 用留档载荷离线重放
python taco_monitor.py --as-of 2026-09-20 --out-dir output/_probe   # 跨天落盘验证
python tools/acceptance.py                  # 端到端验收（自检+真实跑+幂等+产物+对账）
python tools/regress.py <旧.csv> <新.csv>    # 口径变更回归比对（见 §9）
python tools/regress.py --list              # 列出可用的归档快照
install_task.bat                            # 注册每日计划任务（09:10）
install_task.bat status | remove            # 查看 / 卸载
```

## 1. 指数构成（5 个指数输入 + 1 个观察指标 + 2 个油价交叉校验）

| 底稿列 | 指标 | 公开数据源 | 角色 |
|---|---|---|---|
| C | 美国 10 年期国债收益率 | FRED `DGS10` | **指数输入** |
| D | 1 年期通胀互换 USSWIT1 | **FRED `T5YIE`（替代）** | **指数输入** |
| E | 特朗普支持率（RCP 均值） | Silver Bulletin / Datawrapper `kSCt4` | **指数输入** |
| G | 道琼斯工业指数 | FRED `DJIA` | **指数输入** |
| H | 布伦特原油（**ICE 期货首月连续**） | Yahoo Finance `BZ=F` | **指数输入** |
| F | 霍尔木兹日通行量（总艘次） | IMF PortWatch ArcGIS `chokepoint6` | **观察指标 —— 不进指数**（§1.1） |
| H' | 布伦特原油（EIA 现货 FOB） | FRED `DCOILBRENTEU` | 仅交叉校验，不入指数 |
| H'' | 布伦特原油（新浪外盘期货 `OIL`） | 新浪财经 | 仅交叉校验，不入指数 |
| — | ~~德黑兰自由市场 USD 卖出价（里亚尔）~~ | ~~Bonnast~~ | **已移除**（§1.1c） |

**TACO = 5 因子等权 z 分数合成（S）后再取 7 日均线（T）。单位是 z，不是概率、不是预测。**

> 表格里标注「观察指标」的 `F` 与已划掉的里亚尔列**都不参与 S/T**。
> 把它们列在表里是为了说明「数据抓了、放了，但没进指数」—— 不是指数构成。
> 指数输入严格只有 C / D / E / G / H 五个。

### 1.1 霍尔木兹通行量：观察指标（**不进指数**）

底稿 F 列虽有数据，但**反解确认 0 个公式引用 F**，东吴的 TACO 只用 5 个因子。
本项目把它保留为**观察指标**：

```text
指数公式（只有这 8 行参与计算）
  I = C - C[-31]        10Y 美债收益率 31 日变动
  J = D - D[-31]        1Y 通胀互换 31 日变动（T5YIE 代理）
  K = -(E - E[-31])     支持率 31 日变动【取负】
  L = 1/(G/G[-31] - 1)  道指涨跌幅【取倒数】
  M = H - H[-31]        布伦特 31 日变动
  N..R = expanding z(I..M)
  S = mean(N..R)        5 因子等权合成（**只有这 5 个**）
  T = 7-row MA of S     TACO 指数

观察指标（不进任何合成）
  F = TRHBCCCD          霍尔木兹日通行量（总艘次），前值填充到既有日历网格
                        -> 只落盘、只展示；不取 z、不进 S、不进 T
```

**「不进指数」是被断言保护的，不是靠文档承诺**：

- **自检**（离线，`--selftest`）：去掉观察序列后，`S` / `T` / 5 个 `z` 必须**逐点完全相等**；
  且结果里不得出现任何 `Nt/Ntz/S6/T6/Ltz/S6L/T6L`。
- **对账**（每轮，`verify()`）：结果里不得有第 6/7 因子派生量；落盘列契约必须正好 14 列；
  用 `S = mean(5 个 z)` 逐点复算 —— 若观察列偷偷进了合成，多一项，均值必然对不上。
- **验收**（产物级，`tools/acceptance.py`）：回读**落盘 CSV**，逐行验 `composite_S = mean(5 个 z)`；
  并检查 CSV **不得出现** `z_transit` / `TACO6_Index_T6` / `TACO7_*` 等列
  ——「说不进指数却算了」比列缺失更严重，所以两个方向都查。
- **数据层**：观察记录写入 JSONL 时带 `role: "observe"` 与 **`in_index: false`**，
  下游按 `series=="HORMUZ_TRANSIT"` 取水位永远成立，不必先判断这轮是什么模式。

**模式开关是一个闭合枚举，不是两个布尔。** `extended_factor.mode` 只接受
`observe` | `composite`，非法值直接退出；`compute()` 里 `observe_factor` 与
`extended_factor` **互斥**，同时给会抛 `ValueError`。两个独立开关会产生
「观察=true 且 并入=true」这种自相矛盾的组合，而它的表现是「指数被一个声称
不参与合成的列污染了」—— 最难排查的一类，所以在配置层就消灭掉。

**观察指标的两个日期必须分开报**：`F` 经前值填充后其末值日期 = 网格末日，
看起来「今天就有数」；而霍尔木兹是 AIS 事后汇编、滞后 4~7 天，**真实观测日总是更早**。
报告与看板同时给出「网格末日（前值填充）」与「真实观测日（源滞后 N 天）」，
不把「前值填充」当成「今天的水位」。

### 1.1b 可选模式：第 6 因子并入（TACO-6 / TACO-6L）—— **当前未启用**

> **本节描述的是 `extended_factor.mode = "composite"` 时的行为。**
> 当前配置是 `observe`（§1.1），霍尔木兹只作观察指标。这套代码与断言仍完整保留，
> 改回 `composite` 即可复现；`output/_archive/` 留有上一版 7 因子的产物快照。

底稿 F 列虽有数据，但**反解确认 0 个公式引用 F**，东吴的 TACO 只用 5 个因子。
若把 F 列作为第 6 因子并入，**因为该序列水位断裂（§1b），必须同时输出两套口径
—— 谁都不隐藏、不替使用者挑**：

```text
共同：F = TRHBCCCD 通行量（总艘次，前值填充到既有日历网格）

口径 A（31 日变动）→ TACO-6          回答「比一个月前多还是少」
  Nt  = -(F - F[-31])    通行量降 = 供给压力升，故取负（与支持率 K 同向）
  Ntz = expanding z(Nt)
  S6  = mean(N..R, Ntz)  6 因子等权
  T6  = 7-row MA of S6   TACO-6

口径 B（水位）→ TACO-6L              回答「现在是正常水位的百分之几」
  Ltz = -z(F)            水位低 = 压力贡献高
  S6L = mean(N..R, Ltz)
  T6L = 7-row MA of S6L  TACO-6L
```

> `z` 对负号等变（`z(-x) = -z(x)`），所以「先取负再 z」与「先 z 再取负」完全等价。

**为什么必须两套都出**（这是本项目的核心判断，不是工程师的洁癖）：

| | 口径 A（31 日变动） | 口径 B（水位） |
|---|---|---|
| 若断点是**真实信号**（海峡真的被封） | ❌ 失败：低位平台内的小波动读成「压力下降」，方向全错 | ✅ 正确：水位只有正常 6% → 压力高 |
| 若断点是**数据假象**（口径变更/信号丢失） | ✅ 相对稳健：不把假断点当成真实压力 | ❌ 失败：注入一个虚高的压力值 |
| 水位**未断裂**时 | ✅ | ✅ 两者大体重合，可互为交叉校验 |

而**「断点到底是真是假」公开数据无法区分** —— 所以两套都输出，把这个判断显式交回给使用者。

**纪律**：第 6 因子（两套口径共用 `F`）必须**前值填充到既有网格**，绝不参与网格构造。
若它带来 E 列没有的日期，面板长度会变，扩张窗口 z 分数整体漂移，已验证的 5 因子结果
就被改掉了。自检里有专门断言：稀疏输入下 `n_days` / `S` / `T` / 5 个 z **逐点完全不变**，
且两套 6 因子口径互相不得污染对方的 `S6` / `T6`。

### 1.1c 可选模式：里亚尔汇率并入（TACO-7 / TACO-7L）—— **已移除**

> **2026-09-23 按用户要求整体移除**：不再抓取、不再落盘、不再参与任何合成。
> `config.json` 里 `extended_factor_2.enabled=false`、`bonbast_crawler.enabled=false`，
> 定义（含单位证据 `_unit_evidence` 与端点说明）保留供追溯与随时恢复。
> 本节记录当时的实现与硬限制，供将来重新启用时参考。

在（当时的）第 6 因子之上再并入**德黑兰自由市场 USD 卖出价（里亚尔）**，
产出 **TACO-7 / TACO-7L**。同样是两套口径并列，同样不改动 5/6 因子的任何一个数。

```text
F2   = Bonnast USD 卖出价（里亚尔，前值填充到既有网格）
       —— 接口原值是托曼，页面明写 1 Toman = 10 Rials，故一律 × 10

口径 A（31 日变动）→ TACO-7
  Nt2  =  (F2 - F2[-31])   汇率上行 = 里亚尔贬值 = 压力升，故【不取负】
  Ntz2 = expanding z(Nt2)
  S7   = mean(N..R, Ntz, Ntz2)   7 因子等权（5 基础 + 霍尔木兹 + 里亚尔）
  T7   = 7-row MA of S7

口径 B（水位）→ TACO-7L
  Ltz2 =  z(F2)            水位高 = 里亚尔弱 = 压力贡献高，故【不取负】
  S7L  = mean(N..R, Ltz, Ltz2)
  T7L  = 7-row MA of S7L
```

> ⚠️ **符号方向与第 6 因子相反，最容易抄错。** 本项目所有因子的统一约定是
> 「压力上升 → 因子上升」。霍尔木兹是通行量**下降**代表压力上升，故取负；
> 里亚尔是汇率**上升**（贬值）代表压力上升，故**不取负**。约定一致，方向相反。

**必须知道的硬限制 —— 这个因子天生长不了：**

| 读数 | 有效天数 | 有效区间 | 为什么短 |
|---|---|---|---|
| TACO-7（31 日变动） | **28 / 609** | 2026-08-25 .. 2026-09-21 | 需 `F2` 与 `F2[−31]` 同时存在，白吃 31 天回看 |
| TACO-7L（水位） | **59 / 609** | 2026-07-25 .. 2026-09-21 | z 只需 2 个样本，故几乎与数据源等长 |

Bonnast 的 `/graph` 接口**固定只返回 60 天**（实测 `?range=1y` / `?period=1y` 均无效，
`/graph/usd/365` 返回 404）。ffill 到 609 天网格后：
- **源区间 61 天 ≠ 上网格 60 天**。源里含今日（盘中仍在成形）的报价，而既有网格的
  末日锚在基础序列上（通常 = 上一交易日），按 ffill 纪律这一天的值会被丢掉。
  日志分别报「源区间」与「上网格后实际天数」，不许把前者说成「有效」。
- 本地 `output/history/BONBAST_USD_sell_rial.jsonl` 随日更累积，**这是把历史攒长的唯一途径**
  —— 也正是把它做成日更任务的理由。跨指数比较（如「TACO-7 比 TACO 高多少」）必须
  只在重叠窗口内做；把全长曲线画在一张图上会得到错误印象。

**抓取机制**（无登录、无密钥）：首页内嵌一次性令牌 → `POST /json` 取快照；
`/graph/usd` 取近 60 天日频。两条链路做同源交叉校验（容差 5%）。
令牌失效响应实测是 `{"rest":"1"}`（站点侧拼写），**只判 `"reset"` 会把它当合法空载荷、
静默丢掉重试** —— 这个坑踩过。

### 1.2 三层写盘策略（为什么标准名永远是新的）

`atomic_write_bytes` 按「最安全 → 最可用」三级降级，**绝不因为文件被别人开着而中断整轮**：

| 档 | 做法 | 代价 | 记账 |
|---|---|---|---|
| 1 | 写 `.tmp` 后 `os.replace`（原子），带指数退避重试 | 无 | — |
| 2 | **就地覆盖**（`r+b` + truncate + fsync） | 失去原子性（强杀可能写半截） | `INPLACE_WRITES` |
| 3 | 退写 `<名>.locked-<时间戳><ext>` | 换了文件名 | `WRITE_FALLBACKS` |

第 2 档不可省：**「rename-over 被拒」与「文件被独占」是两种不同的状态**。
2026-09-22 实测 `output/taco-latest.csv` 反复 `WinError 5`，而同目录的 `taco_index.xlsx`
与新建文件都能正常 replace，机器上**没有任何 WPS/Excel 进程**，且对该 CSV
`open('r+b')` 明明成功。只靠第 3 档会让**标准名长期停在旧内容上**（当时停在 09:43 的
17 列旧版，而实际数据已是 27 列）—— 而标准名正是下游与肉眼读的那个。
宁可牺牲原子性，也不能让标准名是错的。

旧降级副本由 `_prune_fallbacks` 清理（只留最新），**删除失败会记账**（`PRUNE_FAILURES`）
而不是静默吞掉 —— 静默会让「清理被拦住」和「本来就没什么可清」在外部看起来一模一样，
本项目因此在排查时误判过一次。

## 1b. ⚠️ 霍尔木兹通行量的结构性水位断裂（2026-09 实测）

**这是本项目最重要的一条数据质量发现。**
在当前 `observe` 模式下它**不影响指数**（霍尔木兹不进 S/T），但它是**为什么不能
把这条序列做成因子**的直接证据，也是「抓到了但数字是错的」这一类静默错误的标本。

IMF PortWatch 的 `chokepoint6`（**已核实 `portname` = "Strait of Hormuz"**）`n_total`：

| 月份 | n_total 中位数 | 相对基准 |
|---|---|---|
| 2025-08 ~ 2026-02 | 55 ~ 95 艘次/日 | 86% ~ 148% |
| **2026-03** | **2** | **3%** ⚠️ |
| 2026-04 ~ 2026-09 | 4 ~ 8 艘次/日 | 6% ~ 13% ⚠️ |

**2026-03 断崖式下跌，此后 6 个月没有恢复。**

### 怎么判断这是「数据问题」而不是「运量信号」

三次独立验证：

1. **三字段同步塌**：同一图层的 `n_total`、`n_tanker`、`capacity`（载重吨）
   一起塌掉约 95%。真实的运量下降会先体现在船型结构上，不会让**计数与吨位等比例**崩掉。
2. **只有霍尔木兹断了**（关键对照）：同期同图层的

   | 海峡 | 2026-02 | 2026-03 | 之后 |
   |---|---|---|---|
   | 苏伊士 | 41 | 41 | 40 ~ 42 |
   | 曼德海峡 | 37 | 36 | 27 ~ 37 |
   | 马六甲 | 238 | 221 | 212 ~ 225 |
   | 台湾海峡 | 221 | 226 | 226 ~ 259 |
   | 巴拿马 | 32 | 34 | 29 ~ 35 |
   | **霍尔木兹** | **78** | **3** | **4 ~ 13** |

   所以**不是**全局数据管道故障，是霍尔木兹**单点**的口径/覆盖问题
   （区域性 AIS/GPS 干扰导致漏计，或图层口径变更 —— 公开数据无法区分这两者，属**推断**）。
3. **实取复现**：`curl` 直连 ArcGIS 端点重取，与留档载荷逐日一致，排除了「留档坏了」。

### 对指数的影响（`composite` 模式下），以及因此加装的三道防线

> 以下读数取自 **`composite` 模式**（第 6 因子并入）时的实测，是「断裂会让因子失效」
> 的证据。**当前 `observe` 模式下 TACO 恒为 5 因子，不受此影响。**

水位断裂后，「31 日变动」退化成**断点之后的小噪声**。2026-09-21 实测两套口径**符号相反**：

| 口径 | 第 6 因子 z | 读作 | TACO 读数 |
|---|---|---|---|
| A · 31 日变动 | **−0.274** | 「通行量回升 → **压力下降**」 | TACO-6 = **0.3628** |
| B · 水位 | **+1.174** | 「水位只有正常的 6% → **压力高**」 | TACO-6L = **0.6063** |
| （5 因子，东吴口径） | — | — | TACO = **0.4913** |

`TACO-6`（0.3628）与 `TACO-6L`（0.6063）**分别落在 5 因子 TACO（0.4913）的两侧** ——
这正是两套并列的价值：任何单一数字都会给出一个确定的方向感，而真相是「不知道」。

- **防线 20 —— 水位断裂守卫**：`level_break_check()` 比较「近 45 日中位数」与
  「基准期中位数（366 天窗口，剔除最近 90 天）」，比值超出 `0.4~2.5` 即判定断裂。
  样本不足时返回 `None`（不是 `False`），避免新源在暖机期被误报。
  断裂时报告 §1 / §5a、看板顶部横幅、Excel READ ME 全部显著披露，并在对账里出 **WARN**。
- **防线 21 —— 变动量与水位强制并列**：报告 §5a 输出月度中位数表，
  让「现在是正常的百分之几」永远和 31 日变动一起出现。**只看变动，永远看不见断裂。**
- **防线 22 —— 姊妹序列对照**：见上文第 2 步。这一步把「数据源整体坏了」与
  「某个序列坏了」彻底分开，否则无法决定该换源还是该加防护。

> 这两条经验已回报进 `crawler-source-triage` skill：**「抓到了但数字是错的」**
> 里最隐蔽的一类 —— 序列没缺、没 NaN、格式全对、还在天天更新，
> 但**水位**已经换了量级。判据是「**同一数据源里本该无关的姊妹序列是否同时断裂**」。

## 2. 关于 USSWIT1：为什么用替代源，以及怎么选的

底稿 D 列是彭博终端专有的 **1 年期通胀互换（USSWIT1）**，无公开日频等价物。
本项目**明确不使用底稿 D 列的真实值**，改用公开替代源。

选替代源不是拍脑袋，而是拿底稿真实值当基准，在 **423 个重叠观测**上比较
「31 日差分序列」的相关系数（因为公式里用的是差分，不是水平值）：

| 候选 | 口径 | 频率 | 31 日差分相关 | 采用 |
|---|---|---|---|---|
| **T5YIE** | 5Y 盈亏平衡通胀 | 日频 | **+0.637** | ✅ |
| T10YIE | 10Y 盈亏平衡通胀 | 日频 | +0.535 | |
| MICH | 密歇根 1Y 通胀预期 | 月频 | +0.424 | |
| EXPINF1YR | 克利夫兰联储 1Y 预期通胀 | 月频 | +0.351 | |
| T5YIFR | 5Y5Y 远期盈亏平衡 | 日频 | +0.084 | |
| DGS1 | 1Y 名义国债收益率 | 日频 | −0.131 | |
| DFII5 | 5Y TIPS 实际收益率 | 日频 | −0.509 | |

反直觉但重要的结论：**月频的「1 年期」口径（MICH / EXPINF1YR）反而不如日频的 5Y 盈亏平衡**。

与日频目标序列的节奏对不上。频率匹配比期限匹配更重要。

## 3. 公式（东吴口径）

```
I = C - C[-31]               10Y 美债收益率 31 日变动
J = D - D[-31]               1Y 通胀互换 31 日变动（本项目用 T5YIE 代理）
K = -(E - E[-31])            特朗普支持率 31 日变动，【取负】
L = 1/(G/G[-31] - 1)         道指 31 日涨跌幅的【倒数】
M = H - H[-31]               布伦特原油 31 日变动
N..R = expanding z(I,J,K,L,M)  扩张窗口 z 分数
S = mean(N:R)                5 因子等权合成
T = 7-row MA of S            TACO 指数（7 日移动平均）
```

### 三个致命细节，少一个就复现不出来

1. **网格是日历日，不是交易日。** 周末/假期沿用前一交易日值（前值填充）。
   底稿行号差 31 即日历 31 天。若只保留交易日，31 天会变成约 21 个观测，全错。
2. **z 分数是扩张窗口，不是滚动窗口。** 起点固定在第 31 个索引，窗口随时间右扩。
   用滚动窗口会得到一条完全不同（且通常更好看）的曲线。
3. **7 日 MA 必须跳过空值**（Excel `AVERAGE` 语义）。工作簿 S 列因支持率分项起始晚
   而从第 60 行（idx 55）才有值，MA 窗口起点随之是 55。若用「窗口内任一为空则整窗为空」
   的语义，复现误差会跳到 0.4 量级。

## 5. 数据质量防线（每条都对应一次真实踩坑）

32 条防线（编号 1~29，含 12b / 19b / 19c 三个补丁级条目），
按「先测后用 → 形状识别 → 语义正确 → 落盘可信」排列。
其中 **#20/#21/#22 是「水位断裂」三件套** —— 针对的是最隐蔽的一类错误：
**序列没缺、没 NaN、格式全对、天天更新，但水位已经换了量级。**
**#25/#26/#27 是「不进指数」三件套** —— 观察指标不进合成，靠断言而非文档承诺。
**#28 是回归比对自身的判据陷阱** —— 不固定输入，源修订会伪装成代码回归。
**#29 是「失败轮不许污染标准名」** —— 门禁中止必须只写状态、不碰产物；
顺带把两个长期只写在配置里、代码从未读取的**死配置**开关接上。
**#12b 是验收自身的一个坑**：判产物好坏要判「实际生效的那份文件」，不是标准文件名。

| # | 防线 | 为什么 |
|---|---|---|
| 1 | **先测后用，配置强制** | 每个源必须带 `probe_evidence.ok=true`，自检会拒绝无证据的条目 |
| 2 | **UA 阶梯** | 实测 FRED 封浏览器 UA（`Mozilla/5.0`/Chrome → 0 字节超时），放行 `curl/*`；Datawrapper 反过来封 `Python-urllib/*`（403）。**没有单一 UA 能让所有源满意**，失败表现像网络问题实为 UA 指纹。默认用 `curl/8.19.0`（三源全通），失败逐档降级，实际生效 UA 写进报告 |
| 3 | **出口实测 + 按源覆盖** | 本机环境变量注入了 `http_proxy`/`https_proxy` 指向 `127.0.0.1:56716`——端口在监听但**已无出口**。curl/urllib 默认都会读它，导致全部 0 字节超时，症状与「被 CDN 风控」一模一样。程序显式 `--noproxy '*'` 绕过，并先实测直连。**2026-09-23 补充**：Yahoo 与其余源出口策略相反 —— 直连 Yahoo 被网络网关返回 HTML 拦截页（含「无法访问」字样，HTTP 非 200），必须走 Windows 系统代理（`HKCU\...\Internet Settings`，实测 `127.0.0.1:7897`）。故在 config 中按源声明 `egress`：`"proxy"`（读系统代理）/ `"direct"`（强制不走）/ 缺省（沿用全局直连）。拿不到系统代理时显式报 `egress-proxy-required-but-no-system-proxy`，绝不静默降级成直连 |
| 4 | **假 200 识别** | 按**内容**判定，不看状态码：空 body、JS 挑战页、HTML 冒充 CSV、ArcGIS `error` 响应全部拦下 |
| 5 | **同主机限速 1.2s** | 实测并发 8 个请求后全部挂到超时。限速是正确性要求，不是礼貌 |
| 6 | **纪元零值哨兵** | ArcGIS 缺日期给 `1970-01-01` / epoch 0；解析器对 0 返回 None 并计入 `dropped` |
| 7 | **降序响应** | ArcGIS 按日期降序返回，取首行会拿到最新——但 FRED 是升序。解析器统一排序后再取末条 |
| 8 | **列名陷阱** | FRED 列名不符时直接报 `value-col-mismatch` 并列出实际列名，不静默读错列 |
| 9 | **小基数百分比禁令** | 艘次计数不做 N 期百分比变化（1→8 艘次 = +700%，会把噪声渲染成「升级」） |
| 10 | **修订记账** | 同日期新值覆盖旧值但逐条记账（`n_revised`），累积历史只增不减 |
| 11 | **回源对账** | 从落盘数据独立复算每个展示数字（19 项），结果写 `_verify_last.json`。**分两级**：`fail`（数字对不上）与 `warn`（事实须知但数据完整）。两者混为一谈会让日常任务天天 FAIL，最终把 FAIL 训练成噪音 |
| 12 | **门禁** | 5 个入指数序列中不足 4 个成功则**拒绝生成 TACO**，避免半残指数被当成完整指数 |
| 12b | **验收看「实际生效文件」** | 目标被占用时标准名上是**上一轮的旧内容**。验收脚本必须识别 `<名>.locked-<时间戳>` 降级副本并改看它，否则会把「旧内容缺列」误报成代码故障（实测踩到过） |
| 13 | **`.bat` 纯 ASCII** | 中文注释在 `.bat` 里会被 cmd 按 GBK 解码（文件是 UTF-8），长 CJK 行会字节错位吞掉 CRLF，报「命令语法不正确」却指着一行看起来完全正常的代码。所以 `.bat` 全 ASCII，中文文档放本 README |
| 14 | **`.bat` 全 CRLF** | 三个 `.bat` 统一为 CRLF 换行（`crlf == lf`、无裸 LF）。LF-only 会让 `goto` / `:label` / 括号块在 cmd 下出现**间歇性**解析失败，是无人值守任务最难查的一类故障。验收同时断言「纯 ASCII」与「CRLF」两个条件 |
| 15 | **不误信「命令语法不正确」** | 该报错是 cmd 的**通用报错**，既可能来自文件内容，也可能来自**调用层**。实测：绝对路径 `C:\Windows\System32\cmd.exe` 在本机被安全策略拦截 → 报此错；换裸名 `cmd` 即通，而文件一字未改。**先用两行最小 bat 区分「文件坏」与「调用通道坏」**，再决定改哪里 |

| 19 | **写入韧性（三级）** | 目标文件被别人开着时 `os.replace` 抛 WinError 5，旧版会**整轮崩溃**。现按指数退避重试 → 仍失败则**就地覆盖**（保住标准名）→ 连就地写也不行才退写 `<名>.locked-<时间戳>` 并告警。绝不静默降级。**第 2 档是关键**：实测「rename-over 被拒」与「文件被独占」是两种状态（`taco-latest.csv` 反复 WinError 5，而同目录 `.xlsx` 与新建文件都正常，机器上没有任何 WPS/Excel 进程，且 `open('r+b')` 成功）。只靠退写会让标准名长期停在旧内容上 —— 而标准名正是下游和肉眼读的那个 |

| 21 | **变动量必须与水位并列** | 变动量只回答「比一个月前多还是少」，不回答「现在是正常的百分之几」。报告 §5a 强制输出月度中位数表。**只看变动，永远看不见断裂** |
| 22 | **姊妹序列对照** | 判断「水位断裂」是**单点问题**还是**全局管道问题**，不能只看目标序列本身。同源同期取本该无关的其他序列（同一 ArcGIS 图层的另外 5 个海峡），若它们平稳而目标断裂，则锁定为**单点**口径/信号问题。这一步把「数据源整体坏了」与「某个序列坏了」彻底分开 |
| 23 | **静态格式串校验** | `"%s %s" % (a, b, c)` 这类占位符/实参个数不匹配，Python 只在**执行到那一行**才抛 `TypeError`。本项目实测：`emit.py` 表头 5 列、实参 6 个，导致整轮联网抓取 + 算指数 + 写 history **全跑完之后**才炸。现由 `scan_format_arity()` 在离线自检里静态扫描（`ast` 遍历 `Str % Tuple`），并**额外断言「扫到的格式串 ≥ 50 处」** —— 否则「扫了 0 处」也会通过，那就是一个和 bug 意见一致的假护栏 |
| 24 | **源区间 ≠ 上网格天数** | 第 7 因子的源站点是盘中实时站，`run_date` 当天已有一条仍在成形的报价，而网格末日锚在基础序列上。若把「源区间 61 天」说成「有效 61 天」，落盘 60 天就会被读成「丢了数据」。日志分别报**源区间**与**上网格后实际天数** |
| 25 | **「不进指数」必须被断言，不能只在文档里承诺** | 观察指标最危险的不是算错，而是**偷偷进了合成** —— 指数会给出一个确定的方向感，而它本不该有。三重断言：① 自检里去掉观察序列后 `S`/`T`/5 个 `z` 必须逐点完全相等，且结果里不得出现任何第 6/7 因子派生量；② 对账用 `S = mean(5 个 z)` 逐点复算（多一项均值必然对不上），并检查落盘列契约正好 14 列；③ **验收回读落盘 CSV**，既验 `composite_S = mean(5 个 z)`，又检查 CSV **不得出现** `z_transit`/`TACO6_Index_T6` 等列 ——「说不进指数却算了」比列缺失更严重，所以两个方向都查 |
| 26 | **模式开关是闭合枚举，不是两个布尔** | `observe` 与 `composite` 若做成两个独立布尔，会出现「观察=true 且 并入=true」这种自相矛盾的组合，症状是「指数被一个声称不参与合成的列污染了」。现改为单字段 `extended_factor.mode` 闭合枚举（非法值直接退出），且 `compute()` 里 `observe_factor` 与 `extended_factor` **互斥**、同时给抛 `ValueError`。**能在配置层消灭的矛盾，不要留到运行期靠人去发现** |
| 27 | **观察指标的「前值填充日」与「真实观测日」必须分开报** | `F` 经 ffill 后末值日期 = 网格末日，看起来「今天就有数」；而霍尔木兹是 AIS 事后汇编、滞后 4~7 天，**真实观测日总是更早**。若只报前者，使用者会把「前值填充」误读成「今天的水位」。报告与看板同时给出两者（含滞后天数）—— 落盘列只有 `TRHBCCCD_n_total` 一列（网格值），这两个日期在报告/看板/`latest()` 的 `date_transit` 与 `date_transit_raw` 里分别给出 |
| 28 | **回归比对必须固定输入** | 拿改动前/后两次**真实运行**的产物逐点相减，差异可能全部来自**源修订**，而非代码。实测口径回退后全区间 `TACO` 出现 `max|Δ|=1.175e-02`，按「原始输入是否逐字相同」切分后才发现：输入相同的 **608 天 max|Δ|=0**，唯一变化日是最新一天 —— 上游 `USGG10YR`(+0.05) 与支持率聚合器(+0.105) 被回溯修订。**这个陷阱特别毒**：源修订影响最新一两天，与「新代码只在尾部出错」症状完全重合。判据是「**输入相同日必须逐点相等**」，由 `tools/regress.py` 固化；能 `--from-file` 离线重放就别联网比 |
| 29 | **门禁中止时不得覆盖产物 + 配置开关必须是活的** | 两件事一起踩出来的：CO1 一次**瞬时**抓取失败（Yahoo 走代理偶发），轮次照旧往下走，把一份**算不出 TACO 的残缺表**写到标准名上，**覆盖了上一轮完整读数**。根因有二：① 门禁只判「缺 ≥2 个才拒」，缺 1 个仅告警 —— 但 `composite_S = mean(5 个 z)`，缺任一输入必然算不出 TACO，那档「宽容」没有任何收益、只有风险；② 更隐蔽的是 `abort_on_index_input_fail` / `max_stale_ratio` **只写在 config 里、代码从未读取**（死配置）—— 运维照它们做假设，程序根本没守。修法：实现两个开关（`abort_on_index_input_fail=true` 时任一入指数序列缺失即中止），并让中止路径**只写 `_source_status.json`、绝不碰任何产物文件**；自检里加「**无死配置**」断言（键名**从 config 动态取**，写死在源码里会自我满足）。端到端已验证：缺 CO1 时 `rc=2`、两份产物 md5 **逐位不变**。**宁可不产出，也不产出错的 —— 标准名上留着上一轮的完整读数，比换上一份当天残缺读数安全得多** |

**关于写入降级**：目标文件被别人开着时 `os.replace` 会抛 WinError 5。程序按级降级：
指数退避重试 → **就地覆盖**（标准名内容正确，但非原子）→ 才退写 `<名>.locked-<时间戳>`。

> 关键点：**「rename-over 被拒」不等于「文件被独占」**。实测 `taco-latest.csv` 反复
> WinError 5，而同目录 `taco_index.xlsx` 与新建文件都能正常 replace、机器上没有任何
> WPS/Excel 进程、且对该 CSV `open('r+b')` 成功。所以只靠「退写成降级名」会让
> **标准名长期停在旧内容上**（实测停在 09:43 的 17 列旧版，而实际已是 27 列）——
> 而标准名正是下游与肉眼读的那个。这正是第 2 档存在的理由。

## 7. 每日自动运行

```bash
install_task.bat              # 注册，默认每日 09:10（北京时间）
install_task.bat 08:30        # 指定时间
install_task.bat status       # 查看状态
install_task.bat remove       # 卸载
```

任务名 `taco-monitor-daily`。**为什么用 schtasks 而不是「启动」文件夹**：
可指定时间、可查状态、可静默、有 last result 可追溯；启动文件夹只在登录时触发且无法追溯。

**为什么 09:10**：① 美股周五收盘 + 周末支持率聚合器已更新；② FRED 日频序列通常在前一
工作日 16:00 ET 后落定；③ 霍尔木兹通行量滞后 4–7 天，晚跑不亏。每日 1 次即可，不做高频轮询
——5 个输入里 3 个日频、1 个日频聚合、1 个滞后 4–7 天，高频跑只会重复读到同一批数。

**两个必须注意的点**：

- 计划任务通过 `run_silent.bat` 进入（不是 `run.bat`）。它强制 `RIM_NO_PAUSE=1`，
  否则 `run.bat` 末尾的 `pause` 会让任务永久挂住，下次触发被跳过。
- 计划任务的 `/TR` 指向 `run_silent.bat` 这一个**不含空格**的路径，从而完全避开
  schtasks 的嵌套引号转义陷阱（这是 Windows 计划任务最常见的坑之一）。

> ⚠️ 本环境的沙箱安全策略拦截了 `schtasks.exe`，所以**注册计划任务需要你手动执行
> `install_task.bat`**（双击即可，或用管理员 cmd）。其余环节均已实跑验证。

## 9. 修改配置的正确姿势

1. 改 `config.json`（**不要**手改 `taco_monitor.py` 里的公式常量）；
2. 用 curl 实测新源，把结果写进该条目的 `probe_evidence`（`ok/http/bytes/last_date/last_value/checked`）；
3. `python taco_monitor.py --selftest` —— 无实测证据的条目会被拒绝；
4. 真实跑一轮 → 确认 `_verify_last.json` 是 PASS → 看 §4 对照相关是否仍在 0.92 以上。

跳过任何一步，都可能造出一个「日志全绿但数字是错的」的报告。

**切换指数口径**（5 因子 ↔ 6/7 因子）只改一个字段：

| 目标 | 改动 |
|---|---|
| 5 因子（当前） | `extended_factor.mode = "observe"`、`extended_factor_2.enabled = false` |
| 6 因子 | `extended_factor.mode = "composite"` |
| 7 因子 | 上一条 + `extended_factor_2.enabled = true`、`bonbast_crawler.enabled = true` |

切完必须重跑自检（列契约断言会跟着变：14 / 20 / 27 列）。
**历史留档**：`config-archive/config.20260922-7factor.json` 是 7 因子时期的完整配置，
`output/_archive/` 是同期产物快照 —— 需要回退时可直接对照。

**切换口径后的必做一步：证明「没动过历史读数」**

```bash
python tools/regress.py output/_archive/taco-latest.20260922-7factor.csv output/taco-latest.csv
```

这个工具的判据**不是**「全区间最大差 ≈ 0」—— 那会得出错误结论。
**源数据本身在动**：实测口径回退后全区间 `TACO` 出现 `max|Δ|=1.175e-02`，
看着像「新代码改了历史值」；按「5 个原始输入是否逐字相同」切分日期后才发现：

| 分组 | 天数 | `TACO_Index_T` max│Δ│ |
|---|---|---|
| 原始输入完全相同 | **608** | **0**（逐点一致） |
| 原始输入有变化 | 1（2026-09-21） | 1.175e-02 |

差异全部来自 `USGG10YR`(5.01→4.96) 与 `RCPPTAPP_approve`(38.49→38.60)
在两次运行之间**被上游修订**，代码改动的影响是零。

**这个陷阱特别毒**：源修订影响的多是最新一两天，而「新代码只在尾部出错」
（新字段暖机 / ffill 边界 / 最新值未落定）症状完全重合，光看差异分布分不出来。
所以判据是「**输入相同日必须逐点相等**」。`tools/regress.py` 把这条判据固化了，
并在输入相同日出现差异时精确报出列名与日期（退出码 1）。
**能离线重放（`--from-file`）就别联网比** —— 那样差异只可能来自代码。

## 10. 已知偏差与不做的推断

- **USSWIT1 无公开等价物**：T5YIE 是 5Y 盈亏平衡，与 1Y 通胀互换期限不同。
  31 日差分相关 +0.637 是现有公开候选里最好的，但不是同一个量。
- **支持率口径**：底稿用 RCP 均值，本项目用 Silver Bulletin 贝叶斯平滑均值。
  两者都是聚合器，长期水平接近但短期波动不同。
- **油价口径（2026-09-23 定稿）**：底稿 H 列表头是彭博 `CO1 Comdty` —— ICE 布伦特原油
  **期货首月连续**，不是现货。入指数的是 **Yahoo Finance `BZ=F`**
  （NYMEX Brent Last Day Financial Futures，现金结算、紧跟 ICE 首月连续）。
  与 Yahoo 源逐点核验 **Δ=0**；近 90 日与东吴相关 0.9861。
  历史换源：FRED `DCOILBRENTEU`（现货，口径不符 + 滞后 4–5 交易日）→ 新浪 `OIL`
  （连续合约但换月节奏不同，backwardation 下 09-21 与 ICE 首月分叉约 4 美元）→ 现用 `BZ=F`。
  **API 出口按源覆盖**：Yahoo 需走系统代理（`egress:"proxy"`），其余源直连（详见 §5 #3 出口实测）。
- **原油现货/期货基差**：危机期现货可显著升水（2026-09 扩大到约 +22 美元/桶）。
  入指数的是期货；现货序列（FRED `DCOILBRENTEU`）与另一期货连续（新浪 `OIL`）
  均保留为 `context_only` 交叉校验并在报告 §5b 披露。
- **原油当日会话**：运行当天那一根 bar 是**未收盘**的盘中价，已按
  `drop_inprogress_session` 丢弃，只用完整交易日收盘价（Yahoo 按 `meta.gmtoffset` 定位本地日）。
- **⚠️ 霍尔木兹通行量 2026-03 起水位断裂且未恢复**（详见 §1b）：`chokepoint6`
  的 `n_total` 从约 78 断到约 3 艘次/日并持续 6 个月以上。三字段（计数/油轮/载重吨）
  同步塌约 95%，且同一图层其余 5 个海峡全部平稳 —— 故判定为**霍尔木兹单点的
  口径/覆盖问题**（区域性 AIS/GPS 干扰或图层口径变更，公开数据无法区分）。
  **对 TACO-6 的影响**：31 日变动退化，方向可能与水位相反，本项目自动标记为
  **降级读数**。**对 TACO 无影响**（5 因子不含此项）。**恢复前不要用 TACO-6 做结论。**
- **第 6 因子有两套口径，并列输出（用户选定，不是二选一）**：
  口径 A（31 日变动）→ **TACO-6**；口径 B（水位）→ **TACO-6L**。
  为什么不全用 A：A 在**水位断裂**的序列上会退化成断点噪声甚至反向（本例正是如此）。
  为什么不全用 B：若断裂本身是**数据假象**，B 会注入一个虚高的压力值。
- **⚠️ 第 7 因子（里亚尔）历史只有 60 天，这是数据源硬上限**（详见 §1.2）：
  Bonnast `/graph` 固定只返回 60 天，`?range=1y` / `?period=1y` 实测无效、
  `/graph/usd/365` 返回 404。ffill 到 609 天网格后 TACO-7L 约 59 天有效、
  TACO-7（需回看 31 天）约 28 天有效。**TACO-7 / TACO-7L 不是与 TACO 等长的曲线**，
  任何跨指数比较都必须限制在重叠窗口内。本地 `history/` 会随日更累积。
- **第 7 因子的符号方向与第 6 因子相反**：约定是「压力上升 → 因子上升」。
  霍尔木兹是通行量**下降**代表压力上升（取负）；里亚尔是汇率**上升**（贬值）
  代表压力上升（**不取负**）。这是最容易抄错的一处，报告与配置里都留了显式说明。
- **单位换算靠页面自述 + 双链路互证**：Bonnast 接口返回托曼，页面明写
  `1 Toman = 10 Rials`，故一律 × 10。同日与参考实现
  （`iran-condition-monitor` 的 `fx_daily.bonbast_usd_sell_rial`）互证一致。
  这不是猜的，`config.json` 里留了 `_unit_evidence`。
- **不做「断点真伪」的推断**：霍尔木兹水位断裂到底是真实断航还是口径变更、
  里亚尔是否已进入失控贬值，公开数据都无法区分。本项目只呈现两套口径与水位面板，
  不替使用者选边。
  **公开数据无法区分这两种可能**，故两套都出。水位未断裂时两者大体重合（可互为交叉校验）。
  若改用油轮艘次、载重吨、或 7 日均值后再做差分/取 z，读数还会不同 ——
  本项目只固定 A/B 两种，避免挑口径挑出好看的曲线。
- **TACO-6 / TACO-6L 不可与东吴原版对账**：东吴底稿只用 5 个因子，对账基准只有 5 因子 TACO。
- **相关 ≠ 因果**：只报同期同向/背离，不写「因为…所以…」。
- **不做预测**：不给时点、不给概率。TACO 是压力读数，不是择时信号。
- 仅作研究与监测用途，**不构成投资建议**。
