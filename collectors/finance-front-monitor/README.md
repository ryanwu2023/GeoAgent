# finance-front-monitor —— 美伊冲突「金融战线」高频指标监测

在 `iran-escalation-monitor`（新闻侧：伊朗战备与升级动态）旁边新建的**数字侧**工程。
新闻侧回答「发生了什么、说了什么」；本项目回答「市场为此付出了什么价格」——
九个桶 × 42 条序列 × 17 条派生量，全部可复算、可回源对账。
第 9 个桶（`taco`）是**跨项目对接区**：接入 `taco-monitor`（东吴宏观 TACO 五因子复刻）
的原始序列，只搬数据、不算指数。详见 §11。

```
run.bat                 # 一键三步：自检 → 抓取 → 对账（双击即可；流程在 run.py）
python finance_monitor.py --selftest            # 离线自检（244 项）
python tools/verify_report.py --save            # 回源对账（94 项，留档 _verify_last.json）
python tools/compare_taco_sources.py            # TACO 五因子与对侧逐日对表
python tools/build_config.py                    # 从实测证据重新生成 config.json
python tools/probe_sources.py --proxy http://127.0.0.1:PORT --round N   # 源探测
```

`run.bat` 只负责找一个可用的 Python（托管运行时 → PATH，可用 `RM_PY` 覆盖），
真正的流程住在 `run.py` 里；两者分开是为了「升级解释器」和「改流程」互不牵连。
定时任务设 `RM_NO_PAUSE=1` 可跳过结束时的等待。

## 1. 九个桶（§3–§8 的分节结构 + 第 9 桶 taco）

| 桶 | 内容 | 关键序列 |
|---|---|---|
| oil | 能源成本 | Brent/WTI（期货 vs 现货互验）、天然气、Brent 实现波动率 |
| inventory | 库存与战略储备 | **SPR**（政策工具直接读数）、商业原油库存（EIA 周报） |
| rates | 利率与政策预期 | 国债曲线（3M–30Y）、EFFR、目标区间、TIPS 实际利率、盈亏平衡通胀 |
| equity | 股市 | 三大股指、能源/国防 ETF、标普回撤 |
| credit | 信用与波动率 | VIX、垃圾债 ETF（利差的 FRED 源不可用时保留市场侧代理） |
| fx | 汇率与贵金属 | DXY、USD/CNY、黄金 |
| shipping | **海峡通行量** | 曼德/霍尔木兹/苏伊士/好望角日通行艘次（IMF PortWatch）、油轮载重吨、油轮股价 |

合成指数 **FSI** = Σ(权重×极性×z)/Σ权重，覆盖 11–12 个分量。**单位是 z，不是概率、不是预测**；
覆盖度不同的两期不可比较；分量混有步长 1 期与步长 7 期的 z，只能读方向与量级。

## 2. 信源等级（写在配置里，§12 呈现）

每个链条目声明 `tier`：

- **`official`** —— 官方一手发布：美国财政部（par yield + TIPS 两张表）、纽约联储（EFFR，
  同一响应自带 FOMC 目标区间，白赚一个序列）、EIA 周报 table1（SPR/商业库存，无需密钥）、
  IMF PortWatch（ArcGIS FeatureServer，海峡通行量）。
- **`market`** —— 市场行情：Yahoo chart v8（22+ 符号）。是交易者投出来的事实，
  会修订、会延迟，且**口径会漂移**（见 §5.3 的 ^TNX 例子）。

FRED 属 official 但**当前整体不可用**（Akamai 指纹封锁 Python 与 curl，见 §7）——
按「先测后用」纪律整链移除并在 `data_gaps` 披露，**绝不硬塞一个没实测过的源进配置**。

## 3. 事实 vs 加工：四层分类学（§0 第 10 条）

引用任何数字前先问自己在引用哪一层：

1. **① 原始观测值**——表中「最新值/值日期」列。官方发布或市场收盘。
2. **② 派生量**——按写明的算式从①算出（§9 每条带 definition）：Brent−WTI 价差、
   期限利差、盈亏平衡通胀、7 期日均通行、油轮占比、绕行比……
3. **③ 统计量**——z、σ、分位、档位。对①②的统计加工；档位只是阈值映射，不是判断。
4. **④ FSI**——③的再加权平均。连「指数」都是构造物。

特别标注：政策利率（EFFR/目标区间）极性为 0，其「升级」档表示**政策利率自身发生
异常幅度变动（政策事件）**，不是「金融市场压力升级」。

## 4. 数据质量防线（每条都对应一次真实踩坑）

| # | 防线 | 为什么 |
|---|---|---|
| 1 | **先测后用，构建器强制** | `build_config.py` 校验每个链条目在 `_probe_round*.json` 里有 `ok:true`；无证据的条目被滤掉，序列全空则整条弃用并披露。弃用超半数或 headline<4 → 拒绝生成配置 |
| 2 | **URL 逐字一致** | 探测用 A、配置用 B，证据就是假的。模板（`{year}`）在两侧同样展开 |
| 3 | **同主机限速 1.2s** | 实测 FRED 单请求 1.3s/200，并发 8 个后全部挂到超时——Akamai 把批量并发判为异常。限速是正确性要求不是礼貌 |
| 4 | **假 200 识别** | Stooq 每个符号返回**相同的 796 字节 JS 挑战页**（HTTP 200）；亚特兰大联储「CSV」实为 HTML。校验器按内容判定，不看状态码 |
| 5 | **列名陷阱** | 财政部 par yield 列 `10 Yr`，TIPS 表列**大写 `10 YR`**——两张表风格都不同，写错只会「列名不存在」 |
| 6 | **降序响应** | 纽约联储 `last/400.json` 按日期**降序**，取末条当 latest 会拿到 19 个月前的旧值。校验器取日期最大者 |
| 7 | **纪元零值哨兵** | 缺日期的 feed 给 `1970-01-01`；epoch 转换对 0 返回 None，全报告守卫禁脏值 |
| 8 | **跨年切分** | 财政部 CSV 按年导出：URL 模板取 `{year_prev}`+`{year}` 两年合并，否则次年 1 月历史只剩几天，σ/分位全失真 |
| 9 | **修订记账** | 周频数据发布后回改：同日期新值覆盖旧值但**逐条记账**并在报告披露 |
| 10 | **源间分歧检查** | 主源之外能取到的源只做互验。分歧≠有错（期货 vs 现货、DXY vs 广义美元），按序列配容差，分歧明细进报告 |
| 11 | **小基数百分比禁令** | 艘次计数不做 N 期百分比变化：1→8 艘次 = +700%，会把噪声渲染成「升级」。计数序列只用 7 期均值与结构比 |
| 12 | **回源对账** | `verify_report.py` 从 records jsonl **独立复算每个展示数字**（94 项）；凡参与比对的路径不写死日期，实际读取路径打印在首行 |

## 5. 与「数字」打交道的特有陷阱（新闻类监测没有的）

### 5.1 一个源的「无变化」有两种含义
市场真没动 vs 数据没更新。由「本轮新点」栏与「滞后」栏区分，绝不显示为 0 变动。
海峡通行量是 AIS 事后汇编（滞后 4–7 天），按序列覆盖 `max_lag=14`。

### 5.2 周内季节性
海峡周末船少，逐日比全是噪声。这类序列用**步长 7 期**（与上周同一天比）分级，
行内标 `步长7期`；另给 7 期日均抹平季节性。同表混两种步长的 z 时必须在 §0 声明。

### 5.3 口径会漂移：^TNX 的教训
旧知识说 Yahoo `^TNX` 返回收益率×10（42.3）。实测（2026-09）它**直接返回 4.998**。
教训不在「哪个对」，而在：**不要为记忆里的口径写死缩放**——先看原始载荷，
让主源（财政部 par yield）与交叉源在容差内互验；口径再漂移时分歧检查会大声报警。

### 5.4 单位写在配置里，不写在脑子里
`%` 序列的变动以 bp 显示；派生量一律显式声明 `delta_unit`（`pct_over` 输出已是百分比，
再折 bp 会错得离谱——这类错误对账工具的「量纲一致」用例兜底）。

## 6. 累积历史与快照的区别（与新闻类方向相反）

- **数值历史是资产**：`history/*.jsonl` 跨轮累积，绝不因单轮源回溯长度短而删点
  （新闻快照要修剪，数值历史要保护——搞反必出错）。
- `ALL-observations.jsonl` 按 `(run_tag, series)` 留痕，每轮一个观察账本。
- `max_points_per_series=4000`（约 16 年日频），超出丢最旧。

## 7. 数据缺口与不做的推断（全部实测在案）

- **FRED**：urllib 4 种请求头全超时（40s），curl 单发 200/1.3s，串行限速后仍间歇超时
  → 风控对 IP 级冷却。整链移除；利差（HY/IG）与汽油零售价两条 FRED 专供序列随之弃用并披露。
- **CME FedWatch**：403（主动反爬）→ **不提供加息概率**。政策预期只给代理量
  （2Y 收益率相对目标区间上沿的偏移），给方向不给概率、不给时点。
- **亚特兰大联储概率追踪器**：200 但内容是 HTML。
- **Stooq**：JS 挑战页。
- **EIA Open Data API**：需要密钥 → 用 EIA 自家**无需密钥**的周报 table1.csv 替代。
- **相关 ≠ 因果**：只报同期同向/背离，不写「因为…所以…」。

## 10. 修改配置的正确姿势

1. 改 `tools/build_config.py`（不要手改 config.json——它会被重新生成覆盖）；
2. `python tools/probe_sources.py --round N ...` 拿实测证据；
3. `python tools/build_config.py` 重新生成（证据校验自动过滤不可用条目）；
4. `python finance_monitor.py --selftest` → 真实跑一轮 → `verify_report.py --save`。

跳过任何一步，都可能造出一个「日志全绿但数字是编的」的报告。

## 11. TACO 五因子对接（跨项目）

`taco-monitor`（东吴宏观 TACO 压力指数五因子复刻）已经在爬这五个指标。本工程
按「已爬的核对源头、没爬的补爬虫」把它们接进来，但**只搬数据、不合成指数** ——
指数仍由 taco-monitor 负责，两套实现同时算同一个指数一定会互相打架。

| 因子 | 含义 | 本工程序列 | 对侧源 | 源头关系 | 实证 |
|---|---|---|---|---|---|
| C | 10Y 美债收益率 | `dgs10`（财政部 par yield） | FRED `DGS10` | 同底层、不同发布途径 | 181/181 共有日**逐日完全相同** |
| D | 1Y 通胀互换（代理） | `taco_breakeven5y`（**本次补爬**） | FRED `T5YIE` | **同源同 ID** | 681/681 逐日完全相同 |
| E | 特朗普支持率 | `taco_trump_approval`（**本次补爬**） | Datawrapper `kSCt4` | 数据同源，但**指标定义不同** | 609/609 逐日完全相同 |
| G | 道琼斯工业指数 | `djia`（Yahoo `^DJI`） | FRED `DJIA` | 同底层、不同发布途径 | 最大差 0.001875 点（FRED 只留两位小数） |
| H | 布伦特原油 | `brent`（Yahoo `BZ=F`） | Yahoo `BZ=F` | **同一 symbol** | 503 天中 502 天完全相同 |

核对方法：**双方都用已落盘的原始载荷**，复用同一个解析器逐日对表
（`tools/compare_taco_sources.py`，结果留档 `tools/_taco_source_check.json`）。

### 11.1 三个必须说清楚的「不一致」

1. **因子 E 只是数据同源，不是指标同源。** 对侧是**净支持率**（RCP 手工均值），
   本侧是 Silver Bulletin 的 **approve 单侧建模值**。数据取自同一份 CSV、逐日完全相等，
   但「数据一致」≠「因子可直接互换」——**不要跨项目拼成一条连续序列**。
2. **因子 D 两侧都用了代理。** 1Y 通胀互换公开源不可得，两侧都用 FRED `T5YIE`
   （5Y 盈亏平衡通胀）代理。源相同，但「5Y 盈亏平衡 ≠ 1Y 互换」——期限与工具都不是同一个东西。
3. **因子 H 曾差一天。** 唯一不一致的那天就是**当天的未收盘盘中价**。
   已用 `drop_inprogress_session` 统一为「只取完整交易日收盘」（口径与 taco-monitor 对齐）。

### 11.2 试过并否掉的源

`brent` 试过挂 FRED `DCOILBRENTEU`（欧洲 Brent **现货**）作交叉源，**否了**：
它与 Yahoo 期货的基差在 490 个共有日上中位数 1.69%、最大 22.4%，最近一周扩大到
−7.7% → −16.9%（现货升水），且该序列当时滞后 8 天。这是**真实的期限结构**，
不是数据错误；交叉源的职责是抓「解析错、单位错、取错列」，不是抓基差 ——
把基差放进 4% 容差里，等于让它天天报警，真正的数据错会被淹掉。
基差本身有信息量，但那是另一个指标，不该伪装成校验。

### 11.3 FRED 为什么曾经「整链不可用」

真因是 Akamai 的**双重指纹**：既看客户端类型，也看自称的 UA 名字。
`curl` 自称 Chrome UA → 超时；`curl` 自称 `curl/8.19.0` → 200 / 0.6 秒。
所以「客户端」和「UA」两件事都必须进配置、进探测证据。修正 UA 后 FRED 实测 28/31 可用
（唯一两个不可用的是 `WCSSTUS1` / `WCESTUS1`，FRED **已下线**，404）。
