# iran-escalation-monitor — 伊朗战备与升级动态监测（六大关注域 × 当事方对照）

围绕**「伊朗及其对手的公开叙事里，下一步可能往哪走」**这一问题，采集
**美方官方**（中央司令部 / 国防部 / DVIDS / 财政部 OFAC）、**伊方官方**
（革命卫队通讯社 / 国防部 / IRNA / Pars Today）与**第三方**（专业防务媒体、
航运媒体、智库、议会/审计文件、公共国际媒体）的公开报道与通告，
按**六大关注域 + 一个前瞻域**归类，输出可供大模型直接阅读的结构化 Markdown 日报。

关注的六个具体方向（用户给定，逐条对应报告 §3.1–§3.6）：

1. **打击美军海上作战平台**（航母打击群 / 驱逐舰 / 第五舰队 / NAVCENT）
2. **霍尔木兹海峡 + 曼德海峡双线施压**（含商船扣押、航运袭扰）
3. **打击美方盟友的关键能源设施**（沙特/阿联酋/卡塔尔油气、码头、LNG）
4. **切断海峡海底光缆**（AAE-1 / SEA-ME-WE / SMW5 / FALCON 等系统）
5. **核试验与核计划里程碑**（IAEA 对峙、退出 NPT、浓缩度、核武器化）
6. **一般战备与军事准备**（动员、演习、导弹试射、战损/伤亡承认）

第 7 个域 **升级前瞻**（未来 1–4 周）不是一个并列的"事实域"，而是一个
**意向指标域** —— 见 §一 第 4 条，这是本报告最容易被误读的地方。

```
iran_monitor.py       主程序（纯 Python 标准库，零依赖）
config.json           数据源 / 词表 / 信号桶 / 议题锚点 / 关注域 / 发布主体映射
run.bat               一键运行（自检 → 抓取 → 回源对账 → 产出）
tools/                开发辅助探针与诊断工具，日常无需使用
state/seen.json       去重状态
output/               产出（按日期分目录 + LATEST 快照 + 累积总档）
```

## 一、这份报告监测的是「表态」，不是「事实」

这是理解全部产出的**前提**：

| | 监测对象 | 证据地位 |
|---|---|---|
| 本项目 | 各方**公开说了什么** | 该方表态的**一手记录** |
| 不是 | 事情**真相是什么** | 需要独立来源印证 |

由此推出五条不可协商的规则：

1. **美方官方源与伊方官方源地位完全对称**。美国国防部 / 中央司令部与伊朗革命卫队
   通讯社在本系统中**同为 `T1`**。`T1` 的含义只是「这是该方表态的原始出处」，
   **不等于**其内容已获证实。任何涉己战果 / 战损表述都必须有独立来源才可引用。
2. **交叉验证只做机械配对**：同一议题词 + 同一周出现。程序**不做**语义一致性判断。
   `both_mentioned` 只说明双方都在讲这件事，**不等于**说法一致。
   唯一的例外是 `contradiction` —— 它由**明确的否认词 + 方向正确的配对**触发（见 §五）。
3. **每个结论都能回原文**。每个信号都带 `context` 命中片段（前后数十字符）与链接
   —— 抽取跑在**完整正文**上，而归档 `summary` 会截断到 1500 字；命中若落在截断之外，
   只有 `context` 能让人核对。
4. ★★ **§4「升级前瞻」是意向指标，不是事实指标，更不是预测。**
   它统计的是「谁在公开说下一步要做什么」，其中含大量**威慑性措辞**
   （威胁本身常常是为了避免行动，而不是预告行动）。反过来，真正准备动手的一方
   往往**停止**公开发声，因此**分值低 ≠ 不会升级**。
   它的正确读法是「**公开叙事的温度计**」，不是风险概率。
5. **每个数字都标注来源、口径与信源等级**，且报告里每个数字都能由落盘数据独立复算
   （`tools/verify_report.py` 是唯一的数字级门禁）。

## 二、快速开始

```bash
python iran_monitor.py
```

**不要手动指定代理端口。** 程序自动读取系统代理并打印实际出口：

```
实际出口代理: http://127.0.0.1:7897
```

> ⚠️ 代理端口会漂移（实测同一天内 `7897` → `51681` → `63299`），
> 而且**旧端口常常仍在 listen**：TCP 可连接但无法转发（`Tunnel connection failed: 502`）。
> 写死端口的症状是「所有源突然全挂」，与「被 CDN 风控拦截」**肉眼无法区分**，
> 极难排查。详见 §七 7.8。

常用参数：

| 参数 | 说明 |
|---|---|
| `--selftest` | 离线自检（**554 项**，不联网）。改完词表**必须**先跑这个 |
| `--render-only` | **离线仅重新渲染**：从当日快照重建报告，不联网抓取。改渲染层（表格/标签/说明）后用，免得白抓一遍 |
| `--sources sepahnews,dod-releases` | 只跑指定源 |
| `--days 30` | 覆盖回溯天数（默认取配置 `lookback_hours`） |
| `--backfill` | 时间窗拉到 `config.history.start`，建立更长历史 |
| `--show-all` | 不做折叠，附录列出全部记录（含被闸门挡掉的） |
| `--from-file feeds/` | 完全离线：读 `feeds/<源id>.xml` 或 `.json` |
| `--recompute` | **离线**按当前词表重算累积总档后退出（改完词表/解析器后必跑） |
| `--strict-tls` | 拒绝任何需要关闭证书校验的源（用于审计链路安全性） |
| `--as-of 2026-09-19 --out-dir /tmp/x` | 把本次当作某日、写入隔离目录（**跨天落盘验证专用**） |
| `--proxy http://127.0.0.1:7897` | **仅供排障**的显式出口覆盖，不要写进脚本/计划任务 |

`run.bat` 走的就是四步：`--selftest` → 抓取 → `verify_report.py --save` → 打开报告。
计划任务里请设 `RIM_NO_PAUSE=1`，否则末尾的 `pause` 会永久挂住进程。

```
output/
├── LATEST.md                    主报告（人读 / 大模型读，11 节 + 附录）
├── LATEST-crosscheck.md         交叉验证明细（含「判定依据」）
├── index.md                     日期索引
├── ALL-records.jsonl            累积总档（按 id 去重、永不淘汰、带 first_seen）
├── _source_status.json          每源状态：HTTP、Server、解析条目/产出、源内最新距今天数、实际出口代理、TLS 降级
├── _gate_audit.json             被折叠记录的逐条留档 + **全量**折叠分类计数
├── _verify_last.json            最近一次回源对账结果（数字级门禁留痕）
└── <YYYY-MM-DD>/
    ├── iran-digest-<day>.md        当日主报告
    ├── crosscheck-<day>.md/.json   交叉验证
    ├── weekly-<day>.json           按周 × 当事方信号矩阵
    └── records-<day>.jsonl/.json   当日窗口快照（**窗口内全部**，非仅新增）
```

主报告结构：

```
0 阅读须知 → 1 一页速览 → 2 数据源状态 →
3 六大关注域明细（3.1–3.7）→ 4 升级前瞻指标（意向指标）→ 5 关键实体分布 →
6 交叉验证矩阵（议题 × 周）→ 7 同期对照：双方原文并列 → 8 公开升级信号活跃度（按周）→
9 声明类型分布 → 10 数据源与合规 → 11 已知偏差与误读边界
```

> §8 用「活跃度」而非「强度」是刻意的：该表衡量的是**公开表态的发声热度**，
> 不是任何一方真实战备水平的强弱。真实的战备（戒备等级、弹药实数、损失明细、
> 行动时间表）大多不公开，所以这个分值对「真实强度」是零信息。
> 表内「加权分」= 该周该方命中的各信号桶权重之和（权重在 config 的 `signals` 里人工设定），
> 仍属启发式参数，**不是可比的度量单位**。

## 四、六大关注域 + 前瞻域怎么算

### 4.1 二维匹配 `require_all`：防止一个通用动词污染整个域

最容易犯的错是「把 `attack` 放进『打击美军海上平台』桶就完事」——
结果**每一条**含"袭击"的新闻都会命中该域。

因此 9 个桶改为**二维必需项**：必须**每个子组各命中一次**才算命中。

| 桶 | 子组 1（动作） | 子组 2（对象） |
|---|---|---|
| `us_naval_attack` | strike / struck / hit / target / launch / attack / sink … | US Navy / warship / carrier / destroyer / USS / 5th Fleet |
| `us_naval_reinforce` | deploy / surge / reinforce / reposition / carrier strike group | 同上 |
| `hormuz_threat` | threaten / close / block / mine / seize | Hormuz / Strait / 霍尔木兹 |
| `babelmandeb_threat` | 同上 | Bab el-Mandeb / Red Sea / Gulf of Aden |
| `shipping_interdiction` | seize / board / intercept / **struck** / targeted | tanker / merchant vessel / cargo ship / 商船 |
| `chokepoint_drill` | drill / exercise / war game / live fire | strait / Hormuz / Bab el-Mandeb |
| `energy_strike` | strike / struck / target / hit / attack | refinery / oil terminal / gas field / Abqaiq / Kharg … |
| `energy_threat` | threaten / cut / halt / disrupt | 同上 |
| `cable_threat` | cut / sever / sabotage / attack | undersea cable / subsea cable / AAE-1 / SMW5 … |

自检里为此加了 **通用动词不变量**：`GENERIC` 动作词集里的任何词，
都必须在**某个**子组里以 `require_all` 形式受约束；若被单独放进单维桶，
自检直接判红 —— 否则「收紧词表」时很容易退化成单维。

### 4.2 词表必须写**基础形**，既不能写屈折形，也不能写半截词根

匹配按**末词词尾**派生形态族：

| 词尾 | 派生 | 覆盖 |
|---|---|---|
| `-e` | `stem(?:e\|es\|ed\|ing\|ion\|ions\|ation\|ations)` | deplete → depleted / depleting / **depletion** |
| 辅音+`y` | `stem(?:y\|ies\|ied\|ying)` | casualty → **casualties** |
| 其余 | `w(?:s\|es\|ed\|ing\|d)?` | destroy → destroys / destroyed |

不规则形**必须显式登记**（`strike,struck,hit,hitting,sink,sank,sunk,seize,seizure,
shoot down,shot down,repel,repelled`…）。**两类错误必须同时防**：

1. **写屈折形**：写 `destroyed` 命不中 `Destroys` → 美方 `action_claim` 恒为空集
   → **交叉验证的 contradiction 恒为 0**（最该报的口径对撞一条都报不出来）。
2. **写半截词根**：为规避第 1 类而写 `deplet` / `strik` / `neutraliz` → 代价是
   **原形与 `-ion/-ation` 名词形全漏**，而检查当时只扫 `claims` 不扫 `signals`，
   所以一直没报出来。

→ 自检含 **全词表**（signals + claims + relevance）的半截词根断言 + 词形族覆盖断言。
→ 改完词表用真实语料回扫：`tools/audit_claims.py` 与
`tools/audit_lexicon_fp.py --suspicious`。
→ ★ **收紧词表时最容易连真信号一起删掉**：曾把 `depleted` / `depletion` 整条删掉、
只留 `depleted stockpile`，结果漏掉整个主题最关键的一条证据（标题用的就是裸词）。
漏检**改变了结论方向**，不只是"少一条"。收紧后必须回扫同族词根。

### 4.3 展示闸门 = 信号命中 **且**（主题锚定 ≥1 或 领域词 ≥1 或 该源本身是主题源）

只有信号不够：`targeted` 会命中「住房补贴**定向**发放给原住民社区」。
展示与统计**共用同一个函数** `is_displayable()`，避免「正文看不到、却进了计数」。

### 4.4 关注域是**二维口径**，与「当事方口径」不可相加

§1 表上半部分是**关注域口径**（一条记录命中多个域会被重复计入），
末行是**当事方口径**（每条只算一次）。两个口径由同一个闸门函数产出、内部自洽，
但**列不能相加**。`verify_report.py` 会同时复算两种口径并各自比对。

### 4.5 前瞻域 = 「尚未发生」的表述

`FORESIGHT_BUCKETS = future_threat / condition_ultimatum / imminent_indicator /
mobilization / escalation_ladder`，共同特征是**未来时 / 条件式 / 临战式**。
它同时是 §3.7 域和 §4 专章，**两处数字必须相等**（自检与对账都查这一条）。
强度 = `Σ(信号权重 × 命中次数)`，是启发式排序，**不是概率**。

### 4.6 实体抽取是「被提及」，不是「已发生」

实体一律带**字母/数字边界**：`(?<![A-Za-z0-9])…(?![A-Za-z0-9])`。
实测事故：`Rota` 命中 `Rotational`、`America` 命中 `American`、
`Nimitz`（舰级）被当成 `USS Nimitz`（舰名）—— **凭空多出一艘船**。
普通名词带可选复数 `(?:s|es)?`，**专名不带**（否则 `USS Ford` 会匹配到 `Fords`）。

§5 只统计**提及条数**与代表记录，**不判定实体当前状态**：
文中出现 `Kharg` 可能是「打击哈尔克岛」，也可能是「哈尔克岛正常装船」。
任何「某设施已被打击」的结论必须回到原文。

## 五、交叉验证怎么判

10 个议题锚点（`hormuz` / `babelmandeb` / `us_naval` / `energy_facility` /
`subsea_cable` / `nuclear_program` / `missile_program` / `gulf_shipping` /
`military_drill` / `houthi_front`）× ISO 周归组，只用**通过展示闸门**的记录：

| 分类 | 触发条件 |
|---|---|
| `contradiction` 🔴 | 一方有 `action_claim`，另一方（**或第三方转述其立场**）在同周有 `denial`，**且配对方向正确** |
| `mutual_assert` 🟠 | 双方同周均宣称有行动效果（**不等于**说的是同一件事） |
| `both_mentioned` 🟡 | 双方同周都提到该议题（**不等于**说法一致） |
| `us_only` / `iran_only` | 仅单方提及 —— 单方声明在获印证前不可作为事实 |

`contradiction` 是唯一带语义判断的分类，因此**必须给出触发它的具体条目**：
§7 每组都带「**判定依据**」，列出是哪几条记录、各自命中了哪个词，
**且必须同时列出第三方记录**——实测最典型的一类对撞正是
「第三方转述美方否认伊方说法」，若只列 us/iran，读者就无从复核。

> 对撞方向必须**配对**：美方主张 ← 被伊方或第三方（否认美方）否认；
> 伊方主张 ← 被美方或第三方（否认伊朗）否认。
> 曾把两个第三方变量挂反，于是「美方宣称 + 第三方否认**伊朗**的说法」
> 这种并不矛盾的组合被判成对撞（假阳性）。

## 六、数据源（v1.5.0：120 条登记，79 条启用，41 条停用留档）

**美方**：`dod-releases` / `dod-transcripts` / `dod-news` / `whitehouse-actions` /
`dvids-*` / `treasury-ofac`（制裁，T1）、`gao-reports` / `crs-reports`（T2，机构估算）

**伊方**：`sepahnews`（革命卫队官方通讯社）/ `defapress` / `parstoday` /
`irna-en` / `kayhan` / `mehr-en` / `isna-en` / `tehrantimes` / `iranpress`

**伊流亡 / 反对派**：`iranintl` / `radiofarda` —— **单列，不计入伊方官方表态**，
否则会把反对派报道当成伊朗官方立场。

**第三方（T3）**：各聚合器源（按主题构造的 Google News 查询）、
`usni-news` / `defensenews` / `breakingdefense` / `bbc-me` / `aljazeera` /
航运专业媒体（`gcaptain` / `tradewinds` / `safety4sea` 等）、
智库（`csis-analysis` / `isw` / `carnegie` / `chathamhouse` / `rusi` / `brookings`）

**T4（自媒体/社交平台）一律不采用。** 理由不是「不可信」，而是**不可核验** ——
没有可回溯的原始文件，一旦进证据表就会把整张表的可信度拉平。

### 6.1 信源等级 T1–T4

| 等级 | 含义 | 本项目 |
|---|---|---|
| `T1` | 官方一手（原始记录 / 法律文件 / 官方通稿） | dod-*、dvids-*、whitehouse-actions、treasury-ofac、sepahnews、defapress、parstoday… |
| `T2` | 官方分析 / 审计（机构**估算**） | gao-reports、crs-reports |
| `T3` | 专业 / 商业媒体（**二手转述**） | usni-news、defensenews、bbc-me、航运媒体、智库、各聚合器源 |
| `T4` | 自媒体 / 社交平台 | **不设采集器** |

两条最容易搞错的判定原则：

- **「官方机构」≠ T1**。GAO / CRS 发布的是**分析估算**，不是原始记录 → T2。
- **转述官方结论的媒体仍是 T3**。等级看的是**你手上这份材料由谁加工**，
  不是它引用了谁。要升到 T2，必须实际取到原始报告本身。

报告里关键数字逐个跟来源与等级；§3 每行都带等级徽章；
若某个信号桶**全部**来自 T3，报告会自行警示。

| 源 | 状态 | 原因与替代方案 |
|---|---|---|
| `centcom-afpims` / `navy-*` / `jcs-*` | ⛔ 停用 | AFPIMS `RSS.ashx` 在 Site id 不匹配时返回 **HTTP 200 空体**（不报错）。真实 Site id 未公开，反查失败 → 改用 `gnews-centcom` 取标题层 + `dvids-*` 取一手内容 |
| `ukmto` / `ukmto-news` | ⛔ 停用 | 官网无公开 RSS 端点（实测 404）。UKMTO 是红海/亚丁湾海事通告的一手发布方，缺它 → 「商船被袭/被扣」的时间与位置**精度下降**，只能经航运媒体转述 |
| `farsnews-direct` / `tasnim-direct` / `khamenei-en` | ⛔ 停用 | TLS 证书链不完整 / DNS 无法解析 → 改用对应的聚合器源 |
| `marad-rss` / `imo-pressbrief` | ⛔ 停用 | 旧通道下线 / 无稳定 RSS |
| `dod-contracts-rss` | ⚪ 可达但不启用 | 合同公告是**采购/授信**口径，不是战备表态，混入会污染信号统计（口径不可混用） |

> ★★ **归因警告（2026-09-18 实测）**：上表若有源标为「被 CDN 拦截」，务必先排除
> **本地出口**因素。实测某次运行 12 个源同时失败：6 个报 `Tunnel connection failed: 502`、
> 6 个报 `403 AkamaiGHost / cloudflare` —— 换到存活代理端口后**12 个全部 200 + 真实 RSS**。
> 两种成因的报错**肉眼无法区分**，若不查出口就会把本地网络故障写成
> 「美方官网被 CDN 整站拦截」这种**归因错误**。

### 6.3 信源配置纪律：先探测、后配置

新增源一律走「**分轮探测 → 只把实测可用的写进 config**」，
并把失败证据（日期 + 状态码 + Server 头 + 原因 + 替代方案）写进 `note` 留档。
不做风控绕过（不模拟浏览器指纹、不绕 Cloudflare/Akamai 挑战）。

## 七、工程纪律（这些坑都踩过）

### 7.1 非 ASCII 词必须加**词内边界**，否则短词会嵌进普通词 ★★★

英文短词靠 `\b` 就能定界，但波斯语/阿拉伯语**没有词边界语义**。
早期实现对非 ASCII 词直接用 `str.find()`，于是两字母的 `رد`（否认）
命中了 `فردا`（明天）、`بردار`、`خرد`、`درد`、`سردار` ——
**每一个波斯语句子都命中了「否认」**，凭空造出大量「口径对撞」，
把交叉验证的 `contradiction` 全部污染。

修复：`_fa_pattern()` 对非 ASCII 词加**词内边界**
（左边界总是加；右边界仅对 ≤3 字符的词加，以保留 `نفتکش`、`رزمی`、`یمنی`
这类需要连写的复合词）。
自检与对账均有断言：`رد` 不得命中 `فردا`／`بردار`／`خرد`／`درد`／`سردار`，
`قطع` 不得命中 `قطعنامه`。

### 7.2 同形字（homoglyph）：肉眼查不出来的死词 ★★★

词表里曾有一个 `aaе` —— 最后的 `е` 是**西里尔字母 U+0435**，不是拉丁 `e`。
两个字符在等宽与比例字体下**完全一样**，人工 review 永远看不出来，
而匹配永远不会命中。同类还有 `jcpOA`（大小写混写，看起来像 `JCPOA`）。

→ 自检加断言：全词表不得出现西里尔 / 希腊字母同形字，
词条必须 lowercase 规范化。
**任何"这个词明明在文里、却没命中"的排查，第一步就是逐字节 dump 该词。**

### 7.3 日期解析失败是**双重的静默损失** ★★★

真实源在用、而早期解析失败的两种格式：

```
Wednesday, September 16, 2026 - 17:32      （crisisgroup）
Wed, 29 Jul 26 12:37:14 +0200              （IAEA，两位数年份）
```

失败后果**同时发生**且**互不显眼**：

1. 记录进不了 §8 周趋势（按周统计要求日期可解析）；
2. 年龄算不出来 → **绕过时间窗过滤** → 过期条目混进快照。
   实测一个「14 天窗口」的快照里因此混入了**两个月前**的条目。

症状是「§1 说展示 1115 条，§8 各周加起来只有 1100 条」——
**两处各自看着都正常**，差额没有任何解释。

修好之后还有第三个坑：**两位数年份**。Python 的 `%Y` 是宽松的（接受 1–4 位数字），
`26` 会被解析成**公元 26 年**，且**解析返回成功、不报错**。
记录于是「极旧」，既被窗口过滤掉、又让周归属彻底错乱。

→ 对策：① 两位数年份在**任何 strptime 之前**展开成四位数；
② **年份合理性兜底**：解析成功但年份 < 2000 或 > 今年+1 一律判失败
（「解析成功但年份离谱」比「解析失败」危险得多 —— 失败会被看见，离谱的年份会安静地把
记录放到时间轴两端）；③ 多语月份/星期名统一别名化成英文缩写
（西语 `Septiembre`、法语 `septembre`、德语 `September`），
避免为每种语言各写一套格式表。

### 7.4 无日期条目：纪元零值哨兵 `Thu, 01 Jan 1970` ★★

Google News RSS 对**没有日期的条目**填纪元零值。它不是「一个很旧的日期」，
而是「日期未知」。三个后果：

1. 表格日期栏印出 `Thu, 01 Ja` 这样的**半截垃圾**（`published[:10]`）；
2. **永远过不了窗口判定**（算不出年龄）→ 只要进过一次快照就**永久滞留**，
   重跑也清不掉；
3. 对账工具按 `YYYY-MM-DD` 正则数表行时会少算一行，报**假告警**。

→ 对策：① `is_epoch_sentinel()` 显式识别，`parse_date()` 返回 `None`；
② 记录置 `published=""` + `date_unknown=True`，并在 §2 单独披露条数与来源；
③ 表格日期栏一律走 `date_cell()`：可解析才印 `YYYY-MM-DD`，否则印 `—`
（**绝不印截断的原始字符串**）；机器可读文件走 `date_iso()`（返回空串）；
④ `merge_records()` 对带 `date_unknown` 的**旧**记录不跨轮携带 ——
若它仍在 feed 里，本轮抓取会再收进来（它确实是当前条目，只是没日期）；
已从 feed 掉出的则清掉。累积总档 `ALL-records.jsonl` 仍留原始档。
⑤ 对账加**全报告守卫**：任何表格行都不得残留 `Mon,`…`Sun,` 形式的原始 RFC822 串，
也不得出现 `Jan 1970`。**检查范围要排除说明性文字** —— 我们自己会在披露里
引用这个哨兵当例子，工具连说明一起查就会把自己的揭示文字判成泄漏（假告警）。

### 7.5 `require_all` 的通用动词不变量 ★★

见 §4.1。收紧词表时最容易的退化是把二维桶改回单维，
所以自检把「通用动词必须在某个子组里受约束」写成**不变量**，而不是靠人记得。

### 7.6 落盘合并源必须是「窗口内全部」，不是「仅新增」★

跨天时 `output/<今天>/` 不存在，读回旧记录读到空，而旧记录又已被划为「非新增」
→ 两头都不在，快照会塌（实测 22 条 → 2 条）。
头部**同时**标注「本次新增 N 条」与「当前快照 M 条」。
合并源用 `records_all`，**绝不能**用 `records_new`。

### 7.7 保留旧快照必须**有边界**，否则窗口无限膨胀 ★

保留旧记录的理由是「它仍在窗口内、却已从 feed 列表掉出去，抓不回来」；
一旦它**掉出窗口**，保留就变成永久污染 —— 实测日期解析缺陷把两个月前的条目
放进来后，它们**永远留在当天快照里**：重跑也清不掉，因为重跑时它们既不在新抓取
结果里（已被窗口过滤）、又已在旧快照里。
→ `merge_records()` 对旧快照按 `window_cutoff()` 修剪（日志打印修剪条数）。
**只测「同日重跑」会完全掩盖这一类** —— 见 §7.9 验证清单第 5 步。

### 7.8 代理出口：端口会漂移，而「代理坏了」会伪装成「被风控拦截」★★

| 报错 | 会被误判为 | 真实原因 |
|---|---|---|
| `Tunnel connection failed: 502` | 站点不可达 | 代理不通 |
| `403 AkamaiGHost` / `403 cloudflare` | 被 CDN 拦截 | **出口 IP 被拦**（换出口即 200） |

**归因三步（顺序不能反）**：
1. 打印 `getproxies()` 实际出口，与上次成功抓取时的出口比对；
2. 用一个**已知可通的第三方 URL** 对照探测 → 区分「全线不通」与「单站不通」；
3. **换出口复现一次**再写结论：换出口仍 403 → 站点侧；换出口就通 → 出口侧。

自检里有断言：未覆盖时 opener 必须跟随系统探测结果，覆盖时注入指定出口。
出口信息写入 `_source_status.json` 的 `proxy` 字段与每次运行的首行日志。

### 7.9 验证清单（交付前跑完这六步）

1. `python iran_monitor.py --selftest` → **554 项全绿**
2. `python tools/audit_claims.py` → 词形族无漏检（或有意识的排除项）
3. `python tools/audit_lexicon_fp.py --suspicious` → 无词形族造出的非词
4. **同日重跑** → 快照条数不塌
5. **换日期 + 换全新输出目录**再跑 → 跨天不丢窗口内历史
   ```bash
   python iran_monitor.py --out-dir output/_xday-verify --as-of 2026-09-19
   # 对账隔离目录的产出时，累积档路径**必须显式指定**，否则会拿正式目录的档案比对：
   python tools/verify_report.py \
       --report  output/_xday-verify/2026-09-19/iran-digest-2026-09-19.md \
       --records output/_xday-verify/2026-09-19/records-2026-09-19.jsonl \
       --archive output/_xday-verify/ALL-records.jsonl
   ```
   实测：隔离目录跑出 2741 条（与正式目录同日 2845 条同量级，无塌陷），对账 170 项全绿。
6. `python tools/verify_report.py --save` → **回源对账**（当前 171 项）：
   报告里每个数字都能由落盘数据逐项复算，且「关注域口径 vs 当事方口径」
   「§4 与 §1 同值」「§8 与 §1 的差额 = 日期不可解析数」「快照 ⊆ 累积档」均自洽。

> **程序日志全绿也可能每个数字都错。** 第 6 步是唯一的数字级门禁，
> 结果留档在 `output/_verify_last.json`。
> 而对账工具**自身**也必须被验证：它曾硬编码快照路径日期，跨天后继续报
> 「26 项一致、全绿」，但核对的是**前一天的旧快照**。
> → 任何核对工具都必须默认取**最新日期目录**、支持覆盖（`--date` / `--report` /
> `--records` / `--archive`）、并把**实际读取的路径打印在输出首行**。
> ★ 本轮又踩到同一个坑的另一面：`--archive` 原先写死为正式目录的累积档，
> 于是对账隔离目录产出时拿错文件、报出「快照记录不在累积档」的**假告警**。
> **凡是被对账的路径，一个都不能写死。**

### 7.10 口径分级与信源等级是**两个正交维度**★

- **口径**：披露值（官方直接给出）vs 推断值（机构估算 / 媒体转述）
- **等级**：T1 官方一手 / T2 官方分析 / T3 专业媒体 / T4 自媒体

报告里「财政部 OFAC 文件里的数字」和「商业媒体转述的分析结论」会**并列排布**，
不标等级读者就默认同等可信 —— 这是这类报告最容易被误用的地方。
另外，**金额口径不可混用**：授标/义务（obligation）≠ 实际支出（outlay），
不可相加、不可同名。

## 八、阅读报告时的硬约束

- **不要跨方比条数**。两侧的**可采集性不对等**（见 §11 偏差 11）：伊方有多个可直接
  静态抓取的官方源（sepahnews 100 条、parstoday 120 条），而美方一手面主要靠国防部
  三个 feed + DVIDS + 聚合器（CENTCOM 官网 JS 渲染、海军与参联会 RSS 端点不可用）。
  比条数会**系统性高估伊方表态量**。
- **`—` 不是 `0`**。未收录的周与无法定位时间轴的记录一律渲染 `—`，
  表示「这段我们没在收 / 无法定位」，不是「没有发生」。
- **§4 的分值不是概率**（见 §一 第 4 条与 §11 偏差 5）。
- **§8 的信号分值是启发式**，衡量的是**公开发声活跃度**，
  不可跨周直接比大小，更不可当作任何一方的真实战备强度或战力对比。
- **§5 的实体是「被提及」**，不是状态描述。
- **周粒度粗于事件**：同一周内相隔数天的两次事件会被并入同一行。
- **波斯语信噪比天然更低**：词表覆盖一定不完整，伊方记录的漏检率高于英文源 ——
  这是本项目的结构性短板，已在 §11 偏差 4 明示。

## 九、合规底线（不可协商）

只抓**公开**内容：政府机构 RSS/API、官方通讯社 RSS、公共媒体 RSS。
遵守 robots.txt；不抓需登录内容；**不做任何风控绕过**
（不模拟浏览器指纹、不绕 Cloudflare/Akamai 挑战）。
被拦截或端点失效的源**停用留档**并标注原因，不用绕过手段强行取数。
**不抓实时船舶/航空定位（AIS/ADS-B）类受限数据**，也不做任何打击效果、
军事能力或核能力的评估，不给出「何时会发生什么」的预测 ——
本报告是**公开信息整理的索引**，不是决策依据。
`--from-file` 提供完全离线的退路：用浏览器另存内容即可合法完成解析。
