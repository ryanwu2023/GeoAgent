# defense-spend-monitor — 美军弹药库存与军费开支监测

围绕**持续冲突（如美伊冲突）会延续还是收束**这一问题，从公开数据源收集
**军费开支**与**武器弹药采购/库存**证据，输出可供大模型直接阅读的结构化 Markdown 日报。

```
spend_monitor.py   主程序（纯 Python 标准库，零依赖）
config.json        数据源 / 词表 / 信号词典 / 相关性阈值
run.bat            一键运行
tools/             开发辅助探针（probe_api.py 等），日常无需使用
feeds/             --from-file 离线模式用的本地转存文件
state/seen.json    去重状态
output/            产出（按日期分目录）
```

---

## 一、快速开始

```bash
python spend_monitor.py
```

**不要手动指定代理端口。** 程序会自动读取系统代理并打印实际出口，例如：

```
出口：系统自动探测 -> http://127.0.0.1:63299
```

> ⚠️ 代理端口会变（实测同一天内从 `7897` 变成 `63299`）。
> **永远不要把端口写死在脚本或快捷方式里**，否则表现为「所有源突然全挂」，
> 而症状和「被风控拦截」一模一样，极难排查。

常用参数：

| 参数 | 说明 |
|---|---|
| `--days 60` | 回溯天数（覆盖配置里的 `lookback_hours`） |
| `--backfill` | **历史回填**：把时间窗拉到 `config.history.start`（美伊冲突起始月），并强制重算全部历史月份。**首次建立时间序列时跑一次**，之后不必再跑 |
| `--no-history` | 本次不更新历史序列（只出日报），适合只想刷新当天快照时用 |
| `--sources treasury-mts,gao-reports` | 只跑指定源（调试单个源用） |
| `--show-all` | 不做相关性折叠，正文列出全部记录（全量审阅） |
| `--from-file feeds` | **离线模式**：读 `feeds/<源id>.xml` 或 `feeds/<源id>.json`，完全不联网 |
| `--proxy http://127.0.0.1:63299` | 显式指定代理出口 |
| `--direct` | 绕过系统代理直连。**多半会让所有源失败**，只在确认无代理时用 |
| `--no-seen` | 忽略历史去重状态，全部按新增处理 |
| `--reset-seen` | 清空去重状态后退出 |
| `--selftest` | 跑离线自检（111 项，不联网） |
| `--quiet` | 只输出一行 JSON 结果 |

**首次建库 + 日常更新**：

```bash
python spend_monitor.py --backfill     # ① 只跑一次：把 2026-02 至今的历史序列全量拉出来
python spend_monitor.py                # ② 之后每天跑这个即可（增量刷新最近月份）
```

> 增量为什么不会丢历史：财政部固定拉最近 13 个月，USAspending 合同源 `window_days=365`，
> 联邦公报月计数带本地缓存（历史月不再重复请求）；只有 `--backfill` 会强制重算全部月份。
> **实测同一份数据在 `--backfill` 与日常增量两种模式下产出的趋势报告表值完全一致**（自检 + 手工比对），
> 说明日常运行不会把基线月冲掉。

交付前请跑三项：

```bash
python spend_monitor.py --selftest        # ① 逻辑自检（词边界、单位换算、落盘合并、信号排除、信源等级、月份换算、加总一致性、事件闸门）
python tools/verify_numbers.py           # ② 数字回源对账（联网，逐项与官方 API 比对 + 逐月序列闭环）
```

`tools/verify_numbers.py` 是**对账工具**，不是爬虫：它把 `metrics-*.json` 里的每个金额
重新向财政部 MTS / USAspending 拉一次原始值逐项比对，并复算派生指标。**只要有一个数字
对不上就返回非零退出码**，可直接放进定时任务里当数据质量闸门。

它默认核对**最新日期目录**的快照，并把实际核对的文件路径打在输出首行；
也可 `--date 2026-09-18` 或 `--metrics <路径>` 指定。

> ⚠️ **这个工具曾经把日期写死**（`output/2026-09-17/...`），跨天后仍然「全绿」，
> 但核对的是前一天的旧快照。**一个对着错文件说 OK 的校验工具比没有校验更危险** ——
> 所以取快照的逻辑必须动态，且必须把自己核对了哪个文件打印出来。

## 二·补、这些数字准不准？（口径分级，务必先读）

本项目的数字**不是同一可信度**，混用会得出错误判断：

| 数据 | 来源 | 可靠级别 | 已验证方式 |
|---|---|---|---|
| 国防部月度/累计**净支出** | 财政部 MTS（官方） | **一手权威** | 逐项回源，差 0.00 ✅ |
| 弹药导弹类**授标金额** | USAspending（官方） | **一手权威** | 逐项回源，差 0.00 ✅ |
| 弹药合同单笔金额 | USAspending | 一手，但**有 1–3 月发布滞后** | 逐项回源 ✅ |
| 逐月序列（支出 / 弹药义务 / 政策文档数） | 财政部 + USAspending + 联邦公报 | **一手权威** | 逐月回源 + **加总闭环差 0.00** ✅ |
| **库存水平 / 消耗比例** | CBO、GAO、新闻转述 | ⚠️ **间接推断，非披露值** | 无法回源，只能看原文片段 |

> 交付时的对账结论**不写死在本文件里** —— 日报 §10 会读取 `output/_verify_last.json`，
> 显示**最近一次**对账的项数、时间与范围。写死「N 项差 0.00」必然过期，
> 而**过期的「已验证」比不写更误导**。

> 🔴 **「库存」没有绝对数量**。公开渠道**不存在**美军弹药/拦截弹库存的实时或定期数量披露。
> 报告里的库存判断只有三类间接来源：① CBO/GAO 分析中的**相对表述**（如「已消耗库存的
> 一半到三分之二」）；② 承包商扩产、交付延迟的公开报道；③ 补货合同与对外军售通知。
> **任何具体库存条数都是推断。** 需要准确库存量只能依赖 GAO 受限报告或国防部内部数据。
> 军费数字与库存判断**不在一个可信层级**，请勿等同看待。

### 每条信号都带原文片段

信号是在**完整正文**上计算的，而归档里的 `summary` 会被截断到 1200 字 —— 如果不保留片段，
读者就无法核对某条信号是否真的成立。因此每个信号都写入 `context` 字段（前后各留若干字符），
并在日报的证据板表格里直接展示：

```json
{"bucket": "stress", "weight": 3, "phrase": "depleted",
 "context": "…CBO estimates the conflict has consumed between one-half and two-thirds of the U.S. inventory of certain missile-defense interceptors…"}
```

**请把日报证据板里的「原文片段」列当作核对入口** —— 那里能看到触发判断的原句，而不是只看到结论。

## 二·补二、信源等级（T1–T4）—— 每个数字都标它有多可信

上表是**口径**分级（一手/推断），本节是**信源**分级（谁发布的）。两者都要看。

### 为什么必须分

报告里会同时出现这两种东西：

- 「国防部月度净支出 **$67.92B**」← 财政部 API 的原始记录，可逐项回源，**差 0.00**
- 「拦截弹**已消耗三分之二**」← Defense News 转述 CBO 报告，**原始 CBO 报告本报告都没直连**

不标等级，读者会把两者当成同等可信。**这是这份报告最容易被误用的地方。**

### 四个等级

| 等级 | 含义 | 本项目中有哪些源 | 怎么用 |
|---|---|---|---|
| `T1` 🟢 | **官方一手**（原始记录/法律文件） | 财政部 MTS、USAspending、联邦公报、govinfo 公法、国防部合同公告 | 可直接引用为事实，附 API 端点/文号 |
| `T2` 🟡 | **官方分析/审计**（机构估算） | GAO 报告、**CBO 出版物（RSS）、CRS 报告（congress.gov API）** | 可引用为「官方估算」，**不是披露的精确值** |
| `T3` 🟠 | **专业/商业媒体**（二手转述） | Defense News、USNI News | **仅作线索索引**，引用前必须回溯原文 |
| `T4` 🔴 | **自媒体/社交平台** | 无（**本报告不采集**） | 不采用 |

### 两条最容易搞错的判定原则

1. **「官方机构」≠ T1。** GAO / CBO 发布的是**分析与估算**，不是原始记录 ——
   数字是算出来的，带假设与口径，所以是 T2。
2. **转述官方结论的媒体仍是 T3。** 等级看的是**你手上这份材料由谁加工**，不是它引用了谁。
   「Defense News 转述 CBO 报告」不因源头是官方就升级；要升到 T2，必须实际取到 CBO 报告本身。

> 另外：等级与「证据层」（拨款/合同/支付）是**两个正交维度**。
> 层回答「在战争链条的哪一环」，等级回答「这条信息有多可信」。
> 一条**支付层**信息如果是媒体转述的，它并不比一条**合同层**的官方记录更硬。

### 报告里体现在哪

| 位置 | 内容 |
|---|---|
| §0 状态表 | 新增「等级」列；并给出当前快照的等级分布 |
| §1 一页速览 | **每个关键数字后面直接跟来源源 + 等级** |
| §8.1b | 信号桶 × 信源等级 **交叉表**，并自动判定该桶能否直接引用 |
| §8.2 证据板 | 每个命中短语带等级；某桶全为 T3 时**自动打警告** |
| 附录 D.1 | 等级定义与判定原则 |
| 附录 D.2 | **完整信源清单（含停用源）**：等级 / 发布主体 / 证据层 / 状态 / 可回源程度 |
| 附录 D.3 | **关键事实 → 溯源路径**：每个数字映射到 API 端点或原文 URL |
| 附录 D.4 | 明确声明不采用的来源类型（T4） |
| 附录 D.5 | 等级分布与占比 |

`records-*.jsonl` 每条记录都带 `tier` 与 `publisher` 字段，可直接按等级筛选/重排。

### 当前实例（会被程序自动标注）

**「产能/库存压力」桶已不再是「全部来自媒体」** —— T2 直连源已补齐（见下），
但**绝对库存数量仍然没有公开披露**：

- 🟢 新增 T2 直连：**CBO 出版物 RSS** + **CRS 报告 API**。已直连捕获
  《Estimating the Cost of Combat Operations Against Iran》（`cbo.gov/publication/62756`），
  即此前只能靠商业媒体二手转述的那条证据的**原始出处**。
- ⚠️ 但 CBO 的**正文页对数据中心 IP 返回 403（Akamai）**，只有 RSS 可通 ——
  因此本报告直连到的是**标题 / 摘要 / 链接 / 发布日期**，正文需人工点开。
  这条可达性边界如实写在日报附录 D.3，**不做风控绕过**。
- 🔴 库存的**绝对数量**在任何公开渠道都不存在，这一点没有因为接了 T2 而改变。

> **T3 源仍然必须保留。** 官方源无人转述时也会漏掉关键事件，只是它们进报告后要带等级、只能当线索。

## 二、产出文件

每次运行写入 `output/<日期>/`：

| 文件 | 内容 |
|---|---|
| `spending-digest-<日期>.md` | **主日报**。一眼速览 + 五个证据层 + 战争走向证据板 |
| `war-trajectory-<日期>.md` | 证据板单页版（信号桶 + 观察点） |
| `records-<日期>.jsonl` | 结构化记录（每行一条，含来源链接、金额、弹药词、信号、相关性分、**`tier` 信源等级、`publisher` 发布主体**） |
| `records-<日期>.json` | 同上，JSON 数组格式 |
| `metrics-<日期>.json` | 财务与合同指标快照 |

`output/LATEST.md` 是最新日报副本，`output/ALL-records.jsonl` 是**跨天累积总档**（见下），
`output/index.md` 是归档索引。

### 历史时间序列（回答「在往哪个方向走」）

单日快照只能回答「现在是多少」，回答不了趋势。因此另有一套**逐月序列**产出：

| 文件 | 内容 |
|---|---|
| `LATEST-trend.md` / `history/trend-<日期>.md` | **趋势报告**（人读）：军费实际支出、弹药合同义务、政策活动、信号计数、官方事件时间线、加总一致性、已知偏差 |
| `history/series.jsonl` | 序列长表（机读）：每行 = `{metric, period, value, unit, caliber, source_id, tier, traceable, kind, note}` |
| `history/fr-monthly.json` | 联邦公报月计数缓存（历史月不重复请求） |
| `_title_gate_audit.json` | 被标题闸门过滤掉的标题留档 |
| `_event_filter_audit.json` | 被事件闸门挡下的候选留档（见下） |

序列覆盖**战前基线月 → 开战 → 至今**。基线月是刻意保留的：没有基线就算不出
「开战后是战前的几倍」，只会得到一条从开战起就单调的曲线，看不出跳变。

| 序列 | 口径 | 等级 | 最新观察 |
|---|---|---|---|
| 财政部国防科目实际净支出 | `actual net outlays`（真金白银出账） | `T1` | 战后峰值 2026-07 $86.05B；战后均值/战前基线 = **0.91 倍** |
| USAspending 弹药导弹类合同义务 | `Contract_Obligations`（签了合同的钱） | `T1` | 战后峰值 2026-03 $9.72B；战后均值/战前基线 = **3.25 倍**（已剔除 9 月财年末） |
| 联邦公报月文档数 | 官方 `count` 字段 | `T1` | DPA 相关峰值 2026-05（93 份） |
| 监测信号计数 | 本监测自身收录量 | ⚠️ **启发式** | 只能看方向，**不是官方统计** |

> 🔴 **四条必须先排除的误读**（报告 §6 已逐条写死）：
> ① 9 月是**财年末**，义务额例行暴涨，不可读成战争强度，跨年比较要同月对同月；
> ② USAspending 有 1–3 个月**发布滞后**，最近月份偏低甚至为 0 属正常，不是「补货停了」；
> ③ 支出（outlay）与义务（obligation）**不可相加、不可直接比大小**；
> ④ 监测信号计数受**收录覆盖度**影响，某月下降可能只是某源当月无更新。
> 未收录的月份一律渲染成 `—` 而不是 `0` —— **空 ≠ 零**。

### 官方事件时间线：四道闸门 + 过滤留档

趋势报告 §5 的时间线只收**官方一手/官方分析层**的事件（T1/T2），因为时间线的意义是
「官方在哪个月做出决定」，二手转述会把时间点变成「媒体哪天报道」。

进线要过四道闸门：① 只 T1/T2 → ② 相关性达阈值 → ③ **主题锚定** → ④ 一条记录只归首个命中规则。

第 ③ 道是实测踩坑后加的：`Presidential Determination` 是宽词，**只靠相关性挡不住** ——
这些无关决定书的摘要里有战争泛词，刚好凑到 `relevance=6` 越过了阈值：

| 被挡下的（真实语料） | 为什么无关 |
|---|---|
| Emergency Presidential Determination on **Refugee Admissions** | 难民配额 |
| Presidential Determination … Joint Base Andrews **Golf Course** | 基地高尔夫球场整修 |
| Presidential Determination on … **Peaceful Uses of Nuclear Energy**（沙特） | 核能合作协议 |
| Presidential Determination on Assistance to **Venezuela** | 对委援助 |

**为什么用「锚定」而不是删掉宽词、或加黑名单**：

- 删掉 `presidential determination` 会**连真信号一起删** ——
  `Presidential Determination Pursuant to Section 1245 of the NDAA`
  （§1245＝对伊朗金融制裁条款）就是这样一条真信号，标题里只有这个词组；
- 黑名单是穷举，遇到没想到的噪声就失效；锚定是正向条件，不会因未预见的噪声而放行。

**被挡下的候选逐条留档**在 `_event_filter_audit.json`（含标题/等级/相关性/命中规则/原因），
可以直接复核「没进时间线」到底是真无关、还是**收紧词表时删过头了**。

> 这与 `_title_gate_audit.json` 是同一条纪律：**压假阳性最容易连真信号一起删掉**，
> 没有留档就无法复核。自检里专门有一条用例，用**真实语料里的 `relevance=6`** 测这批噪声
> —— 合成样本给它们 0 分会掩盖「摘要泛词把噪声抬过阈值」这个真问题。

### ⚠️ 快照语义（先读这段，否则会误判数据量）

`LATEST.md` 与各日 `spending-digest-*.md` 都是**滚动窗口快照**：收录**抓取窗口内抓到的全部记录**，
而不是「只有当天新增的那几条」。

| | 窗内记录 | 本次新增 | LATEST.md 条数 |
|---|---|---|---|
| 第 1 天 | 20 | 20 | **20** |
| 第 2 天 | 22（含昨天 20 条） | 2 | **22** ← 不是 2 |
| 第 2 天重跑 | 22 | 0 | **22** ← 不缩水 |
| 第 3 天（旧记录掉出窗口） | 3 | 3 | 3（累积档仍有 25） |

- 第 0 节分别标注「本次新增 N 条」与「当前快照 M 条」，两个数含义不同。
- **掉出时间窗的记录不会丢** —— 它们在 `ALL-records.jsonl` 里，按 `id` 去重长期累积，
  每条带 `first_seen`（首次出现的日期），适合做跨越数月的长周期分析。

> 落盘采用**按 id 与窗口内全部记录合并**的策略：同日重跑**不会**覆盖当天数据，
> 跨天运行**也不会**丢掉仍在窗口内的历史。
> 这个坑曾经真实存在（跨天时 LATEST.md 会退化成只有当天新增的几条），原因详见代码注释与自检用例。

## 三、核心设计：三级证据链 + 两层旁证

这份报告的分析骨架是**钱和弹药的时间顺序**：

```
拨款层  govinfo 公法 / 联邦公报总统决定书(DPA、506(a)(3) 裁减授权)
          → 有没有新钱、有没有新的扩产或动武授权        【领先】
              ↓
合同层  USAspending 弹药导弹类(PSC 13xx/14xx)新签合同 + PSC 分类聚合
          → 弹药补货速度 = 打得起的物质基础
              ↓                                        【滞后 1–3 个月】
支付层  财政部 MTS 表5 国防科目月度实际净支出
          → 真金白银出账节奏（最硬、最慢）

旁证：审计层 GAO（官方自己承认的产能/库存瓶颈） · 新闻层（线索，须回溯官方源）
```

**读法**

- 三段**同向走强** → 「持续/升级」的强证据
- 三段**同向走弱** → 「降级/结束」的强证据
- **拨款层放量而支付层停滞** → 钱批了但没花出去（产能或流程卡点）
- **合同层放量而支付层不动** → 合同是授标总额，不等于当期支出，不要混为一谈

报告 §8 会给出三个信号桶（🔴 持续/升级、🟢 降级/结束、🟠 产能/库存压力）的计数与加权净值。

> ⚠️ **净值是启发式证据索引，不是预测模型。** 它按短语命中计数，**不理解语境** ——
> 「停火谈判破裂」也会被计成降级信号。权重是人工先验，未经回测。
> 请把它当作**检索入口**：沿着它给出的链接去读原文，再自己下判断。
> 报告里已把这个局限写在 §8.2。

### 相关性折叠（GAO / 新闻源必读）

GAO 与新闻的 RSS 返回的是**全部主题**的最新条目。为压低噪声，正文按
**标题强主题词锚定**做过滤（配置项 `topic_title_terms`）：

- 只有当「正文含弹药/导弹武器术语」或「**标题**命中强主题词」或「本身是 PSC 过滤出的合同」
  才算相关，其余在正文中折叠并在该节注明折叠条数
- **折叠的记录仍完整写入 JSONL 归档**，不会丢。要全量看就加 `--show-all`
- 相关性分写入每条记录的 `relevance` 字段，可自行重排序或调 `relevance_min`

设计上踩过的两个坑（已在代码注释中固化）：

1. **不能只用摘要关键词判定** —— 否则《房贷保险》《空管系统现代化》会靠
   `budget`/`inventory` 这类泛化词混进来
2. **不能只看摘要** —— 《Arms Sales Notification》（对外军售通知）是核心文件，
   但标题通用、没有摘要，纯靠摘要关键词会被判 0 分**全部误杀**（实测 6 份）

## 五、常见问题排查

按 `crawler-source-triage` 技能的**四层模型**，依次排除：

| 症状 | 层 | 先查什么 |
|---|---|---|
| 所有源全挂 | ① 网络 | **先打印实际出口**（本程序每次都会打印）。端口写错、或误加 `--direct`，症状与被风控完全一样 |
| 部分源 403 | ② 风控 | 看 `Server` 头：`AkamaiGHost` / `cloudflare` 是出口 IP 被拦，换出口或停用该源，别硬刚 |
| 200 但没数据 | ③ 源可用 | 看状态表的「源内最新」列，和今天差几天。差很多就是**源停更**，不是代码问题 |
| 数据有了但字段空 | ④ 解析 | 用**真实数据**跑一遍看产出；合成样本永远测不出词边界和单位换算的坑 |
| 日报比上次小 | 落盘 | 检查是否踩了「同日重跑覆盖」——本程序已按 id 合并防护，配 `--selftest` 回归测试 |
| 正文看不到某条记录 | 过滤 | 该记录 `relevance` 低于阈值被折叠，加 `--show-all` 确认 |
| 官方事件时间线混入无关条目 | 闸门 | 宽词（如 `Presidential Determination`）未过主题锚定。查 `_event_filter_audit.json` 的 `dropped` 段，可复核是否删过头 |
| 弹药金额比预期小几个百分点 | 截断 | USAspending 不显式传 `psc_codes` 时只按金额返回前 100 个 PSC 类，**弹药小类会被静默截断**（实测少算 $2.42B / 6.1%）。必须显式传 PSC 码表 |
| 月度序列整体偏移约 9 个月 | 换算 | USAspending 的 `period` 是**财年月**（`FY2026-P01`＝2025-10），必须换算成日历月。换算错会整体偏移 9 个月 |
| 9 月数字异常高 | 财年末 | 美国财年 9 月 30 日结束，9 月义务额例行暴涨，**不是战争强度**。本程序已把 9 月剔出战前基线 |

单个源调试：

```bash
python spend_monitor.py --sources treasury-mts
```

探针脚本（判断源是否还活着）：

```bash
python tools/probe_api.py --get "https://api.fiscaldata.treasury.gov/services/api/..."
python tools/probe_api.py --post "https://api.usaspending.gov/api/v2/search/spending_by_award/" --body tools/body_munitions.json
```

## 六、怎么扩展

### 加一个新的 RSS 源

在 `config.json` 的 `sources` 里追加：

```json
{
  "id": "my-source",
  "name": "我的来源",
  "kind": "rss",
  "layer": "新闻层",
  "enabled": true,
  "url": "https://example.com/feed",
  "url_alternates": ["https://mirror.example.com/feed"],
  "window_days": 30,
  "stale_after_days": 30
}
```

`stale_after_days` 可按源覆盖全局阈值。**数据本身发布就慢的源必须单独放宽** ——
例如 USAspending 新签合同有 1–3 个月发布滞后，用全局 30 天会让它一直误报停更
（本项目把它设为 120 天）。

失效的源把 `enabled` 改成 `false` 并写清原因，**不要删除** —— 留下记录，日后可恢复。

### 调词表

- `munitions_terms` — 弹药/导弹型号词。**一律用字母数字边界匹配**，
  短词必须验算它可能嵌在哪些常见单词里（`Patriot` 会命中 `patriotic` 吗？不会，因为有边界；
  但 `warhead` 这类要多加小心）
- `signal_lexicon` — 三个信号桶的短语与权重。**不要放太泛的短语**
  （如 `GAO recommends`），GAO 报告几乎每篇都有，会把整个桶灌成假阳性（实测过）
- `topic_title_terms` — 相关性锚定的**标题**强主题词
- `extra_keywords` — 辅助关键词，只加分、不单独构成锚定
- `munitions_context_exclude` — 排除词组，如 `Patriot Act`

## 六·补、每天自动更新

历史序列**建一次**，之后每天只做增量。`config.json` 的 `schedule` 段记录计划
（`time_local: "08:30"`、`timezone: "Asia/Shanghai"`、`cadence: "daily"`），
程序自身**不常驻**，由外部调度器触发。

日常命令就是不带参数的那条：

```bash
python spend_monitor.py
```

Windows 下用 `run.bat`（已随项目提供）挂到「任务计划程序」即可：

```
任务计划程序 → 创建基本任务 → 每天 08:30 → 启动程序 → run.bat
```

`run.bat` 会依次跑 **① 离线自检 → ② 抓取 → ③ 回源对账闸门**，任一步失败即返回非零退出码。
**挂到计划任务时必须设 `DSM_NO_PAUSE=1`** —— 否则末尾的 `pause` 会让任务永久挂住。

```
set DSM_NO_PAUSE=1   （在任务计划程序的「操作」里作为环境变量或包一层 cmd /c）
```

首次建立历史序列要先跑一次 `run.bat --backfill`，之后每天跑 `run.bat` 即可。

也可以在 WorkBuddy 里配一个**每日自动化**，让它每天定时执行上面那条命令。

> 建议在计划任务里**串上数据质量闸门**：`verify_numbers.py` 有任何一项对不上就返回非零退出码。
> **程序日志全绿也可能每个数字都错** —— 日志只说明「没报异常」，不说明「数字对」。
> 想看逐月序列的完整对账（较慢），手动跑 `python tools/verify_numbers.py` 不带 `--skip-months`。

## 七、合规

- 全部为**公开**来源：政府数据 API、政府机构 RSS、公共媒体 RSS
- 遵守 `robots.txt`；不抓取需登录内容
- **不做任何风控绕过**（不模拟浏览器指纹、不绕 Cloudflare/Akamai 挑战）
- 不抓取实时船舶/航空定位类受限数据
- 每条记录均保留原始链接与发布时间，可逐条溯源
- 本工具只做**公开证据汇总与机械计算**，不构成结论、不构成投资建议
