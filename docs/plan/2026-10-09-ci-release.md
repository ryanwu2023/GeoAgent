# GeoAgent CI/CD 完善计划

范围已确认：测试仅构建与自动化验证，不部署测试站点；正式环境沿用 Sealos、SQLite 和现有域名。

参考 PiChat 的验证、制品、手动生产发布、健康检查、独立手动回滚和证据留存流程，适配为 Kubernetes 镜像发布。

## 实施与验收

1. 分支/MR 自动构建、TypeScript 检查、完整后端测试、JUnit 报告；测试 tag 导出镜像制品。
2. 正式 tag 必须受保护且已合入 main；先验证，再手动部署同一份镜像制品，避免二次构建差异。
3. 生产部署和回滚共用环境互斥锁；记录前后镜像、提交、流水线；拒绝过期流水线覆盖新部署。
4. 发布前检查采集任务，使用 SQLite backup API 备份数据库；只更新应用镜像，保留 PVC、Secret 和 sidecar。
5. 部署后检查 rollout、内部 API 和网关路径；失败记录真实状态，不自动恢复数据库。
6. 独立手动回滚读取该流水线保存的旧镜像，校验当前镜像和发布标识，避免旧回滚按钮覆盖后续发布；回滚后重新检查。
7. 编写正式发布、测试 tag、回滚、数据恢复边界、变量和故障处理文档，并在 GitLab 验证真实执行。

## 边界

- 不新增测试站点或测试数据库；测试使用隔离的临时数据。
- 不把 PiChat 的服务器路径、数据库重建、产品或沙箱发布逻辑复制到 GeoAgent。
- 不自动回滚数据库，不承诺不兼容数据库变更可直接回退代码。
- SQLite 单副本 Recreate 会有短暂中断；零停机不是本次目标。
- 数据库备份保留在现有 PVC，是发布前恢复点，不等于异地灾备。
