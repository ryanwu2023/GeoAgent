## 2. 已确认的项目事实

### 2.1 爬虫源码和运行数据不是一回事

- 爬虫源码位于 `collectors/`，注册表为 `collectors/collectors.json`。
- 统一入口为 `scripts/collect.py`。
- 当前注册 19 个采集器，共 111 个爬虫 Python 文件。
- 真实运行输出预期写入 `data/collector-output/<collector>/output/`。
- `data/collector-output` 当前不存在。
- `backend/paths.py::collector_read_root()` 在找不到真实输出时，会回退到 `examples/demo-data`。
- `examples/demo-data` 约 1.3 MB；当前本地 `data` 约 6.3 MB。
- 当前 `data/research.sqlite3` 中有 1 个快照、948 条快照记录、5 条历史问答。它们来自 Demo 导入，不能当作实时或完整爬虫数据。
- `data/` 已被 Git 忽略，不要提交 SQLite、归档或真实爬虫输出。

### 2.2 当前数据链路

```text
collectors/*
  -> scripts/collect.py / scripts/refresh_crawlers.py
  -> data/collector-output（不存在时回退 examples/demo-data）
  -> backend.adapters.load_bundle()
  -> 字段归一化 / URL 清洗 / 精确 URL 去重 / 分类 / 原始文件归档
  -> data/research.sqlite3 不可变快照
  -> FastAPI
  -> React 地图、证据台账、指标、问答与简报
```

### 2.3 已确认的主要性能瓶颈

原 `/api/workspace` 会一次返回某主题下的全部证据摘要，同时还返回地图、指标、来源、项目、资产和情景数据。前端虽然只渲染约 30 行，但仍接收、解析、保存并搜索整个证据集合。

因此首要问题不是 React 卡片数量，而是接口载荷边界：列表搜索与地图数据被绑在同一个全量响应中。
