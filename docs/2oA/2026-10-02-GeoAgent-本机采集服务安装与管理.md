## macOS LaunchAgent 管理

先检查，不改变系统状态：

```bash
.venv/bin/python -m scripts.collector_service_ctl status --platform macos --dry-run
```

安装或更新本机采集服务：

```bash
.venv/bin/python -m scripts.collector_service_ctl install --platform macos --exclude-id taco-monitor
```

当前本机验收阶段暂时排除 `taco-monitor`。这是调度层的显式排除，不会删除注册表配置；恢复 TACO 时重新安装时去掉该参数即可。

这条命令会生成/更新项目内 plist，并执行：

```text
launchctl bootstrap gui/$(id -u) /Users/yujunjun/opensource/GeoAgent/data/service-config/com.geoagent.collector.plist
```

查看真实状态：

```bash
.venv/bin/python -m scripts.collector_service_ctl status --platform macos
```

停止并移除 LaunchAgent 注册：

```bash
.venv/bin/python -m scripts.collector_service_ctl uninstall --platform macos
```

重新安装前推荐先卸载，再安装；安装命令会复用项目 `.venv`，不会切换到系统 Python。

## UI 调度配置与采集后的产物

本地页面 `http://127.0.0.1:8010/` → **采集管线监控** → **调度配置**提供服务级配置：

- **全局采集间隔（分钟）**：对应 `scripts.collector_service` 每轮完成后的 `sleep(interval_sec)`；当前不是每个采集器各自的墙上时刻 cron。
- **排除采集器**：写入项目目录的 `data/service-config/collector-settings.json`，例如验收阶段保留 `taco-monitor` 排除。
- **允许部分成功进入导入门禁**：默认关闭；打开后部分成功 run 才可能进入自动导入。
- **自动导入快照**：当前后台服务固定开启。采集结果通过 staging/发布门禁后，服务调用导入逻辑生成不可变 snapshot；失败或门禁跳过会写入运行报告和账本。
- **简报生成**：不会随每轮采集自动生成。顶部 **生成简报** 是基于当前选定 snapshot 的独立分析动作，生成两个主题的研究简报。

点击 **保存并应用** 会更新项目内 JSON，并重新安装当前平台的 LaunchAgent/Task Scheduler；它可能让后台服务从新配置开始下一轮。顶部 **更新快照** 仍是人工导入已发布采集产物，不会启动采集器。

实际链路为：

```text
后台定时任务
  -> collector_service 执行 enabled 采集器
  -> staging / 输出门禁 / 发布 data/collector-output
  -> --auto-import 导入不可变 snapshot
  -> UI 风险监测、证据、指标、问答读取选定 snapshot
  -> 用户需要时点击“生成简报”产生研究简报
```

配置 API 为 `GET /api/collector/config` 和 `PUT /api/collector/config`；API 返回 `source=launch-agent` 或 `source=project-settings`，用于区分当前配置来自现有后台任务还是项目配置文件。

## 状态、日志与数据核对

```bash
# 服务状态
.venv/bin/python -m scripts.collector_service_ctl status --platform macos

# 查看最新账本运行
.venv/bin/python - <<'PY'
from pathlib import Path
from backend.collector_ledger import CollectorLedger
for row in CollectorLedger(Path("data/collection-runs/ledger.sqlite3")).runs(5):
    print(row)
PY

# 读取服务日志
tail -f data/service-logs/collector.stderr.log
tail -f data/service-logs/collector.stdout.log
```

来源级状态（只读，不会触发网络探测）：

```bash
curl 'http://127.0.0.1:8010/api/collector/sources?collector_id=readiness-monitor'
```

接口只投影采集器已发布的 `_source_status.json`、`_fetch_stats.json`、`_source_health.json`；没有这些文件时返回 `available=false`。停用源会单列为 `disabled`，不计入失败。

运行状态要区分：`running`、`success`、`partial`、`failed`、`abandoned`。服务被终止时，下一次启动会把遗留的 `running` 记录标记为 `abandoned`，避免误显示为当前运行。
