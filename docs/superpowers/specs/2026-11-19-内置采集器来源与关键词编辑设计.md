# 内置采集器来源与关键词编辑设计

日期：2026-11-19
关联：[采集管线自定义配置设计](2026-11-11-采集管线自定义配置设计.md)

## 1. 需求

用户要求：采集管线配置页里，内置采集器也要像配置化管线一样有“基本信息 / 来源 / 关键词 / 版本历史”等标签，并且可以在页面编辑。

已确认的范围（2026-11-19 与用户确认）：

- **只改能改的。** 有来源列表（`config.json` 的 `sources`，每项带网址）的新闻类内置采集器开放编辑，共 16 个：asset-transmission、diplomacy、eu-domestic、geopolitical-source、iran-domestic、iran-escalation、israel、meeting-calendar、mideast、naval、opinion、readiness、ru-diplomacy、russia-domestic、ua-front、ukraine-aid（均为 `-monitor`）。
- **不能改的不动。** 数据序列类（finance-front、taco、defense-spend 等结构化接口）、没有配置文件的（xinhua、stcn、market-context 及转发类小采集器）保持只读，只显示基本信息。
- **不改造为配置化管线。** 仍跑原采集代码，分桶、立场、信号、基线、相关度打分等专有逻辑全部保留；页面只改它们的来源清单和词表。

## 2. 业务规则

1. 编辑以“覆盖层”保存，不改仓库里的 `config.json`：
   - 来源：按来源 ID 修改名称、网址、等级、启用、备注；新增来源（以同一采集器的已有来源为模板复制专有字段）；删除来源。
   - 词表：`config.json` 里所有“字符串数组”形式的词表（分桶词组、实体别名、立场词、信号短语、准入词、排除词等），按 JSON 路径整体替换。基线、报告、请求参数、来源清单本身、下划线开头的注释字段不列入。
2. 每次保存生成新版本（`collection_pipeline_versions`），记录修改人和修改说明，可回滚到任意历史版本。版本 1 是“与代码一致”的空覆盖层。
3. 生效时间：保存后从下一次运行该采集器（整批或单采）起生效，与配置化管线的启用规则一致；不单独定时。
4. 代码更新 `config.json` 时：覆盖层只覆盖用户改过的来源字段和词表，代码新增的来源、未改过的词表照常随代码更新；代码删掉的来源，其覆盖项自动忽略。
5. 名称、说明可改；主题、启停沿用原规则（主题由注册表决定，启停即“排除采集器”列表）。
6. 权限：沿用 `/api/pipelines` 仅管理员；远端采集模式（HFT）只读；PiChat 的 MCP 管线工具仍不能修改内置采集器（只管理配置化管线）。

## 3. 校验

- 网址：http/https，主机不能是内网/保留地址（复用配置化管线的主机检查）。
- 来源 ID：新增时必填，字母数字与 `-_`，在本采集器内唯一。
- 等级：只能选该采集器已用过的等级值。
- 词：去首尾空白，单个 ≤200 字符，每个词表至少 1 个词、≤2000 个；每个词必须能编译为正则（部分采集器把词当正则用）。
- 未知词表路径、未知来源 ID（修改/删除时）报 422 并指出字段。

## 4. 实现

- `backend/builtin_config.py`：可编辑清单、词表发现与命名、覆盖层计算/校验/合并、运行时写合并后的配置文件。
- `pipeline_service`：内置管线的 PATCH 与回滚走覆盖层；详情返回 `builtin` 视图（来源、词表、可选等级、是否可编辑）。
- 运行时：`scripts/collector_service.py` 组装注册表后，对有覆盖层的内置采集器写 `collector-output/<id>/state/config.override.json`，并经注册表 `env` 传 `GEO_COLLECTOR_CONFIG`；16 个采集器读取配置时优先用该变量。数据库不可用时不加覆盖层，按代码配置运行并告警。
- 前端：内置采集器显示“基本信息 / 来源 / 关键词 / 版本历史”；来源为表格式编辑（名称、网址、等级、启用、删除、按模板新增），关键词按词表分组显示，可搜索。
- 不涉及数据库结构变更（复用现有管线与版本表）。

## 5. 验收用例

| 编号 | 场景 | 预期 |
|---|---|---|
| BC-01 | 打开可编辑内置采集器 | 显示来源、关键词、版本历史标签，来源数与 config.json 一致 |
| BC-02 | 打开不可编辑内置采集器（如 TACO） | 只读，提示由代码维护 |
| BC-03 | 修改来源网址并保存 | 版本 +1；下次运行时采集器读到新网址 |
| BC-04 | 新增来源 | 继承模板专有字段，ID 唯一；重复 ID 报错 |
| BC-05 | 删除来源 | 运行配置中不再有该来源 |
| BC-06 | 修改分桶词表 | 运行配置中对应路径被替换，其它词表不变 |
| BC-07 | 输入内网网址 / 非法正则 / 空词表 | 422 并定位字段，不生成新版本 |
| BC-08 | 回滚到版本 1 | 覆盖层清空，运行配置与 config.json 一致 |
| BC-09 | 代码新增来源后 | 合并结果包含新来源，用户改动仍在 |
| BC-10 | 远端模式 / 非管理员 | 写操作被拒 |
| BC-11 | 数据库不可用 | 整批照常按代码配置运行 |

## 6. 试跑与测试运行（2026-11-20 补充）

用户要求：可编辑的内置采集器也要有“试跑”和“测试运行”，与配置化管线一致。只读内置采集器不变。

| | 试跑 | 测试运行 |
|---|---|---|
| 用哪份配置 | 页面草稿（含未保存修改） | 已保存的当前版本 |
| 跑哪些来源 | 相对已保存版本改动或新增的启用来源；没有改动时取前 5 个启用来源；最多 5 个 | 全部启用来源 |
| 怎么跑 | 原采集代码，同步，超时 150 秒，全局最多 2 个并发 | 原采集代码，后台运行，超时 900 秒，复用配置化管线的并发上限与互斥 |
| 结果 | 抽屉里按来源列出入选与被口径排除的条目、抓到的条数、抓取错误 | 运行记录 + “本次新增”（正式产物里还没有的条目） |
| 写什么 | 不写任何表和目录（临时目录用完即删） | 只写运行记录与本次新增；不进快照、不写去重台账、不碰正式输出和增量状态 |

隔离方式：
- 输出、状态都指向隔离目录（测试运行在 `.pipeline-trials/<采集器ID>/`），每次从空输出、空状态开始，结果只反映这一次抓取。
- 旧式采集器（注册表 `legacy_output`：伊朗升级、海军、战备）把输出和状态写在源码目录，先复制源码目录到隔离目录再运行。
- 导入扫描只看 `<采集器ID>/output`，不会扫到隔离目录。

限制：采集器只把通过关键词口径的条目写进产物（个别采集器另写被排除的条目），抓到但没命中词表的条目不逐条列出，抽屉里显示“抓到 N 条”帮助判断是网址问题还是词表问题。

| 编号 | 场景 | 预期 |
|---|---|---|
| BC-12 | 改一个来源后试跑 | 只跑这个来源，用的是未保存的新值，列出入选条目 |
| BC-13 | 未改动直接试跑 | 跑前 5 个启用来源 |
| BC-14 | 试跑草稿含内网网址 | 422 并定位字段，不运行 |
| BC-15 | 测试运行 | 运行记录 trigger=trial，本次新增只含正式产物里没有的条目，不写去重台账、不进快照 |
| BC-16 | 旧式采集器测试运行 | 在复制的源码目录里运行，源码目录的 output 不变 |
| BC-17 | 只读内置采集器 | 没有试跑、测试运行按钮；接口拒绝 |
