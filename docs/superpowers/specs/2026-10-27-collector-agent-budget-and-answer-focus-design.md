# 单采集器补采、智能问答预算与核心结论优化设计

日期：2026-10-27

## 1. 目标

本次改造解决三个问题：

1. 用户可以直接选择任意采集器单独重新采集，不必启动全部采集器。
2. 本地模型多 Agent 问答支持在页面配置单个子 Agent 超时、全部子 Agent 总超时，以及按人民币计价的单次问答费用上限。
3. 模型回答的核心结论直接围绕用户原始问题展开，不再优先陈述内部记录数、线索分布、维度覆盖或工具调用统计。

PiChat 嵌入问答保持现状；本次 Agent 预算只作用于 GeoAgent 本地模型问答。

## 2. 单采集器补采

### 2.1 交互

- 采集器列表中的每个采集器直接提供“单独采集”操作。
- 采集器详情继续保留“补采”操作，两处调用相同接口。
- 提交时只传入当前采集器稳定 ID，后台不得自动扩展为同主题或全量采集。
- 页面沿用当前批次、日志、来源状态、输出门禁和快照导入状态展示。
- 已有采集批次运行时，单采集器操作不可提交，并明确显示需要等待当前批次结束。

### 2.2 运行参数

单采集器补采使用明确的请求参数，不隐式沿用全量采集的长时间等待：

- 单次超时默认 300 秒；
- 默认尝试 1 次；
- 失败后用户可使用现有“重试失败项”操作；
- 成功后仍执行输出门禁和自动导入；
- 失败不得触发其他采集器。

全量采集行为本次不改变，避免在同一改造中同时调整采集调度策略。

## 3. 智能问答 Agent 配置

### 3.1 配置位置

在“连接与 MCP 配置”中新增“智能问答 Agent”页签。模型 URL、模型名称和 API Key 仍由“后台模型”页签管理，Agent 页签只管理运行策略。

配置保存在项目本地数据目录的独立 JSON 文件中，采用临时文件替换的原子写入方式。该文件属于运行数据，不提交 Git，不保存模型密钥。

### 3.2 配置字段

| 字段 | 默认值 | 有效范围 | 含义 |
|---|---:|---:|---|
| 单个子 Agent 超时 | 70 秒 | 5—300 秒 | 单个专业子任务允许的最长墙钟时间 |
| 全部子 Agent 总超时 | 150 秒 | 10—900 秒 | 本轮所有专业子任务共同允许的最长墙钟时间 |
| 最大并行子 Agent 数 | 2 | 1—3 | 同时运行的专业子任务数量 |
| 输入价格 | 空 | 大于等于 0，人民币/百万 Token | 用于估算输入费用 |
| 输出价格 | 空 | 大于等于 0，人民币/百万 Token | 用于估算输出费用 |
| 单次问答费用上限 | 空 | 大于 0，人民币 | 本地问答允许的估算总费用 |

总超时必须大于或等于单个子 Agent 超时。

### 3.3 未配置费用时的行为

- 单次问答费用上限留空时，不执行费用限制。
- 未设置费用上限时，输入和输出价格均可留空；若填写价格，仅用于页面展示估算费用。
- 设置费用上限时，输入和输出价格必须同时配置，否则拒绝保存。
- 价格为零是有效值，适用于内部免费模型；费用上限仍按零费用计算。

### 3.4 费用估算与限制

当前兼容模型接口不能保证都返回统一的 Token 用量，因此费用口径明确为“系统估算”，不是账单金额。

- 输入 Token 使用现有统一估算器计算系统提示、用户问题、工具回执和上下文。
- 输出 Token 使用模型返回正文计算。
- 估算费用公式为：

  `输入Token ÷ 1,000,000 × 输入单价 + 输出Token ÷ 1,000,000 × 输出单价`

- 调度新子 Agent 前，系统根据它的最大上下文额度和输出预留估算最坏费用并预留预算。
- 并发子 Agent 必须先成功预留预算才能启动，避免多个任务同时越过上限。
- 子 Agent 完成后以实际估算量替换预留量，释放未使用额度。
- 剩余预算不足时，未启动的子 Agent 标记为“费用上限降级”，主 Agent 继续使用已有证据形成最终回答。
- 费用限制只约束本地问答中的模型调用，不影响只读工具调用、采集器、翻译任务或 PiChat。

## 4. 超时与降级

- 单个子 Agent 达到单任务超时后，仅该任务降级，其他已运行任务继续。
- 全部子 Agent 达到总超时后，取消尚未完成的专业子任务。
- 超时和费用降级都写入可审计过程，包含 Agent 名称、原因、耗时和已完成的工具调用。
- 不向用户展示隐藏思维链，只展示任务目标、工具调用、阶段摘要和降级原因。
- 无论子 Agent 超时、费用不足、模型失败或引用复核失败，系统都必须基于已经取得的有效证据生成最终回答。
- 若完全没有可用材料，最终回答明确说明资料不足并列出下一步所需数据，不返回空答案。

## 5. 核心结论写作约束

### 5.1 回答优先级

最终回答第一部分必须直接回答用户原始问题，按以下顺序组织：

1. 当前状态；
2. 最新变化；
3. 基于证据的判断；
4. 后续走势取决于什么；
5. 用户问题涉及资产时，再说明条件性资产含义。

美伊问题不得以俄乌内容开头，俄乌问题不得以美伊内容开头。跨主题内容仅在确有传导关系时作为补充。

### 5.2 内部统计的位置

以下内容不得作为核心结论的主要表述：

- 快照包含多少条记录；
- 升级、持续、缓和或待研判各有多少条；
- 覆盖多少维度或多少来源；
- 调用了多少工具、读取了多少全文；
- 子 Agent 使用了多少上下文。

用户主动询问数据覆盖时可以直接回答；其他情况下，这些信息只能放入“口径与限制”或折叠的分析过程。

### 5.3 最终复核

最终复核增加以下检查：

- 第一段是否回答了原始问题；
- 第一段主题是否与问题一致；
- 核心结论是否被内部统计主导；
- 是否将媒体报道、单方声明和模型推论区分开；
- 降级情况下是否仍生成完整结论。

不符合时先尝试修订；修订失败则使用确定性的降级模板重建答案，而不是返回错误占位或“见上”。

## 6. 接口与数据流

### 6.1 Agent 配置接口

- `GET /api/qa-agent/settings`：读取公开运行策略。
- `PUT /api/qa-agent/settings`：校验并保存运行策略。
- 返回中包含配置来源、是否启用费用限制和字段说明，不包含模型密钥。

### 6.2 问答过程

1. 本地问答开始时读取一次 Agent 配置，冻结为本轮策略。
2. 规划器按问题生成专业子任务。
3. 调度器同时检查并发数、单任务超时、总超时和费用预留。
4. 子 Agent 返回后记录估算输入、输出 Token 和费用。
5. 主 Agent基于成功结果、降级结果及工具证据完成最终综合。
6. 返回内容包含公开的本轮费用摘要和降级状态，核心结论不展示内部运行统计。

## 7. 错误处理

- 配置文件不存在：使用默认超时，费用无限制。
- 配置文件损坏：配置接口返回明确错误，本地问答使用安全默认超时并禁用费用限制，不读取半成品字段。
- 单价填写不完整：拒绝保存。
- 费用上限无法计算：拒绝启用费用限制，不猜测价格。
- 模型未返回用量：使用统一估算器，标注“估算”。
- 浏览器重复提交：后端以现有采集服务锁拒绝第二个运行，页面保留当前批次。

## 8. 验收标准

1. 任意采集器可以从列表或详情页单独采集，运行报告中只出现该采集器。
2. 单采集器补采默认超时 300 秒、尝试 1 次，失败不会启动其他采集器。
3. Agent 配置页可以保存并重新读取两个超时、并发数、两个单价和费用上限。
4. 未配置费用上限时不限制问答；配置上限时缺少任一单价无法保存。
5. 并发子 Agent 在启动前预留费用预算，预算不足的任务不启动。
6. 单任务超时和总超时均能触发明确降级，其他成功材料继续用于最终回答。
7. 问答过程展示估算 Token 和估算费用，但核心结论不展示内部数据分布。
8. 美伊问题的核心结论直接回答美伊，俄乌问题直接回答俄乌。
9. 超时、超预算和模型异常均不会造成最终回答为空。
10. PiChat、采集器、翻译与现有模型密钥配置不受费用上限影响。
