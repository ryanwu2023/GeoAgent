# GeoAgent 会晤日历采集器整合设计

日期：2026-10-25

## 1. 目标与范围

把 `C:\Users\chongwu26001\WorkBuddy\2026-09-17-15-16-18\meeting-calendar-monitor` 原生整合到 GeoAgent，使统一采集管线能够运行、监控和导入该采集器，并在前端展示美伊、俄乌及相关多边议题中关键人物未来一段时间的会晤计划、地点、确认状态和来源依据。

首版默认展示当前日期起未来 120 天，同时保留已经举行、已推迟、已取消、已否认和过期未证实的记录供核验。会晤日历进入冻结快照，问答、简报、地图和证据详情使用同一快照版本。

本功能不把媒体预告自动写成已确认会晤，不预测会晤一定举行，也不把计划地点解释为人员实时位置。

## 2. 原生采集器整合

将完整采集器复制到项目的 `collectors/meeting-calendar-monitor/`，保留：

- `meeting_monitor.py`、`config.json`、`tools/verify_report.py` 和 `run.bat`；
- `output/LATEST.jsonl`、`LATEST.csv`、`LATEST.md` 及按日归档；
- `state/events.json` 和 `state/transitions.jsonl`；
- 原始载荷、采纳信号、拒收记录、来源健康和统计文件。

在 `collectors/collectors.json` 注册：

- ID：`meeting-calendar-monitor`；
- 中文名称：`关键人物会晤日历`；
- 主题：`usiran`、`ukraine`；
- 入口：`meeting_monitor.py`；
- 自检：`--selftest`；
- 输出类型：新增 `meeting-calendar`。

统一爬虫管理器按照现有规则运行采集器。由于该采集器建议北京时间 08:30 后每日运行一次，首版仍服从全局采集轮次，不在采集器内部另建常驻调度器；后续可在统一调度配置中增加采集器级频率。

## 3. 快照数据模型

新增会晤适配器读取 `output/LATEST.jsonl`，并在导入时产生两类数据。

### 3.1 会晤日历对象

每条对象至少包含：

- 稳定事件 ID、标题和会议类型；
- 开始日期、结束日期、日期精度和原始日期表达；
- 地点和地点精度；
- 人物 ID、人物中文名、职务、国家及参与方；
- 轨道：美伊、俄乌、以伊/胡塞、多边；
- 状态、状态中文名、确认等级、是否存在口径冲突；
- 是否人工基线、基线说明及公开源核验状态；
- 首次发现、最近发现、状态变化；
- 支持声明和来源清单；
- 对应 GeoAgent 证据记录 ID。

状态保持采集器原语义：

`已确认 > 日期已定 > 已安排 > 已预告 > 媒体报道 > 暂无确认日期`

`已否认 / 已推迟 / 已取消 / 过期未证实 / 已举行` 单独管理，不折叠进上述排序。

### 3.2 证据记录

每个会晤生成一条可检索的 GeoAgent 记录，用于问答、简报和证据详情。记录保留：

- 会晤标题、参与人、日期、地点和状态摘要；
- 最强来源的原始链接和来源等级；
- 全部声明及状态变化放入结构化扩展字段；
- `event_at` 使用明确日期；月份、当周、区间和待定日期保留精度，不伪造具体某天；
- 美伊轨道绑定外交斡旋或中东相关维度，俄乌轨道绑定外交斡旋，多边会议按涉及主题分别绑定；
- 非会晤政治日程基线可以保留在专用日历，但不能伪装成领导人会晤。

公开证据与人工基线分开标注。Google News 聚合只作为发现线索；T1/T2 来源才能抬升确认状态。

## 4. 地点与地图边界

建立受控地点字典，为莫斯科、北京、深圳、多哈、日内瓦、纽约、华盛顿、德黑兰、安卡拉等明确会晤地点提供参考坐标。

地图点必须显示为“计划会晤地点”，并包含以下限制：

- 只有明确城市或场馆才生成点位；
- 国家级地点、地区级地点和地点未定不生成精确点；
- 地图点不表示领导人当前所在位置或实际行程；
- 计划会晤与军事行动使用不同图层和图标；
- 已取消、已否认或过期未证实默认不显示在当前计划图层，但可以通过状态筛选查看。

## 5. 后端接口

新增只读接口：

`GET /api/meetings`

参数包括：

- `snapshot_id`：必填，保证冻结快照一致；
- `topic`：`all / usiran / ukraine`；
- `track`、`status`、`person`；
- `start`、`end`；
- `include_inactive`：是否包含取消、否认、推迟和过期记录；
- `offset`、`limit`。

返回日历记录、总数、状态统计、取数时间和口径说明。

`GET /api/meetings/{event_id}` 返回完整声明、来源、状态变化和关联证据。接口必须校验事件属于请求快照，不能跨快照回退到最新数据。

现有地图接口增加可选的 `meeting` 图层数据，但不改变既有军事、外交和新闻点位协议。

## 6. 前端交互

在主工作区新增独立菜单“会晤日历”，位于“风险监测”和“证据台账”之间。

页面由四部分组成：

1. 顶部摘要：未来 7 天、30 天、120 天的会晤数量，以及已确认、已安排、待确认和异常状态数量。
2. 筛选栏：主题、人物、状态、日期范围和“包含取消/推迟/过期”。
3. 时间线与列表：按日期排序，展示日期精度、地点、参与人、状态和最强来源等级。
4. 详情抽屉：展示完整参与人、地点、确认依据、冲突声明、状态变化、来源链接和关联证据按钮。

地图增加“计划会晤”图层开关。点击会晤点打开相同详情，列表点击有坐标的会晤时地图定位到该地点。

界面明确显示：

- “计划会晤地点，不代表实时位置”；
- “媒体报道”和“暂无确认日期”不得使用与“已确认”相同的视觉强度；
- 时间精度为月份、当周或区间时，原样展示，不补写具体日期；
- 同一事件存在来源冲突时显示口径冲突标识。

## 7. 问答与简报

会晤证据记录进入现有 GeoAgent 检索工具，因此本地 MCP Agent 和 PiChat 都可以检索。典型问题包括：

- 未来一周有哪些美伊或俄乌相关重要会晤？
- 特朗普、普京、泽连斯基和伊朗领导人近期有哪些已确认安排？
- 哪些会晤仍停留在媒体报道，缺少官方确认？
- 哪些会晤被推迟、取消或到期后没有证实举行？

研究简报可增加“未来外交日程”段落，最多列出近期关键会晤，并区分事实、计划和待核验线索。会晤日历只能作为外交情景触发条件之一，不能单独决定冲突升级或缓和结论。

## 8. 错误处理与数据质量

- 采集器失败时保留上一冻结快照，不清空历史会晤。
- 来源部分失败时展示覆盖缺口和来源健康，不把失败解释为没有会晤。
- 同一会晤重复报道通过稳定事件 ID 归并。
- 状态变更保留旧状态和依据，不覆盖历史。
- 无日期或无地点的数据可以进入列表，但不得伪造日期或地图点。
- 非会晤基线必须带 `non_meeting` 标记并在前端单独说明。
- 适配失败记录到快照错误列表，其他采集器仍可继续导入。

## 9. 验收标准

1. `meeting-calendar-monitor` 出现在统一采集器列表，可以运行、自检、补采并查看来源健康。
2. 一轮采集后自动进入新快照，不需要手工复制输出。
3. 重复导入不会产生重复会晤；状态变化可以回溯。
4. 美伊和俄乌主题只展示相关会晤，多边会议可以同时关联两个主题。
5. 前端正确区分日期精度、状态等级、来源等级和口径冲突。
6. 已明确地点的未来会晤进入独立地图图层；地点未定不生成点位。
7. 点击会晤能打开来源和关联证据，外部链接可访问。
8. 问答能够检索会晤日历，并明确区分已确认、计划和媒体线索。
9. HTML 简报可包含未来外交日程，引用保持快照一致。
10. 采集器自检、适配器测试、接口测试、前端测试、生产构建和真实采集验收全部通过。

## 10. 不在首版范围

- 自动写入个人日历或发送会议提醒；
- 根据会晤安排自动生成交易指令；
- 对未公开的领导人行程进行推断；
- 用模型替代采集器的确认等级规则；
- 独立于统一管线运行第二套常驻调度服务。
