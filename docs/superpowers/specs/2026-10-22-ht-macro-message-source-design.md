# 华泰宏观消息数据源与 MCP 接入设计

## 目标

在 GeoAgent 内新增一个内部消息数据源。系统使用账号登录取得访问令牌，维持令牌有效期，每天三次抓取消息列表，将有用且不重复的数据保存到本地数据库，并通过现有 GeoAgent MCP 提供只读查询能力。

本功能不把上游账号、密码或访问令牌写入 Git、数据库、原始响应归档、普通日志或 MCP 返回。

## 总体方案

采用“独立采集服务 + 独立 SQLite 数据库 + 现有 GeoAgent MCP 工具”的方式：

1. 新增 `ht-macro-message-monitor` 采集模块，负责登录、令牌刷新、分页抓取、标准化和落库。
2. 采集模块作为长驻后台任务启动，以便每 27 分钟刷新令牌。
3. 消息列表按北京时间 08:00、14:00、20:00 抓取；服务启动后立即补采一次。
4. 消息存入独立 SQLite 数据库，避免与研究快照数据库互相阻塞。
5. 现有 GeoAgent MCP 直接只读访问该数据库，不对外代理上游接口。

## 配置与秘密管理

`.env.example` 只声明空白配置项：

- `HT_MACRO_BASE_URL`
- `HT_MACRO_REGION`
- `HT_MACRO_USERNAME`
- `HT_MACRO_PASSWORD`
- `HT_MACRO_CLIENT_CATEGORY`
- `HT_MACRO_REFRESH_INTERVAL_SEC`，默认 1620 秒
- `HT_MACRO_FETCH_TIMES`，默认 `08:00,14:00,20:00`
- `HT_MACRO_PAGE_SIZE`，默认 20，与用户给定请求一致
- `HT_MACRO_MAX_PAGES`，默认 100
- `HT_MACRO_ENABLED`，默认关闭；本地完成配置后显式开启

真实值只保存在已被 `.gitignore` 排除的 `.env` 或进程环境变量中。访问令牌仅保存在进程内存；服务重启时重新登录。异常文本在写日志前执行秘密脱敏。

## 上游接口流程

### 登录

向 `/application/auth/oauth/two-stage/login` 发送 POST JSON：区域、用户名、密码和客户端类别。程序兼容 `access_token`、`accessToken` 以及嵌套数据对象中的令牌字段，缺少令牌时将本次认证标记为失败。

### 刷新

每 27 分钟向 `/application/auth/oauth/refresh/token` 发送 POST，请求头携带当前 Bearer Token，请求体为：

```json
{"accessToken": "当前访问令牌"}
```

若响应返回新令牌，原子替换内存令牌。若刷新失败或令牌失效，自动重新登录；重新登录仍失败时保留错误状态并按退避策略重试，不删除已有数据。

### 消息抓取

向 `/application/lgrp-server/lgrp/api/msg/list` 发送 POST，请求头携带 Bearer Token。固定业务筛选为：

```json
{
  "pageNum": 1,
  "pageSize": 20,
  "msgTypes": ["WX"],
  "infoFlowSource": "external",
  "isImportant": null,
  "isShowMyCncpt": 0,
  "queryMsgType": 3
}
```

程序递增 `pageNum`，直到返回列表为空、已达到 `total`、整页均为既有数据且已越过安全回看窗口，或达到最大页数。401/403 时重新登录后只重试一次，避免无限认证循环。

## 数据筛选与标准化

本数据源先完整保存接口返回的有效消息，再基于字段标记其业务用途，不在采集阶段因模型判断直接删除消息。标准化记录包含：

- 上游唯一标识、消息 ID、消息类型；
- 标题、内容摘要、AI 标题、AI 短摘要、AI 内容；
- 消息时间、上游更新时间、首次采集时间、最后采集时间；
- 文本类型、文本分类、行业、标签；
- 群聊名称、发送人、接收时间、原始消息类型；
- 是否重要、数据来源、原始记录摘要、内容指纹；
- GeoAgent 主题、维度、相关性状态和人工复核状态。

`extraInfo` 作为不可信 JSON 解析；解析失败时保留原始字符串和错误标记。业务标记只用于检索和后续清洗，不把上游 AI 摘要视为已经核验的事实。

## 去重与更新

去重优先级如下：

1. `unqMsgId`；
2. `externalUnqMsgId`；
3. `msgType + msgId`；
4. 规范化标题、内容摘要、消息时间及群聊组成的 SHA-256 指纹。

数据库对规范化唯一键建立唯一约束。同一消息再次出现时更新可变字段与 `last_seen_at`，保留 `first_seen_at`，不增加记录数。每个抓取批次单独记录请求页数、新增数、更新数、重复数、失败信息和耗时。

## 本地存储

数据库默认位于 `GEO_DATA_DIR/ht-macro/messages.sqlite3`，主要表为：

- `messages`：标准化消息及来源信息；
- `message_tags`：一条消息的多个标签；
- `collection_runs`：采集批次及统计；
- `schema_meta`：数据库版本。

原始响应写入 `GEO_DATA_DIR/ht-macro/raw/YYYY-MM-DD/`，只保存业务响应，不保存请求头、登录响应或访问令牌。写入采用事务、WAL 和忙等待，保证 MCP 查询与采集可以并发。

## MCP 能力

在现有 GeoAgent MCP 中增加三个只读工具：

- `geo_internal_message_search`：按关键词、开始/结束日期、群聊、标签、文本分类和分页查询；默认按消息时间倒序。
- `geo_internal_message_get`：按公开记录 ID 获取单条完整标准化记录。
- `geo_internal_message_stats`：返回记录总数、最近消息时间、最近成功采集时间、分类与标签统计。

工具返回统一包含查询范围、分页状态、读取时间和数据边界说明。MCP 不返回上游账号、发送人内部 ID、群聊内部 ID、接收人 ID、原始 `extraInfo`、访问令牌或数据库路径；可展示群聊名称和发送人显示名。

## 启动与运行状态

`start.bat`/`start.ps1` 启动主服务时一并启动该长驻采集服务，`stop` 脚本负责停止。若未启用或配置不完整，主项目仍正常启动，状态页显示“未配置”而不是持续报错。

服务状态文件只包含最近登录、刷新和采集的时间及脱敏错误。每日三次抓取失败不会影响令牌刷新，单次刷新失败也不会删除已入库内容。

## 测试与验收

- 登录、刷新字段变体、401 后重登、网络超时和错误响应单元测试；
- 多页抓取、总数变化、空页、最大页数和重复页测试；
- 四层去重、重复更新、事务回滚及并发读取测试；
- MCP 搜索、详情、统计、分页、日期过滤及秘密不泄露测试；
- 启停脚本集成测试，验证未配置时主服务仍可运行；
- 使用伪造接口响应完成自动测试，真实接口只做一次脱敏连通与小范围采集验收。

验收成功标准：重复抓取不增加重复记录；服务运行超过 27 分钟后仍可访问上游；三个固定时点可形成采集批次；重启后历史数据仍在；外部 Agent 能通过 MCP 搜索和读取消息；代码仓库和日志中不存在真实凭据及令牌。
