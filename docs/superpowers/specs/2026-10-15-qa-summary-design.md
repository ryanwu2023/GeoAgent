# 智能问答总结优先设计

## 目标

智能问答使用用户原始问题检索当前快照中的结构化指标和新闻证据，并由模型生成一段完整中文回答。回答需要直接说明主要进展、判断及不确定性；检索结果继续作为可展开的研究依据，而不是主要答案。

## 返回结构

问答接口新增 `summary` 字段。模型成功时，`summary` 是面向用户的一段完整回答；`message` 只描述模型运行和引用校验状态。`facts`、`inferences`、`citations` 与 `gaps` 保留，用于审阅和追溯。

模型输出 JSON 新增：

```json
{
  "summary": {
    "text": "直接回答用户问题的完整中文段落",
    "evidence_ids": ["已有证据ID"]
  }
}
```

总结必须包含至少一个有效证据 ID，且只能使用所引证材料或程序计算中存在的数字。总结不得补充外部事实、概率、评分、价格目标或收益预测。

## 页面交互

问答结果顶部展示“总结回答”，使用较强的视觉层级呈现 `summary.text`。事实、模型推论、引用来源、数据缺口和分析步骤放在可展开的“研究依据”区域。模型失败时显示失败原因并保留本地检索结果；模型未配置或当前范围无证据时，不伪造总结。

## 兼容性与错误处理

历史答案可能没有 `summary`，前端需要兼容空字段。后端继续验证引用 ID、中文内容和数字来源；总结校验失败时整次模型回答降级为本地检索，避免展示无法追溯的结论。

## 验收

- 模型根据用户原始问题和检索证据返回一段完整中文总结。
- 总结引用全部存在于当前检索范围，数字可在引用或程序计算中找到。
- 页面先显示总结，再按需展开研究依据。
- 模型失败、无模型配置和无检索证据时保留现有降级能力。
- 真实问题“近期美伊冲突有什么进展”能够返回总结性段落和可打开的引用。
