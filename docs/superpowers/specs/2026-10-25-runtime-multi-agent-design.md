# GeoAgent 运行时多 Agent 设计

日期：2026-10-25

## 目标

在现有本地单 Agent Harness、九个只读工具、冻结快照和引用校验基础上，增加按问题复杂度启用的多 Agent 研究流程。复杂问题由主协调 Agent 将事件、市场与反证任务并行分配给三个子 Agent；简单事实查询继续使用原单 Agent 流程。

## 角色

| 角色 | 职责 | 允许使用的工具 |
|---|---|---|
| 主协调 Agent | 规划、任务分配、合并备忘录、补查、最终回答与引用校验 | 九个正式工具 |
| 事件 Agent | 军事、外交、制裁、地区事件和时间线 | 工作区、公开证据、华泰消息工具 |
| 市场 Agent | 指标变化、资产传导、市场验证和数据缺口 | 指标、分析视图、公开证据和华泰消息工具 |
| 反证 Agent | 来源冲突、单方声明、反向材料、口径和失效条件 | 公开证据、分析视图和华泰消息工具 |

子 Agent只输出带证据 ID 的结构化研究备忘录，不直接生成面向用户的最终答案。华泰消息始终标记为内部补充线索，不能进入公开证据引用映射。

## 启用规则

满足以下任一条件时启用多 Agent：

- 问题同时涉及事件进展和资产影响；
- 要求综合研判、简报、情景、反证或后续观察；
- 规划器识别出三个及以上研究维度。

简单数值、单条来源、单一指标或单一证据读取继续走单 Agent，减少等待和模型费用。环境变量允许关闭多 Agent 或调整每个子 Agent的模型轮次、工具次数、总耗时和并发数。

## 执行流程

1. 主 Agent锁定快照、主题、维度和日期范围。
2. 现有宽检索建立共享证据池。
3. 主协调器发布三个子任务；子 Agent并行执行有限工具循环。
4. 每个子 Agent返回摘要、关键主张、证据 ID、内部消息 ID、反证、缺口和建议补查。
5. 主 Agent将备忘录写入研究上下文，按需补查，再生成最终答案。
6. 原有引用与数字校验器检查最终回答；任一子 Agent失败时使用其余结果继续。

## 预算与隔离

- 所有 Agent共享一个 `LocalGeoTools` 实例和冻结 `HarnessScope`，因此证据、全文和内部消息预算统一去重。
- 每个子 Agent有独立模型轮次和工具调用上限；协调器另有总工具调用和总耗时上限。
- 子 Agent只能调用角色白名单中的九个现有工具，不注册新业务工具。
- 稳定调用 ID包含子 Agent身份、工具和规范化参数摘要，断点恢复不重复执行成功调用。
- 完整工具结果仍写入 `qa_artifacts`，消息流只发送紧凑摘要。

## 可观察性

`tool-trace/v1` 增加 `agent_id`、`agent_role`、`parent_agent_id` 和 `task_id`。子 Agent生命周期使用 `kind=agent`，状态包括 `running`、`completed` 和 `degraded`。其工具调用携带相同 Agent身份。

前端在现有阶段分组内增加子 Agent分组，展示角色、任务、状态、耗时、工具数和错误；工具卡片及完整详情继续复用现有组件。历史记录缺少 Agent字段时保持原展示。

## 失败与恢复

- 单个子 Agent超时、模型格式错误或工具失败，只将该子任务标记为降级。
- 协调器保留其他成功备忘录，并在最终回答中陈述缺口。
- 运行检查点保存子任务状态和备忘录；恢复时不重复执行已经完成的子 Agent及工具调用。
- 三个子 Agent全部失败时回退到原单 Agent主循环和确定性兜底，最终必须返回非空回答。

## 非目标

- 不修改 PiChat。
- 不修改九个本地工具及二十个对外 MCP 工具的协议。
- 不展示隐藏思维链。
- 不让子 Agent访问互联网、文件系统或数据库。
- 不将报道数量转换为概率，也不将内部消息视为已核验事实。
