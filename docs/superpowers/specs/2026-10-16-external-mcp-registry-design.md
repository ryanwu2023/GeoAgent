# GeoAgent 外部 MCP 服务注册表设计

日期：2026-10-16

## 目标

在现有 MCP 工作台中增加外部 MCP 服务管理能力。用户可以查看服务列表，新增、编辑和删除服务；新增或修改配置必须通过真实 MCP 协议连通性测试后才能保存。

本功能不改变 GeoAgent 自身 `/mcp` 只读业务工具及其鉴权方式。外部 MCP 服务是 GeoAgent 主动连接的上游服务。

## 用户流程

MCP 工作台顶部增加两个视图：

1. `本地工具`：保留当前工具目录、参数、试调用和调用实况。
2. `外部 MCP 服务`：展示已配置服务列表及配置详情。

外部服务列表每项显示：

- 服务名称；
- 类型；
- URL；
- 配置状态；
- 最近测试时间；
- 最近一次成功测试发现的工具数量；
- 编辑和删除操作。

新增流程：

1. 点击“新增 MCP 服务”；
2. 填写名称、类型、URL 和 Key；
3. 点击“测试并保存”；
4. 后端使用草稿配置执行 MCP `initialize` 和 `tools/list`；
5. 测试成功后原子写入注册表，并返回脱敏后的服务信息和工具摘要；
6. 测试失败时显示具体阶段和安全化错误，不保存草稿。

编辑流程与新增一致。Key 留空表示沿用已保存的 Key；填写新 Key 表示用新 Key测试，成功后替换。名称、类型或 URL 发生变化但测试失败时，旧配置保持不变。

删除操作从注册表中移除指定服务，不删除已经导入的新闻、证据、快照或研究结果。删除前页面要求用户确认服务名称。

## 配置字段

| 字段 | 规则 |
|---|---|
| 名称 | 必填，1–80 个字符；同名服务不允许重复 |
| 类型 | 首版支持 `http`，含 Streamable HTTP 及 HTTP 响应中的 SSE 数据帧 |
| URL | 必填，只允许 `http` 或 `https`；禁止 URL 内嵌用户名、密码、查询凭据和片段 |
| Key | 新增时必填；编辑时可留空沿用；纯 Key 自动转换为 `Bearer <key>`，完整 `Bearer` 值直接使用 |

首版保留类型字段和扩展边界，但不伪装支持尚未实现的独立 SSE 或 stdio 传输。

## 后端架构

新增独立的外部 MCP 注册表模块，负责：

- 配置验证；
- 稳定服务 ID 生成；
- 密钥归一化；
- 脱敏公开投影；
- 原子读写；
- 旧配置迁移；
- 测试成功后的保存事务。

配置保存在 `data/mcp-servers.json`。`data/` 已被 Git 忽略。文件结构为：

```json
{
  "version": 1,
  "servers": [
    {
      "id": "haifutong",
      "name": "haifutong",
      "type": "http",
      "url": "https://example.com/mcp",
      "authorization": "Bearer secret",
      "created_at": "2026-10-16T00:00:00Z",
      "updated_at": "2026-10-16T00:00:00Z",
      "last_test": {
        "ok": true,
        "tested_at": "2026-10-16T00:00:00Z",
        "duration_ms": 320,
        "tool_count": 8,
        "tool_names": ["knowledge_search"]
      }
    }
  ]
}
```

`authorization` 只在后端内部读取。公开接口不返回该字段，也不返回掩码后的部分 Key，避免泄漏长度或前后缀。

旧 `data/mcp-config.json` 在首次读取新注册表且注册表不存在时迁移为一个 `http` 服务。迁移成功后旧文件保留作为恢复材料，但后续写入只更新新注册表。

## API

### `GET /api/integrations/external-mcp`

返回脱敏服务列表。响应包含 ID、名称、类型、URL、是否已配置 Key、最近测试摘要，不包含 Authorization。

### `POST /api/integrations/external-mcp/test-and-save`

请求包含可选服务 ID、名称、类型、URL 和可选 Key。

- 新增时没有服务 ID，Key 必填；
- 编辑时服务 ID 必填，Key 为空则读取旧 Key；
- 使用草稿配置执行真实协议测试；
- `initialize` 和 `tools/list` 均成功才原子保存；
- 返回脱敏配置、服务器信息、工具名称及测试耗时；
- 失败返回明确错误，磁盘配置不变。

测试连接不调用任何业务工具，不把测试成功解释为业务数据可用。

### `DELETE /api/integrations/external-mcp/{server_id}`

删除服务配置并返回剩余脱敏列表。不存在的 ID 返回 404。

## MCP 协议测试

测试使用配置草稿连接目标 URL：

1. 发送 `initialize`，协议版本沿用项目当前版本；
2. 发送 `notifications/initialized`；
3. 发送 `tools/list`；
4. 验证返回工具为数组；
5. 记录耗时、服务端信息、工具数量和有限工具名摘要。

连接超时为 60 秒，不跟随重定向，单次响应上限为 20 MB。错误信息不包含请求头、Key、完整响应正文或本机路径。

## 前端状态与错误处理

外部服务页包含列表区和详情表单区。新增和编辑共用表单。

- 未测试的草稿不提供独立“保存”按钮；唯一提交动作是“测试并保存”。
- 测试期间禁用表单和重复提交，显示当前阶段。
- 成功后刷新列表并选中已保存服务，清空 Key 输入框。
- 失败后保留草稿以便修改，列表中的旧配置保持不变。
- 删除成功后清空当前表单；删除失败显示错误并保留列表。
- Key 输入框使用密码类型，浏览器中不持久化，不从后端回填。

## 与现有 MCP 新闻源的关系

现有 MCP 新闻获取继续可用。完成迁移后，它从注册表读取指定服务；若只有一个服务则默认使用该服务。存在多个服务时，新闻源操作必须明确选择服务 ID，避免隐式调用错误的上游。

本次工作台功能只负责服务注册、测试和管理，不自动调用外部工具、不自动导入数据，也不改变工作快照。

## 验证与验收

后端测试覆盖：

- 多服务新增、列表、编辑和删除；
- 新增缺少 Key；
- 编辑留空 Key 沿用旧值；
- 同名冲突；
- URL 与类型验证；
- `initialize` 失败不保存；
- `tools/list` 失败不保存；
- 测试成功才原子保存；
- 公开响应和错误日志不含 Key；
- 旧单服务配置迁移；
- 删除不影响快照和已导入数据。

前端验证覆盖：

- 服务列表、新增、编辑、删除流程；
- 表单必填和测试中状态；
- 成功后列表刷新与 Key 清空；
- 失败时旧配置不变且草稿保留；
- 生产构建通过。

验收标准：用户能够在 MCP 工作台连续配置两个不同服务；每个服务只有在真实连通性测试成功后才出现在已保存列表；刷新页面后配置仍存在；任何页面和公开接口均看不到 Key。
