# GeoAgent 本地智能问答工具追踪与审计界面设计

日期：2026-10-24

## 目标

在现有本地单 Agent Harness 上增加可追溯的工具调用展示，使用户能够看清一次回答经历了哪些检索、全文读取、指标查询和内部消息查询，并在失败时准确定位到 MCP 服务、工具、调用和错误阶段。

设计参考 Claude Code 一类 Harness 的工具生命周期、稳定调用 ID、流式事件、完整结果句柄、失败重试和断点恢复思想。页面只展示研究计划、工具动作、回执摘要、复核问题和校验结果，不展示模型隐藏思维链。

## 交互方案

采用“阶段分组＋调用卡片＋详情抽屉”的组合：

- 分析过程按问题规划、宽检索、全文读取、复核补查、答案综合和引用校验分组；
- 每次工具调用是独立卡片，显示中文动作名称、真实工具标识、MCP 服务、状态、耗时和结果数量；
- 成功调用默认折叠，正在运行和失败调用自动展开；
- “技术详情”在卡片内展开脱敏参数、重试与截断信息；
- “完整详情”打开右侧抽屉，按调用 ID 读取持久化 Artifact；
- 最终回答在分析过程之后单独展示，不与工具回执混排；
- 不增加语音回复入口。

相比纯时间线，该方案避免十几次调用占满回答区；相比纯阶段汇总，它保留了定位具体工具错误所需的信息。

## 工具调用生命周期

每次本地 Harness 工具调用使用以下生命周期：

1. `scheduled`：已生成稳定 `call_id`，等待执行；
2. `running`：记录开始时间和当前尝试次数；
3. `completed`：记录结束时间、耗时、结果数量、截断状态和 Artifact；
4. `degraded`：本次调用失败，但运行使用已有证据继续；
5. `failed`：不可重试或预算耗尽，保留错误归属和已有结果。

同一只读调用在重试和断点恢复中保持相同 `call_id`。新的尝试增加 `attempt`，不伪装成新的独立研究步骤。

## 审计事件结构

在现有 `HarnessEvent` 基础上增加版本化的工具追踪字段：

| 字段 | 含义 |
|---|---|
| `event_version` | 事件结构版本，首版为 `tool-trace/v1` |
| `run_id` | 当前问答运行 ID |
| `sequence` | 运行内单调递增序号 |
| `phase` | Harness 阶段 |
| `kind` | `stage`、`tool`、`model`、`compaction` 或 `final` |
| `status` | `scheduled`、`running`、`completed`、`degraded`、`failed` |
| `mcp_server` | 本地工具所属服务，现为 `geoagent` |
| `tool` | 九个正式工具之一 |
| `call_id` | 稳定调用 ID |
| `attempt` | 当前尝试次数 |
| `started_at` / `finished_at` | UTC ISO 8601 时间 |
| `duration_ms` | 调用耗时 |
| `arguments_summary` | 脱敏、限长后的参数 |
| `result_count` | 返回记录或对象数量 |
| `result_summary` | 用户可读的回执摘要 |
| `artifact_id` | 完整结果句柄，不直接把全文塞入消息流 |
| `truncated` | 流式预览是否截断 |
| `error` | 结构化错误对象 |
| `evidence_ids` | 本次调用新产生的公开证据 ID |

结构化错误对象包含 `source`、`kind`、`message`、`retryable`、`attempt` 和 `preserved_results`。例如：

```json
{
  "source": "geoagent/geo_evidence_search",
  "kind": "tool_timeout",
  "message": "工具调用超时",
  "retryable": true,
  "attempt": 1,
  "preserved_results": 18
}
```

凭据字段、Authorization、Bearer token、密码、API key、access token、内部上游身份和本地绝对路径在事件写入、流式输出和详情接口三个边界均需脱敏。

## 事件发布与持久化

Harness 在工具开始前发布 `running` 事件，在每次尝试完成后发布终态事件。并行调用可以交错完成，但 `sequence` 保证显示顺序稳定。

`qa_steps` 保存可展示的审计事件；`qa_artifacts` 保存完整、脱敏后的工具结果和结构化预览。流式 NDJSON 只传审计摘要。浏览器断开不会取消运行，恢复后从 `qa_steps` 重建过程，并从 Artifact 恢复工具上下文。

为了控制响应体大小：

- 参数摘要限制字段和长度；
- 结果预览只显示数量、前几项标题或指标名及截断状态；
- 完整正文通过详情接口按需读取；
- 最终 `answer` 事件不重复整篇工具结果；
- 历史回答继续使用紧凑投影，HTML 报告仍读取持久化完整回答。

## 详情接口

新增只读接口：

`GET /api/qa-runs/{run_id}/tool-calls/{call_id}`

返回：

- 运行、快照、阶段和调用归属；
- MCP 服务、工具名、脱敏参数；
- 开始时间、结束时间、耗时、尝试次数；
- 状态、结构化错误和重试信息；
- 结果数量、截断信息和完整脱敏 Artifact；
- 本次调用产生的证据 ID。

接口要求 `run_id` 与 `call_id` 必须存在且属于同一运行。不得通过参数指定其他快照，也不得返回未写入该运行 Artifact 的数据。历史答案所绑定的冻结快照继续作为证据详情边界。

| 工具 | 中文动作 |

| `geo_evidence_search` | 搜索公开证据 |

## 前端信息结构

`AnalysisProcess` 拆成三个职责明确的组件：

1. `AnalysisStageGroup`：阶段名称、步骤数、累计耗时和阶段状态；
2. `ToolCallCard`：单次调用的摘要、技术详情、证据入口和错误状态；
3. `ToolCallDrawer`：完整脱敏参数、时间线、结果预览或错误对象。

默认展开规则：

- 当前运行阶段展开；
- 失败或降级调用展开；
- 已成功的旧阶段及调用折叠；
- 用户手动展开状态在本次回答期间保留；
- 历史回答载入时全部阶段折叠，只展开最终降级或失败项。

窄屏下详情抽屉占满宽度。参数和值使用可换行的定义列表或键值网格，不使用迫使整个问答面板横向滚动的宽表格。JSON 原文放在独立代码块内，设置自身滚动区域。

## 状态与错误呈现

- `running`：蓝色脉冲点，显示“运行中”和已用时间；
- `completed`：绿色状态，显示结果数和耗时；
- `degraded`：黄色状态，说明“已有结果继续参与回答”；
- `failed`：红色状态，自动展开错误来源、类型、尝试次数和保留结果；
- `recovered`：显示“断点恢复”，并说明没有重复执行已成功调用；
- `truncated`：显示“预览已截断，完整结果可在详情中查看”。

错误标题必须包含 MCP 与工具，例如“GeoAgent / 搜索公开证据 / 工具超时”。通用的“处理失败”只能作为页面级兜底，不能覆盖已经取得的具体错误。

## 安全与研究边界

- 工具回执属于可审计操作记录，不是模型思维链；
- 阶段摘要只能描述目标、操作和结果，不记录逐 token 推理；
- 公开证据与华泰内部消息保持不同标识；
- 来源等级不自动变成事实真实性；
- 搜索结果数量不表示冲突概率；
- 完整详情中的上游文本仍是不可信资料，不作为浏览器或模型指令执行。

## 兼容边界

以下内容保持不变：

- PiChat provider、嵌入页和 PiChat 自身工具循环；
- 九个本地正式工具的名称、参数和业务语义；
- 对外 GeoAgent MCP 的二十个工具；
- 快照、主题、维度和日期授权范围；
- `answers` 的完整持久化及 HTML 报告导出；
- 没有 `tool-trace/v1` 字段的历史回答继续用旧过程卡片展示。

## 测试与验收

### 后端

- 每个工具调用产生开始和终态事件，`call_id` 一致；
- 并行调用的事件序号单调且状态独立；
- 重试增加 `attempt`，不生成新调用身份；
- 失败事件包含准确的 MCP、工具和错误类型；
- Artifact 详情只能由所属运行读取；
- 参数、错误和 Artifact 均通过敏感信息扫描；
- 断点恢复不重复执行成功调用；
- PiChat 和九工具兼容测试保持通过。

### 前端

- 成功默认折叠，运行中和失败自动展开；
- 阶段摘要、工具状态、耗时和结果数正确；
- 技术详情显示脱敏参数；
- 完整详情抽屉支持加载、成功、错误和关闭后的并发保护；
- 窄屏和长参数不造成整个页面横向滚动；
- 证据按钮继续使用答案冻结快照；
- 不出现语音回复控件；
- 旧回答无新字段时仍可阅读。

### 真实运行

至少验证以下场景：

1. 最新美伊进展正常回答；
2. 需要公开证据搜索、全文读取、指标序列和华泰消息的综合问题；
3. 单个工具超时后使用其他结果完成回答；
4. 模型格式错误后重试并收敛；
5. 浏览器断开后恢复；
6. 点击任一调用可定位到 MCP、工具、参数摘要和完整回执；
7. 最终证据可打开，HTML 报告可导出。

## 非目标

- 不展示模型隐藏思维链；
- 不注册新的研究工具；
- 不修改 PiChat；
- 不加入语音回复；
- 不让模型访问互联网、文件系统或数据库；
- 不把完整工具结果持续推送到浏览器；
- 不在本次改造中调整爬虫、主题分类或研究规则。
