# GeoAgent 本地智能问答 Harness 可靠性设计

日期：2026-10-24

## 目标

在不修改 PiChat 接入、不修改现有九个只读工具注册及对外 MCP 行为的前提下，加强本地模型智能问答的 Harness 工程。重点解决单次运行内状态混杂、长工具结果粗粒度截断、模型或工具失败后丢失进度、独立只读任务不能并行、过程展示缺少真实运行状态，以及评测难以定位失败阶段的问题。

首轮仅建设可靠的单 Agent Harness，不增加子 Agent，不引入通用 Agent 框架，也不把地缘研究系统改造成开放式执行环境。

## 明确边界

以下能力保持原样：

- PiChat provider、PiChat 请求协议和 PiChat 自身的工具循环；
- GeoAgent MCP 服务及其二十个对外工具；
- 本地问答当前使用的九个工具名称、参数、Schema、业务语义和只读权限；
- 快照、主题、维度、日期范围和证据访问约束；
- 公开证据与华泰内部消息分开呈现、分别核验的规则。

本次只调整本地 OpenAI-compatible 模型路径。PiChat 仍可继续调用现有 GeoAgent MCP 工具，不经过新的本地 Harness。

## 总体架构

保留 `qa_agent.run_agent()` 作为兼容入口，在其下拆分五个运行组件：

1. **Harness Runner**：维护阶段状态机，决定下一步是执行工具、请求模型、压缩上下文、恢复检查点还是生成降级答案。
2. **Execution Scheduler**：调用现有九个工具；只读且互不依赖的调用可以有界并行，存在前后依赖的调用保持串行。
3. **Context Manager**：维护模型可见上下文、研究记忆、证据引用、华泰消息、预算和完整结果句柄。
4. **Checkpoint Store**：持久化每个成功阶段的最小可恢复状态。
5. **Finalizer and Validator**：复用当前引用与数字校验，并保证任何失败路径都返回可读答案。

现有问题规划器、混合检索、工具实现和最终校验继续复用。模块拆分的目的不是改变研究口径，而是让运行状态、上下文和失败恢复有明确边界。

## 运行状态机

本地问答使用以下状态：

1. `planning`：锁定问题、快照、筛选范围、研究重点和预算。
2. `discovering`：获取工作区摘要，执行宽检索，并按需读取指标目录和华泰消息统计。
3. `reading`：读取模型或排序器选出的关键公开证据正文、指标序列和华泰消息正文。
4. `reviewing`：检查时效、来源矛盾、反证、缺口和需要补查的内容。
5. `synthesizing`：生成完整中文回答和独立引用映射。
6. `validating`：逐句校验引用、数字、时间范围和内部消息边界。
7. `completed` 或 `degraded`：保存最终回答；降级状态必须说明未完成的阶段和原因。

状态只能按允许的边迁移。工具失败不会把状态退回起点；模型超时从最近检查点继续。

## 上下文治理

### 结果分层

每个工具调用产生三层结果：

- **完整结果**：保留于当前运行的结果存储中，供后续按句柄读取或恢复，不重复塞入模型。
- **结构化预览**：包含调用范围、记录数量、前几条结果、来源、时间、截断状态和可继续读取的 ID。
- **研究记忆**：在上下文接近预算时生成，保留已确认事实、冲突说法、指标日期、反证、数据缺口和对应证据 ID。

完整公开证据仍以快照为事实来源；检查点只保存记录引用和运行状态，不复制整份快照。华泰消息保存公开消息 ID及本轮读取状态，不改变内部消息数据库。

### 预算

预算至少分成：

- 工具说明与系统约束；
- 研究计划；
- 当前阶段工具回执；
- 关键正文；
- 研究记忆；
- 最终回答预留。

Harness 在每轮模型请求前估算大小。超过软阈值时先移除可重新获取的旧预览，再生成研究记忆；超过硬阈值时停止扩展检索并进入综合。不得通过直接切断 JSON 字符串形成不可解析上下文。

### 信息优先级

上下文保留顺序为：

1. 用户原始问题和明确筛选；
2. 核心安全与研究边界；
3. 已选择的关键证据和引用映射；
4. 最新研究记忆与未解决问题；
5. 当前阶段工具结果；
6. 可重新获取的旧摘要。

## 检查点与恢复

在每个成功阶段以及每批工具调用完成后保存检查点，字段包括：

- `run_id`、问答 ID和快照 ID；
- 当前状态和状态版本；
- 原始问题、主题、维度、日期范围；
- 研究计划和剩余预算；
- 已执行工具调用及参数摘要；
- 成功、失败、重试和截断状态；
- 已检索与已读取的公开证据 ID；
- 已检索与已读取的华泰公开消息 ID；
- 当前研究记忆；
- 最后有效模型草稿；
- 模型名称、耗时和错误类型。

检查点写入现有本地 SQLite，新建独立的 `qa_runs`、`qa_steps` 和 `qa_artifacts` 表，不改变 `answers` 表语义。运行完成后答案仍写入 `answers`。

恢复规则：

- 工具参数或范围错误作为结构化回执返回，允许模型修正，单次调用最多重试两次；
- 工具超时只标记该工具失败，保留同批其他成功结果；
- 模型超时从最近检查点重试一次；
- 重试仍失败时使用最后有效草稿、研究记忆和已读证据进入确定性综合；
- 服务重启后，前端可以读取未完成运行；用户再次提交同一运行时从检查点恢复；
- 快照或筛选范围发生变化时不得复用旧运行检查点。

## 有界并行调度

首轮仍是一个主 Agent。并发发生在 Harness 的只读工具执行层：

- 工作区摘要、指标目录和华泰消息统计可并行；
- 多个互不依赖的证据检索可并行；
- 已获得 ID 后，多条公开证据正文可按小批次并行读取；
- 已获得消息 ID 后，多条华泰消息正文可按小批次并行读取。

以下调用必须串行：

- 搜索之后按 ID 读取；
- 指标目录之后读取指定序列；
- 补查词依赖上一轮复核结论；
- 最终综合依赖所有选定结果。

调度器限制总并发、单工具并发、单调用超时和总体运行时间。并行批次的结果按调用 ID稳定排序，保证相同输入可复现。

## 错误处理与确定性降级

Harness 将错误分为参数错误、范围错误、工具超时、工具不可用、模型超时、模型格式错误、上下文超限、引用校验失败和运行取消。

每类错误都包含：

- 用户可理解的中文说明；
- 是否可重试；
- 已完成到哪个阶段；
- 哪些结果仍有效；
- 采用了何种降级路径。

最终回答遵循以下顺序：

1. 使用已通过校验的模型最终稿；
2. 使用最后有效草稿并删除无效句；
3. 使用研究记忆与已读证据生成确定性结构化回答；
4. 至少返回检索结论、来源范围和明确数据缺口。

任何单一工具、模型调用或引用异常都不能导致空白回答。

## 前端过程展示

现有“分析过程”扩展为真实 Harness 运行视图，展示：

- 当前阶段和总体状态；
- 工具调用名称、参数摘要、耗时和结果数量；
- 并行批次中各调用的独立状态；
- 重试、超时、降级和恢复标记；
- 候选证据、已读正文、指标和华泰消息数量；
- 上下文压缩发生时间、压缩前后规模和保留内容类型；
- 最终公开引用与华泰内部消息补充。

页面不展示模型隐藏思维过程，只展示计划、操作、工具回执摘要、复核问题和最终结论。历史回答继续可读；没有新 Harness 字段的旧记录使用现有展示方式。

## 运行可观测性

每次问答记录：

- 各阶段耗时；
- 模型请求次数、超时和重试；
- 工具成功率、错误类型和延迟；
- 上下文大小、压缩次数和最终预留；
- 证据候选数、全文读取数、最终引用数；
- 降级原因和最终完成状态。

日志和前端均不得记录模型密钥、华泰登录凭据或内部上游标识。

## 测试与验收

### 单元测试

- 状态迁移合法性；
- 上下文预算、压缩和研究记忆；
- 检查点保存、恢复和范围隔离；
- 工具批次并发上限与稳定排序；
- 参数错误、工具超时和模型超时的重试规则；
- 确定性降级始终返回答案；
- 公开证据与华泰消息不会混用引用。

### 集成测试

- 正常本地问答完整通过七个阶段；
- 任一工具失败时其他结果仍参与回答；
- 模型首次超时后从检查点恢复；
- 服务重启后恢复未完成运行；
- 大工具结果触发压缩而不产生损坏 JSON；
- PiChat 路径的请求次数、协议和返回结构保持不变；
- MCP 九个既有工具名称、Schema 和结果保持兼容。

### 固定问题评测

继续使用固定问题集，比较本地 Harness 与 PiChat 的：

- 最新事实覆盖和时间范围准确性；
- 引用可打开率与引用支持度；
- 无来源数字率；
- 反证、不确定性和数据缺口覆盖；
- 指标日期、口径和资产传导解释；
- 工具成功率、总延迟、上下文规模和降级率。

首轮通过标准：

- 所有失败注入场景均返回非空中文答案；
- 同一快照和筛选范围内的恢复不重复执行已成功工具；
- PiChat 和 MCP 兼容测试无变化；
- 本地正常问答、超时问答和恢复问答都能在前端查看完整审计过程；
- 不新增写操作工具，不扩大模型数据访问范围。

## 非目标

- 不修改或重新注册现有九个工具；
- 不修改 PiChat；
- 不加入子 Agent；
- 不让本地模型访问互联网、文件系统或数据库；
- 不改变爬虫、快照和研究规则；
- 不生成交易指令、收益预测或无依据概率。

## 分阶段交付

1. 建立状态对象、运行存储和检查点读写。
2. 引入 Context Manager，替换粗粒度字符截断。
3. 引入有界只读调度器和结构化错误回执。
4. 将现有 `run_agent` 迁移到状态机，并实现恢复与确定性降级。
5. 扩展流式接口和前端过程展示。
6. 增加失败注入、兼容性测试和固定问题评测。
