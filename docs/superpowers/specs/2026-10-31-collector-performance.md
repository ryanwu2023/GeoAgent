# 采集性能与无损发布

用户授权：先修缓存和重试，再优化并发；不减少采集数据；测试通过后发布 Sealos，不能中断已有批次。沿用现有采集器注册、主题、来源、候选上限、超时和导入门禁。

方案：军费采集器遵守运行器输出/状态路径，从上次发布产物恢复历史月份缓存和累计记录；成功 HTTP 响应在同一批次重试间复用，失败不缓存，下一批仍重新验证新数据。新增地缘采集器采用独立持久 HTTP 条件缓存、同批重试检查点及逐源进度，来源并发 3，单主机串行限速，输出顺序稳定。全局采集器并发保持默认 4，不在未测情况下盲目放大全局负载。

替代方案：仅扩大总并发不能解决重复请求；缩短超时/减少来源会损失数据，拒绝。缓存只跳过同批已成功 HTTP 请求，不把失败转换为成功；跨批通过条件请求刷新，历史近期月份仍刷新。

输出隔离：新产物在 staging 中，全部重试失败不覆盖 live；跨批旧数据和本批输入输出明确区分。缓存损坏按未命中处理，临时文件原子替换，不持久化认证头。

验证：缓存冷热请求数、进程重启复用、请求体隔离、错误不缓存、历史月份 39→9 请求、并发输出等价与主机限速、真实重试、失败不覆盖 live。全量 PostgreSQL 后端测试、前端测试/构建。CI 在部署前检查采集锁与运行台账，并在最终 rollout 前持续持有相同采集互斥锁；当前批次结束后才能发布。真实网络耗时另测，不能将模拟测试耗时称为线上全量耗时；缺 key/上游故障如实标 partial。

架构：采集调度 → 4 个采集器进程 → 单采集器持久 state/cache + 隔离 staging → 原子发布产物 → 现有 PostgreSQL 快照导入。网络：原有代理/公开源路径不变，新采集器同域限速保留；无新增对外 API、数据库表或权限。
