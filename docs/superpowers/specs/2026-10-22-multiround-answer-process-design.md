# 智能问答多轮分析过程设计（2026-10-22）

## 目标

用户提交问题后，GeoAgent 在非 PiChat 模式下执行三轮递进分析，并在最终答案前展示可核验的过程摘要。过程说明结论如何由当前快照、检索证据和复核动作形成，但不展示模型隐藏推理。

## 交互结构

1. 第一轮：理解原始问题、锁定快照和时间范围、完成首轮内部检索并形成阶段回答。
2. 第二轮：复核首轮回答的遗漏、时效性、来源局限和过度推断，扩展内部检索并重写阶段回答。
3. 第三轮：继续复核第二轮结论，以新的检索词补充证据并形成收敛回答。
4. 最终复核：汇总三轮结果，检查引用范围和新增数字，随后在过程卡片下展示最终中文结论。

每轮显示阶段状态、阶段回答、复核问题、内部补查词、新增证据数量和可点击依据。工具或模型失败只显示一次中文降级说明，并沿用上一轮有效结果；不会把原始工具参数、长日志或隐藏思维链直接展示给用户。

## 数据与接口

`POST /api/ask/stream` 继续使用 NDJSON。`progress` 事件可在同一轮多次更新；前端按轮次替换状态。`AnalysisRound.stage` 区分三轮分析与最终综合，避免将最终综合计为第四轮。

## 验收

- 提交后输入框立即清空。
- 运行中能看到当前轮次、复核与补查状态。
- 完成后显示 3/3 轮及最终复核完成。
- 最终回答独立于过程草稿。
- 过程中的证据 ID 均可打开，最终回答仍通过引用和数字校验。
- PiChat 模式保持单次 Agent 调用。
