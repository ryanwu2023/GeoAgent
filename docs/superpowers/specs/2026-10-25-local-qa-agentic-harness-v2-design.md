# GeoAgent 本地问答 Agentic Harness V2 设计

日期：2026-10-25  
状态：已获用户方案确认，待执行计划评审  
适用范围：本地模型问答链路；PiChat 接入路径和现有 9 个 GeoAgent MCP 工具协议保持不变

## 1. 背景与目标

当前本地问答已经具备问题规划、工具调用、上下文管理、检查点恢复、多 Agent 分工、引用校验和最终降级回答等基础能力，但研究行为仍偏向“固定预取、一次性子任务、模型自由收敛”。这导致即使候选证据和工具调用数量较多，最终回答仍可能出现：最新事实遗漏、主题污染、关键分面无全文支撑、反证不足、指标选择不匹配、引用粒度过粗及回答模板化等问题。

本次改造目标是将本地问答升级为有边界、可恢复、可审计的研究闭环：

1. 根据用户问题动态规划研究分面和时间范围；
2. 由事件、市场和反证子 Agent 执行有限的“搜索—选择—精读—补查—备忘录”循环；
3. 使用共享研究台账记录主张、证据、反证、时间、来源和核验状态；
4. 使用覆盖门禁阻止模型在关键研究任务未完成时过早生成最终答案；
5. 将新闻事实、程序计算、内部消息和模型推论清晰分开；
6. 保证任一内部异常下仍能返回自包含、可读的中文答案；
7. 使用固定问题集和质量评分，与 PiChat 输出进行可重复对比。

## 2. 不在本次范围内

- 不修改 PiChat 的嵌入、认证和后台调用路径；
- 不新增或删除公开的 9 个本地问答工具；
- 不把报道数量转换为情景概率；
- 不展示模型隐藏思维链；
- 不让模型自由计算数据库中不存在的数值；
- 不重写为通用 Claude Code 运行时；仅借鉴其明确工具协议、稳定调用身份、上下文压缩、检查点、子任务隔离和可观测性模式。

## 3. 总体架构

```text
用户问题
  ↓
问题规划器：主题、时间、分面、约束、查询计划
  ↓
协调器创建固定研究范围与共享 ResearchLedger
  ↓
┌──────────────┬──────────────┬────────────────┐
│ 事件研究 Agent │ 市场传导 Agent │ 反证核验 Agent   │
│ 搜索→精读→补查 │ 指标→路径→解释 │ 主张→反查→冲突 │
└──────────────┴──────────────┴────────────────┘
  ↓
ResearchLedger 合并、事件聚类、来源关系与覆盖状态
  ↓
ReadinessGate
  ├─ 未通过且有预算：生成缺口任务并继续工具循环
  └─ 已通过或预算耗尽：进入综合
  ↓
回答草稿 → 主张/引用/数字独立校验 → 修复或降级
  ↓
最终中文回答、引用、内部消息补充、审计轨迹、HTML 报告
```

协调器是唯一最终回答写入者。子 Agent 只产生结构化研究备忘录和台账更新，不直接向用户作答。

## 4. 研究范围与问题规划

### 4.1 固定范围

每次运行在开始时冻结：

- `snapshot_id`
- `topic`
- `dimension`
- `start`
- `end`
- 用户原始问题
- 规划版本

所有主 Agent、子 Agent、工具调用、引用和导出报告必须使用同一范围。恢复运行时若范围发生变化，应拒绝复用旧检查点。

### 4.2 结构化查询对象

检索计划不再只使用扁平长字符串，而使用以下结构：

```json
{
  "facet": "military",
  "query": "俄乌前线最新变化",
  "must_entities": ["乌克兰", "俄罗斯"],
  "should_terms": ["战线", "无人机", "导弹", "防空"],
  "exclude_entities": ["伊朗"],
  "start": "2026-10-19",
  "end": "2026-10-25",
  "preferred_tiers": ["T1", "T2"],
  "expected_role": "support",
  "lane": "core"
}
```

现有 MCP 工具参数保持不变。协调器在调用工具前将结构化对象编译为现有参数，并在本地检索与重排阶段执行实体门控、时间门控、来源偏好和排除条件。

### 4.3 时间策略

“最新”类问题采用逐级扩展：

1. 最近 48 小时：优先发现最新高可信事件；
2. 最近 7 天：补足事件主线、外交、军事和反证；
3. 最近 30 天或用户指定范围：提供背景和变化基准。

同时保存 `published_at` 与 `event_at`。若只有发布时间，输出必须说明其不一定等于事件发生时间。若最近 72 小时没有高可信新增，明确显示陈旧性提示，不得把库内最晚记录称为“今日进展”。

## 5. ResearchLedger 共享研究台账

### 5.1 数据结构

每条台账记录至少包含：

```json
{
  "ledger_id": "stable-id",
  "facet": "diplomacy",
  "claim": "美伊间接接触仍在进行",
  "claim_type": "media_report",
  "status": "reported",
  "event_at": null,
  "published_at": "2026-10-25T02:00:00Z",
  "supporting_ids": ["record-id"],
  "conflicting_ids": ["record-id-2"],
  "full_text_ids": ["record-id"],
  "source_tiers": ["T2", "T3"],
  "independent_sources": 1,
  "syndicated_sources": 2,
  "verification": "pending",
  "confidence": "limited",
  "agent_role": "event",
  "open_questions": ["是否有当事方官方确认"]
}
```

### 5.2 主张类型

- `verified_fact`：有可核查官方动作或多源独立互证；
- `official_statement`：只能证明主体作出声明；
- `single_party_claim`：当事方单方行动或结果说法；
- `media_report`：媒体转述或知情人士报道；
- `program_calculation`：程序基于结构化数据计算；
- `internal_message`：华泰内部消息，必须单列并待外部核验；
- `model_inference`：模型基于证据作出的分析推论；
- `gap`：当前范围内缺乏足够依据。

### 5.3 合并原则

- 同源转载归入同一事件簇，不增加独立来源数；
- 不同来源使用相同标题时不直接删除，而是记录来源关系；
- 官方原文、独立采写和转载分开标记；
- 冲突说法同时保留，不以后写内容覆盖；
- 关键结论必须至少绑定一条已读取全文的公开证据；
- 内部消息不得进入公开引用映射。

## 6. 子 Agent 有限工具循环

### 6.1 通用状态机

每个子 Agent 运行 2 至 4 个模型决策轮次：

```text
PLAN
  → SEARCH
  → SELECT
  → READ
  → ASSESS
      ├─ 有关键缺口且有预算 → FOLLOW_UP_SEARCH / READ
      └─ 覆盖完成或预算耗尽 → MEMO
```

模型每轮只能输出以下动作之一：

- `tool`：从角色白名单选择一个工具和参数；
- `ledger_update`：提交结构化主张与证据映射；
- `memo`：完成子任务；

不允许子 Agent 输出最终用户答案。

### 6.2 事件研究 Agent

负责：

- 最新事件与时间线；
- 外交、军事、政策及地区外溢；
- 事实、声明、转述和推论分类；
- 读取关键事件正文；
- 对高风险主张寻找第二来源。

复杂问题的最低覆盖：最新事件、外交或军事主线、至少一条冲突/待核验信息。

### 6.3 市场传导 Agent

负责：

- 根据问题匹配 3 至 6 个指标，而非固定读取目录第一项；
- 获取相关指标序列；
- 由程序生成期初、期末、峰谷、观测数、频率和滞后；
- 区分市场表现、经济传导假设和因果边界；
- 避免将跨主题共享市场变化单独归因于冲突。

### 6.4 反证核验 Agent

负责：

- 消费事件 Agent 与市场 Agent 的候选主张；
- 搜索相反报道、未执行条件、来源冲突和市场反向表现；
- 检查“计划”是否被误写为“行动”；
- 检查报道时间与事件时间；
- 形成判断失效条件和下一步观察点。

### 6.5 工具预算

预算不再只按问题类型静态给出，还根据以下反馈动态调整：

- 未覆盖分面数量；
- 新增独立证据率；
- 重复率和转载集中度；
- 最新日期材料是否缺失；
- T1/T2 来源是否缺失；
- 关键主张是否只有摘要、没有全文；
- 是否存在需要复核的冲突；
- 剩余上下文和输出预留。

连续两轮没有新增独立证据且覆盖已满足时允许提前停止。关键分面仍缺失且有预留预算时必须继续补查。

## 7. 检索、排序与主题污染控制

### 7.1 双通道结果

检索结果分为：

- `core`：满足主题实体和事件动作约束，可用于主题核心事实；
- `cross_topic`：仅存在间接关系，可用于市场背景或跨主题分析；
- `rejected`：不满足主题准入，保留审计原因但不进入回答上下文。

美伊核心记录不能仅因为包含“中东、原油、风险”而准入；俄乌核心记录不能仅因为出现“俄罗斯”而准入。

### 7.2 华泰内部消息

- 删除人为拼接 `topic_bridge` 的相关性提升；
- 使用消息实际文本、已有主题标签和相关性状态筛选；
- 将实体词、事件词和资产词拆开检索并重排；
- “中东原油策略”但不含伊朗、霍尔木兹或胡塞等直接实体时，只能进入跨主题市场补充；
- 内部消息在回答中使用独立章节和独立来源标识。

### 7.3 重复查询语义

搜索回执增加内部语义字段：

- `matched_total`
- `matched_already_seen`
- `returned_new`
- `budget_exhausted`
- `top_existing_ids`
- `cache_reused`

界面和模型不得将 `returned_new = 0` 表述为“数据库没有资料”。应显示“命中 N 条，其中本轮新增 0 条”。

### 7.4 共享查询缓存

缓存键使用：

`snapshot + topic + dimension + start + end + tool + canonical_arguments`

多个 Agent 请求相同查询时共享结果。底层只执行一次，但每个 Agent 都能获得同一结果视图。唯一新证据才计入发现预算，缓存读取不重复计费。

## 8. 分面全文选择

复杂局势问题的精读预算先分配保底，再全局重排：

- 最新事件：2 条；
- 外交或谈判：2 条；
- 军事或安全：2 条；
- 反证或来源冲突：2 条；
- 其余预算：按新鲜度、直接性、来源质量、正文完整度和事件多样性分配。

军事打击、伤亡、协议条款、制裁范围等高风险主张，优先读取两条独立来源全文。未读取全文的候选记录只能用于“线索”或“数据缺口”，不能直接成为最终关键事实。

所有子 Agent 后续读取的全文必须合并回共享 `key_evidence` 和 ResearchLedger。

## 9. ReadinessGate 覆盖门禁

### 9.1 覆盖状态

每个计划分面具有以下状态：

- `unstarted`
- `searched`
- `full_text_supported`
- `conflicted`
- `gap_confirmed`
- `budget_exhausted`

### 9.2 最终收敛条件

允许进入最终综合必须满足：

1. 所有必需分面达到 `full_text_supported`、`conflicted`、`gap_confirmed` 或 `budget_exhausted`；
2. “最新”问题已经检查最近 48 小时及最近 7 天；
3. 至少执行一次反证搜索；
4. 关键事实有全文依据；
5. 市场问题已读取匹配指标；
6. 最新材料不足时已有陈旧性警告；
7. 内部消息与公开证据已分开；
8. 有足够输出 token 预留。

模型若提前返回 `final`，该结果保存为 `candidate_draft`。协调器根据门禁缺口生成下一轮定向任务，不立即结束。

预算耗尽时允许强制收敛，但最终答案必须明确列出未完成分面和降级原因。

## 10. 综合、引用与数字校验

### 10.1 最终回答结构

结构根据用户问题动态裁剪，复杂局势问题默认包括：

1. 结论摘要；
2. 最新进展或事件主线；
3. 判断依据与证据分层；
4. 量化指标与资产传导；
5. 反证与不确定性；
6. 后续观察点；
7. 数据口径与缺口。

问题若只问具体数值、来源或原文，不强制展开完整七段。

### 10.2 逐主张引用

- 每个关键段落绑定 1 至 3 条真正支持该段的证据；
- 公开引用只能使用已经检索且允许引用的证据 ID；
- 关键事实默认优先使用已读取全文证据；
- 不允许使用一个通用 `S1` 覆盖整篇回答；
- 引用失败只降级对应主张，不使整篇答案失败。

### 10.3 程序化数字块

指标数值、单位、日期、前值、变化额、变化率、峰谷和观测数由程序根据工具结果生成。模型只描述含义、条件传导和限制。

数字校验失败时：

1. 精确定位数字所属主张或表格单元；
2. 删除或替换问题数值；
3. 保留不依赖该数值的定性结论；
4. 不删除整个段落或破坏 Markdown 表格；
5. 若无法修复，显示“具体数值校验未通过”，仍返回完整回答。

## 11. 错误处理与恢复

- 工具超时：保留已取得结果，记录 MCP 服务、工具、参数、调用 ID、重试次数和错误类型；
- 模型格式错误：把具体错误作为结构化 observation 回灌下一轮，执行一次针对性修复；
- 子 Agent失败：其他子 Agent继续运行，协调器保留对应分面缺口；
- 上下文超限：保留 ResearchLedger、精选摘录和 artifact 句柄，完整正文仍可按需重读；
- 引用校验失败：降级具体主张，不删除全部回答；
- 任一失败路径：最终必须返回包含“结论、依据、限制、观察点”的自包含中文答案；
- 恢复运行：使用稳定调用 ID 和检查点，不重复执行已成功的只读工具调用。

## 12. 前端可观测性

前端展示研究过程而非隐藏思维链：

- 阶段名称与完成状态；
- Agent 名称和研究任务；
- MCP 服务与工具名称；
- 参数摘要；
- 调用 ID；
- 开始、结束与耗时；
- 命中数量、已见数量和本轮新增数量；
- 读取的证据 ID；
- 缓存复用、重试、降级和错误来源；
- 每个研究分面的覆盖状态；
- 最终回答使用的证据与指标。

聚合对象工具不得显示为“返回 0 条结果”。无参数调用显示“无需参数”。长标识符必须正常换行，不能逐字符竖排。

## 13. 评测体系

### 13.1 评分维度（100 分）

| 维度 | 分值 |
|---|---:|
| 范围与截至时间正确 | 8 |
| 最新事实覆盖 | 15 |
| 主线与时间线 | 10 |
| 来源和事实边界 | 12 |
| 引用准确率 | 15 |
| 反证与矛盾处理 | 10 |
| 指标正确性 | 10 |
| 资产传导质量 | 8 |
| 缺口与观察点 | 7 |
| 可读性与决策价值 | 5 |

硬性限制：

- 主题污染、把计划写成行动、把报道数写成概率：总分上限 59；
- 关键数字无来源或单位错误：指标项计 0，并按项扣分；
- 最终正文为空、“见上”或表格残缺：不及格；
- “最新”问题忽略已有近三日关键事件：最新事实覆盖最高 5 分；
- 引用打不开或正文不支持主张：引用计错。

### 13.2 固定问题集

至少覆盖：

- 最新美伊冲突进展；
- 近两个月美伊主线；
- 胡塞—沙特和红海外溢；
- 霍尔木兹封锁或恢复判断；
- 美伊对原油、黄金、美债、信用、美元和权益的影响；
- “选举后打击伊朗”说法的支持与反证；
- 最新俄乌军事、援助、外交和制裁；
- 俄乌停火或会谈是否执行；
- 乌克兰援助实际交付；
- 俄罗斯财政压力；
- 欧洲天然气、粮食、贸易和援乌拨款；
- 美伊与俄乌的共同和相反资产驱动；
- 华泰内部消息与公开证据交叉核验。

每道题保存固定快照、金标事件、必需分面、允许的关键指标和不可接受的主题污染样例。

## 14. 实施顺序

1. 新增 ResearchLedger 和 ReadinessGate；
2. 将三个子 Agent 改为真正的有限工具循环；
3. 引入结构化分面查询、主题硬门控和分面全文配额；
4. 修复华泰内部消息的相关性与重复检索语义；
5. 实现问题驱动的多指标选择和程序化数字块；
6. 改造逐主张引用和局部数字修复；
7. 扩展前端可观测性和覆盖状态展示；
8. 扩充固定评测集并运行本地与 PiChat 对比；
9. 使用真实美伊、俄乌问题进行端到端回归和视觉验收。

## 15. 完成定义

以下条件全部满足方可认为 V2 完成：

- 复杂问题中的子 Agent 至少能执行“搜索—选择—全文—补查—备忘录”序列；
- 模型无法在关键分面未处理时直接结束；
- 最终关键主张能回溯到台账和具体证据；
