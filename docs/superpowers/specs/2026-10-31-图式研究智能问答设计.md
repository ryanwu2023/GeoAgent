# GeoAgent 图式研究智能问答设计

## 1. 背景与目标

当前本地智能问答已经具备工具调用、证据全文读取、多 Agent、研究覆盖检查、断点恢复、费用控制、引用与数字校验等能力，但任务理解和研究路径仍较依赖关键词规则与固定分面。短问题可能具有很高的研究深度，长问题也可能只是材料总结；仅凭关键词、问题长度或固定 Agent 组合，容易造成研究不足或过度执行。

本次改造采用完整图式研究 Agent 架构，目标是：

- 由模型理解任务意图、研究广度和执行深度；
- 由 Harness 校验计划、管理权限、预算、时间和执行状态；
- 由证据与执行反馈决定是否升级模式或重新规划；
- 由 Evaluator 判断证据是否真正回答子问题，而不只检查是否执行过检索；
- 在五分钟默认总时限内优先保证研究质量；
- 无论模型、MCP、页面连接或校验是否异常，都尽量返回有依据、说明缺口的最终答案；
- 保持 PiChat 路径不变，新旧本地 Harness 可配置切换和回退。

默认质量策略为“质量优先”。系统采用自动模式，并允许用户强制深度研究；不提供强制 Fast，以免绕过最低质量门槛。

## 2. 设计原则

1. **模型负责研究判断，Harness 负责执行纪律。**
2. **任务完成以验收条件为准，不以调用次数或结果数量为准。**
3. **研究计划可以修订，但每次修订必须有原因、版本和预算记录。**
4. **一条证据可以支持多个研究分面，不能被迫单标签归类。**
5. **数字来自程序查询，事实、声明、报道和模型推论必须分开。**
6. **最终答案围绕用户原始问题组织，不以内部数据分布或工具调用过程开头。**
7. **前端展示可审计动作和决策摘要，不展示隐藏思维链。**
8. **所有时间、预算、阈值、角色和模式策略均可配置并保留版本。**
9. **先持久化结果，再向前端通知，浏览器断开不能终止后台研究。**
10. **渐进迁移，复用成熟能力，不一次性替换数据、工具和证据底座。**

## 3. 目标架构

```text
用户问题
   ↓
Task Classifier
生成意图、广度、深度、时效性、风险和建议模式
   ↓
Policy Engine
校验主题、权限、最低模式、费用和五分钟总时限
   ↓
Research Planner
生成动态任务图、证据要求、验收条件和依赖关系
   ↓
Plan Validator
校验结构、依赖、工具权限、并发、时间和预算
   ↓
Task Graph Executor
按依赖执行节点，可分配给不同专业 Worker 并行运行
   ↓
Evidence Ledger
保存事实、声明、指标、推论、反证、来源冲突和缺口
   ↓
Research Evaluator
检查任务是否真正回答、证据是否足够新且支持结论
   ├─ 证据不足 → Replanner 增加针对性补查节点
   ├─ 证据冲突 → 增加来源核验和反证节点
   └─ 达到条件 → Report Synthesizer
   ↓
Citation & Numeric Validator
逐主张检查引用、数字、时间与指标口径
   ↓
最终答案或可解释降级答案
```

Fast、Standard、Research 统一使用任务图：

- **Fast：** 一至两个节点，例如“查询指标→回答”。
- **Standard：** 两至四个节点，例如“检索→读取全文→核验→回答”。
- **Research：** 四至八个研究任务，可多 Agent 并行并允许动态再规划。

质量优先的最低模式策略：

- 预测、情景分析、最新综合局势、资产影响默认 Research；
- 明确的数值、来源、原文查询可以 Fast；
- 已提供完整材料的简单总结可以 Fast；
- 分类置信度偏低时至少 Standard；
- 用户选择“强制深度研究”时直接 Research；
- Fast 或 Standard 在执行中发现证据不足、冲突或重大未确认事件时自动升级。

## 4. 改造边界

### 4.1 保留并复用

- `LocalGeoTools` 与现有 GeoAgent 只读工具；
- 华泰内部消息检索；
- 工具参数校验、白名单和访问权限；
- 工具批量执行、并发、超时、重试和缓存；
- PostgreSQL 运行、步骤、工具回执和证据持久化；
- Token、费用、上下文和并发限制；
- 引用、数字和指标口径校验；
- 确定性降级答案；
- PiChat 嵌入问答链路。

### 4.2 新增或拆分

- `qa_router.py`：任务画像、执行模式选择与升级策略；
- `qa_plan_schema.py`：任务图、节点、验收条件和计划版本结构；
- `qa_plan_validator.py`：结构、依赖、权限和预算校验；
- `qa_graph_executor.py`：任务图依赖调度与节点执行；
- `qa_evaluator.py`：程序与语义双层研究评估；
- `qa_replanner.py`：根据缺口生成补查节点与计划修订；
- `qa_synthesizer.py`：问题驱动的动态回答结构；
- `qa_orchestrator.py`：薄协调层；
- `qa_tool_registry.py`：标准化工具能力、权限和来源元数据；
- `qa_role_models.py`：分角色模型选择与回退。

原 `qa_harness.py` 在迁移期保留为兼容入口，新架构稳定并完成评测后再缩减或移除。

## 5. 任务画像

Classifier 输出结构化 `TaskProfile`：

```json
{
  "intent": "scenario_analysis",
  "breadth": "multi_domain",
  "depth": "deep",
  "freshness": "latest",
  "risk_level": "high",
  "requires_counterevidence": true,
  "requires_metrics": true,
  "requires_internal_sources": true,
  "suggested_mode": "research",
  "confidence": 0.88,
  "reason": "问题涉及未来情景、军事能力、政治意图和资产影响"
}
```

允许的意图至少包括：事实查询、材料总结、原因分析、比较分析、综合研究、预测研判、资产影响、来源核验和报告生成。

Policy Engine 可以基于权限、风险和质量策略提高模式，不得在缺乏明确依据时降低 Planner 建议的研究深度。

## 6. 研究任务图

`ResearchGraph` 至少包含：

- `plan_id`、`revision`、`parent_revision`；
- 用户原始问题和规范化研究目标；
- 执行模式与截至时间；
- 任务节点及依赖；
- 每个节点的工具类别、验收条件和预算；
- 修订原因、增加、取消和替换的节点；
- 当前配置版本与模型角色版本。

节点示例：

```json
{
  "id": "T2",
  "type": "capability_assessment",
  "objective": "评估伊朗封锁霍尔木兹海峡的能力与现实约束",
  "depends_on": [],
  "allowed_tool_categories": ["public_evidence", "internal_research", "market_data"],
  "acceptance_criteria": [
    "取得军事或航运层面的能力证据",
    "记录美国及盟友的反制能力",
    "明确不可观测的数据缺口",
    "检查至少一项相反证据"
  ],
  "budget": {
    "tool_calls": 8,
    "seconds": 90
  }
}
```

研究维度由 Planner 根据问题动态生成，不再对所有复杂问题固定要求外交、军事、市场和反证同一套分面。

## 7. 节点状态与计划修订

主状态：

```text
PENDING → READY → RUNNING → EVALUATING → COMPLETED
```

异常或中间状态：

- `INCOMPLETE`：证据不足，可以补查；
- `CONFLICTED`：证据冲突，需要交叉核验；
- `BLOCKED`：依赖、权限或工具不可用；
- `DEGRADED`：预算或时间不足，但已有部分可靠结果；
- `CANCELLED`：计划修订后不再需要。

只有 `COMPLETED` 与经过说明的 `DEGRADED` 节点可以进入最终综合。

Replanner 不重复通用查询，而是根据 Evaluator 的具体缺口生成新任务。默认最多三次计划修订。每次修订保留完整审计链。

## 8. 双层验收与证据台账

### 8.1 确定性检查

- 是否执行了真实时间范围；
- 是否读取完整正文；
- 证据 ID 是否存在；
- 指标是否包含日期、单位和来源；
- 工具是否有权限；
- 依赖是否完成；
- 时间、费用和调用预算是否超限。

### 8.2 语义检查

- 证据是否真正回答子任务；
- 证据是否足够新；
- 声明是否被误写为事实；
- 结论是否超出材料；
- 是否存在来源冲突；
- 是否遗漏重要反证；
- 指标是否能支持所述传导关系。

一条证据允许多标签：

```json
{
  "evidence_id": "E1",
  "facets": ["diplomacy", "military", "market"],
  "nature": "media_report",
  "source_tier": "T2",
  "freshness": "latest_48h",
  "supports": ["C1"],
  "contradicts": ["C2"],
  "full_text_read": true,
  "verification": "single_source_pending"
}
```

优先采用数据库已有结构化标签；缺失或不确定时再调用语义分类模型。

## 9. Evaluator 与动态再规划

Evaluator 必须输出结构化结果：

```json
{
  "task_id": "T2",
  "status": "incomplete",
  "verified": ["已经取得伊朗官方威慑表态"],
  "missing": ["缺少最新实际部署证据", "缺少美国海军同期反制材料"],
  "conflicts": [],
  "recommended_action": "replan",
  "suggested_queries": [
    "伊朗 霍尔木兹 实际部署 快艇 水雷 官方",
    "CENTCOM Hormuz escort minesweeper deployment"
  ]
}
```

Harness 不接受“研究质量良好”之类不可审计的自由文本作为完成凭据。

动态升级和再规划触发条件包括：

- 核心子问题未回答；
- 最新高可信材料缺失；
- 来源或时间口径冲突；
- 重大事件只有单一来源；
- 指标与新闻叙事不一致；
- Fast 或 Standard 发现跨领域依赖；
- 已有结论缺少反证或失效条件。

达到五分钟总时限后停止扩展，使用已有证据生成带缺口说明的答案。

## 10. 工具发现与外部 MCP

统一工具注册表记录：

- MCP 服务与工具名称；
- 能力类别；
- 支持主题；
- 读写风险；
- 延迟和成本等级；
- 权限与鉴权要求；
- 结果类型和参数 Schema。

路由顺序：

1. 用户和环境权限过滤；
2. 根据任务目标进行语义召回；
3. Planner 或 Worker 在候选工具中选择实际调用；
4. Harness 校验参数并执行。

外部 MCP 通过工作台配置后映射到统一能力类别。所有调用必须保留 MCP 服务名、工具名、参数摘要、时间、结果、错误、证据来源和截断状态。

## 11. Multi-Agent 策略

Multi-Agent 与问题复杂度解耦。只有满足以下条件才拆分：

- 至少两个任务相对独立；
- 需要不同专业能力或工具集；
- 并行预计节约时间；
- 剩余费用、Token和时间足够；
- 不会大量重复检索。

受控角色模板包括：事件研究、外交研究、军事研究、市场分析、来源核验、反证评估、内部研究和比较分析。Planner 可以选择模板，不能创建无限权限角色。只有主协调者可以生成最终答案。

## 12. 分角色模型配置

支持分别配置：

- Classifier：意图、广度、深度分类；
- Planner：任务图与验收条件；
- Worker Fast：查询扩展和普通摘要；
- Worker Reasoning：深度研究；
- Evaluator：完成度、冲突与缺口；
- Synthesizer：最终长文本综合；
- Translation：中文化。

每个角色可配置 URL、Key 引用、Model、最大输出 Token、温度、超时、重试、输入输出单价和启用状态。密钥只保存在本地后端，不返回前端、不进入 Git。

默认回退链：

```text
角色专用模型 → 推理模型 → 默认模型 → 确定性降级
```

## 13. 配置体系

建议默认配置：

```json
{
  "default_mode": "auto",
  "quality_profile": "quality_first",
  "allow_force_research": true,
  "deadline_seconds": 300,
  "reserve_synthesis_seconds": 40,
  "max_plan_revisions": 3,
  "max_tasks": 8,
  "max_parallel_tasks": 3,
  "max_total_tool_calls": 48,
  "max_tool_calls_per_task": 8,
  "max_context_tokens": 64000,
  "require_counterevidence_for": ["scenario_analysis", "prediction", "asset_implication"],
  "minimum_mode": {
    "prediction": "research",
    "scenario_analysis": "research",
    "current_situation": "research",
    "fact_lookup": "fast"
  }
}
```

配置保存版本、修改时间、修改人、变更差异和生效状态。历史问答引用当时配置版本。

五分钟默认软预算：分类与策略十秒、规划与校验三十秒、首轮执行一百五十秒、评估与补查六十秒、综合与校验四十秒、容错十秒。阶段可以借用剩余时间，但最后四十秒优先保留给最终答案。全部时间均可配置。

## 14. 正确性前置修复

图式 Agent 上线前必须修复：

1. 时间窗口按实际查询参数和回执记录，不能在任意搜索成功后同时标记48小时与7天完成；
2. 反证状态区分已搜索、候选命中、全文读取和有效反证；
3. 补查调用 ID 包含计划版本、任务 ID、查询摘要和时间范围；
4. 证据采用多标签；
5. 强制综合前重新运行 Evaluator；
6. 前值缺失时显示缺失，不使用窗口首值代替；
7. 费用账本持久化，恢复后继续累计；
8. 页面推送失败不终止后台研究；
9. 最终结果先持久化再通知前端；
10. 并发同时受运行配置和计划约束；
11. 工具参数使用 Schema 校验；
12. 支持原生 Tool Calling 时优先使用原生协议，JSON 文本仅作为兼容回退。

## 15. 错误隔离与恢复

节点独立失败。MCP 失败时依次尝试：同类替代工具、一次受控重试、记录缺口、交给 Evaluator 决定降级或继续。

断点恢复必须恢复：任务图版本、节点状态、工具回执、证据台账、费用、已用时间、模型角色、配置版本、Evaluator 结论和待执行补查任务。恢复后只继续未完成节点。

## 16. 动态回答结构

统一底线：首句直接回答问题；区分事实、声明、报道和推论；关键判断有证据；数字来自程序；说明反证、缺口和时效。

- 事实查询：直接答案、日期口径、来源和限制；
- 最新局势：核心判断、最新变化、事件主线、判断变化、反证、观察点；
- 情景预测：核心判断、基准与尾部情景、条件、反证和触发点；
- 资产影响：地缘驱动、传导机制、指标验证、条件方向和失效条件；
- 来源核验：主张、不同说法、已确认、冲突和缺口。

Synthesizer 根据 `TaskProfile` 选择或组合模板，不再强制所有问题使用同一五段式报告。

## 17. 前端可审计展示

前端展示任务画像、执行模式、任务图、计划修订、节点状态、MCP调用摘要、证据ID、Evaluator结论、缺口、费用和时间。技术细节默认收起。

系统展示“为什么新增任务、哪里证据不足、为什么升级模式、哪个工具失败”，但不展示隐藏思维链、逐 Token 推理或敏感原始错误。

## 18. 评测体系

固定问题集至少覆盖事实查询、最新局势、原因分析、情景预测、资产影响和来源核验，每类不少于十题；加入短问题高深度、长材料简单总结、来源冲突、最新资料为空、MCP超时、指标日期不同步、内外部材料冲突、跨主题和统计口径差异等困难样本。

质量评分：

| 指标 | 权重 |
|---|---:|
| 直接回答原问题 | 15% |
| 最新信息覆盖 | 15% |
| 事实与证据准确性 | 20% |
| 引用支持关系 | 15% |
| 反证与不确定性 | 10% |
| 分析与传导深度 | 15% |
| 数据口径正确性 | 10% |

另行统计时间、调用数、Token、费用、MCP失败率、计划修订次数和降级率。

同题对比当前本地 Harness、新图式 Agent、PiChat、关闭动态再规划的新图式 Agent、关闭多 Agent 的新图式 Agent，以识别质量收益来源。

## 19. 迁移阶段

### P0：正确性与可恢复性

完成第14节全部修复，旧 Harness 继续运行。

### P1：图式规划核心

实现 TaskProfile、ResearchGraph、Planner、Plan Validator、模式路由与自动/强制深研。

### P2：图执行器

实现依赖调度、节点并发、角色模板、工具语义路由、节点预算与恢复，复用现有 Scheduler。

### P3：Evaluator 与 Replanner

实现程序与语义双层评估、动态缺口任务、版本管理、最多三次再规划和五分钟总时限。

### P4：综合、配置与前端

实现动态回答模板、分角色模型配置、任务图展示、MCP溯源和HTML报告适配。

### P5：评测与切换

建立固定测试集、PiChat对照、影子运行、质量评分、默认切换与回退开关。

配置项：

```text
QA_ORCHESTRATOR=legacy | graph | shadow
```

- `legacy`：旧 Harness；
- `graph`：新图式 Agent；
- `shadow`：旧 Harness 回答用户，新图式 Agent 后台执行并记录对比。

## 20. 验收标准

- “伊朗会封锁霍尔木兹吗”识别为 Research；
- 已提供完整材料的简单总结走 Fast；
- 用户问美伊时不能由俄乌材料主导；
- 最新问题记录真实查询窗口；
