# 爬虫统一调度与 MCP 新闻接入设计

## 目标

项目服务启动后立即可用，并在后台按顺序运行全部本地爬虫。每个爬虫优先执行 `run_new.bat`，不存在时执行 `run.bat`；单个任务失败不阻断后续任务。全部任务结束后同步输出并冻结新快照。

页面提供 MCP 新闻源配置、连接测试、工具发现和新闻抓取。MCP 返回内容直接进入不可变快照，但统一标记为“待核验”，不视为已证实事实。

## 爬虫调度

- 独立后台进程读取 `collectors/collectors.json`，按注册顺序执行已启用爬虫。
- 每个项目只选择一个启动文件：`run_new.bat` 优先，其次为 `run.bat`。
- 调度环境设置 `RM_NO_PAUSE=1`、`RIM_NO_PAUSE=1`、`DSM_NO_PAUSE=1`，避免交互暂停和打开编辑器。
- 每个任务保留开始时间、结束时间、退出码、日志文件和错误摘要；状态写入 `data/crawler-runs/current.json`。
- 服务启动脚本先启动 Web 服务，再启动隐藏的爬虫调度进程。已有有效调度进程时不重复启动。
- 停止脚本核验进程身份后，先终止当前爬虫子进程及调度器，再停止 Web 服务。
- 全部任务结束后增量同步输出，并调用本地导入接口生成新快照。
- `market-context-monitor` 增加标准 `run.bat`，使所有启用项目均符合统一入口约定。

## MCP 配置与调用

- 本地配置保存于 Git 忽略的数据目录。服务端不向浏览器返回 Authorization 原文，只返回是否已配置。
- 支持 MCP Streamable HTTP：初始化、会话 ID、工具列表和工具调用。
- 页面配置服务器名称、URL、Authorization；支持测试连接和刷新工具列表。
- 页面选择新闻工具，并依据工具输入结构填写查询词、主题和最大条数；同时保留 JSON 参数编辑能力以兼容不同服务。
- MCP 返回的文本或结构化内容完整归档，再规范化为 `geo.v6/1`：稳定 ID、标题、摘要、原始链接、发布时间、采集时间、来源与主题。
- 相同链接沿用现有快照去重逻辑。采集文本仅作为资料，不作为应用执行指令。
- 新闻导入成功后立即生成新快照；结果核验状态为“待核验”，来源性质标明“MCP 新闻检索”。

## 页面

- 数据源面板增加“爬虫任务”和“MCP 新闻源”两个区域。
- 爬虫区域展示总数、执行中任务、成功/失败/跳过数量和最近日志。
- MCP 区域展示脱敏配置、连接状态、工具选择、查询参数和“获取新闻并生成快照”操作。
- 所有状态与错误采用中文；外部新闻链接保留原始语言并可直接打开。

## 安全与失败处理

- Authorization 不写入前端包、日志、快照或 Git。
- MCP URL 仅允许 HTTP/HTTPS；后端设置超时、返回体上限和本地写入边界。
- MCP 连接、工具调用或内容解析失败时不生成半成品快照，并保留可读错误。
- 爬虫失败不影响 Web 服务；调度器崩溃也不终止 Web 服务。

## 验收

- 启动项目后页面可立即访问，爬虫后台逐个运行且无交互窗口。
- `run_new.bat` 优先规则、失败继续、重复启动保护和停止联动均有测试。
- MCP 密钥不会通过状态接口回传，连接测试能列出工具。
- MCP 新闻能形成带来源和时间的记录并进入新快照。
- 全量后端测试、前端构建和浏览器关键流程通过。
