# 快照驱动的页面模型总结设计

## 目标

量化指标、情景推演和资产关联三个页面始终使用当前工作快照的全部相关数据。新快照产生后，旧快照的程序分析和模型总结不得继续显示；用户进入页面时，如果当前范围尚无总结，则自动调用模型生成完整中文研究回答。

## 刷新范围

刷新键由 `snapshot_id + topic + dimension + start + end + page + rule_version` 组成。以下情况触发刷新：

1. 导入或采集产生新快照并切换为工作快照；
2. 用户进入量化指标、情景推演或资产关联页面；
3. 用户切换主题、维度或日期范围；
4. 研究员完成证据复核，导致当前快照范围内的信号发生变化。

进入页面先重新请求 `/api/workspace`，确保结构化指标、证据、情景规则和资产矩阵均来自同一快照。模型总结不阻塞基础页面展示。

## 模型总结

后端新增页面总结接口。输入为刷新键及页面类型，服务端从冻结快照重新读取全部相关数据，并向模型提供：

- 当前值、前值、变化、时间、单位和统计边界；
- 相关证据及研究员复核状态；
- 情景条件、反证、失效条件和数据缺口；
- 资产传导规则、市场验证和待观察触发条件。

模型返回一段完整中文总结，直接回答当前变化、研究判断、资产含义及不确定性。量化指标页面侧重重要变化和异常解释；情景页面侧重成立条件、反证和下一触发项；资产页面侧重条件方向、期限和传导机制。

数字必须来自程序提供的事实包，引用必须属于当前快照。模型不得使用未提供的数字或把同步变化表述为已证实因果。

## 缓存与并发

同一刷新键只生成一次模型总结，保存到 SQLite。重复进入页面直接读取缓存。前端对同一键只保留一个进行中的请求；快速切换页面时，过期响应不得覆盖当前页面。

新快照使用新的缓存键，因此会重新生成。旧结果保留用于审计，但不会显示为当前结果。规则版本变化同样强制重新生成。

## 失败处理

模型未配置、超时、结构校验失败或引用校验失败时，页面继续展示程序计算和本地研究规则，并显示明确状态。失败结果不作为成功缓存；再次进入页面可以重试。模型总结必须标注生成时间、快照前缀和生成模式。

## 前端呈现

三个页面顶部增加“模型综合判断”区域，状态包括：正在汇总、模型总结、模型不可用和生成失败。刷新时只更新总结区域，不清空已经加载的图表、矩阵或情景卡片。

## 验收

1. 新快照切换后，三个页面均不显示旧快照总结。
2. 首次进入页面会生成总结，重复进入不重复调用模型。
3. 切换主题、维度或日期范围会使用新的总结范围。
4. 三个页面使用相同快照，所有数字和引用均能回溯。
5. 模型失败时结构化页面仍可用，并可再次触发生成。
6. 快速切换页面不会出现跨页面或跨快照响应覆盖。
