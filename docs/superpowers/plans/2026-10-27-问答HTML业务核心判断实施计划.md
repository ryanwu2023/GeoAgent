# 问答 HTML 业务核心判断实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在用户导出问答 HTML 时额外调用一次模型，按照原始问题语境生成可校验的业务核心判断，并在模型失败时保持报告可导出。

**Architecture:** 新增独立的业务核心判断生成器，负责语境识别、同快照材料整理、模型调用、输出校验和安全回退；HTML 渲染器只消费已经生成的核心判断，不直接访问模型。现有下载接口改为异步调用生成器，前端继续使用同一 URL 下载并展示生成状态。

**Tech Stack:** Python、FastAPI、Pydantic/标准 JSON、现有 OpenAI-compatible 模型客户端、MarkdownIt、React、TypeScript、pytest、Node 测试。

**Spec:** `docs/superpowers/specs/2026-10-27-问答HTML业务核心判断设计.md`

## 全局约束

- 所有新增文档、用户文案和错误提示使用简体中文。
- 核心判断长度为 150 至 300 个中文字符，直接回答用户问题的状态、变化、触发条件和相关资产含义。
- 语境来自原始问题、主题与筛选、当前回答、同快照证据和结构化指标，不固定为美伊与俄乌双主题。
- 快照编号、检索范围、来源等级和证据数量不得成为核心判断主体。
- 新增数字必须能由允许证据或结构化指标支持；内部消息不得写成已核实事实。
- 模型失败、超时、输出无效或校验失败时，HTML 仍须成功导出。
- 不更改原问答正文、引用、发布时间、采集时间和原始链接。
- 不向 HTML 泄露内部 ID、密钥、模型服务地址或异常堆栈。

## 评审重点

- 用户问题同时提到美伊和俄乌，但页面主题仍停留在单主题时，应以原始问题优先生成跨主题判断；由任务 1 的范围测试覆盖。
- 用户只问油价、霍尔木兹或援乌等细分问题时，不得泛化成全平台综述；由任务 1 的细分语境测试覆盖。
- 模型输出包含未提供的数字、无效证据 ID 或内部消息断言时，必须拒绝并回退；由任务 2 的校验测试覆盖。
- 模型超时、HTTP 错误或非 JSON 输出时，下载接口仍返回可用 HTML；由任务 3 的接口测试覆盖。
- 用户连续点击导出时，前端必须禁用按钮且恢复状态，失败时给出可理解提示；由任务 4 的交互测试覆盖。
