# 多源地缘新闻采集器实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增一个可单独调度、按来源审计的配置化采集器，把 20 个公开官方及媒体来源中的美伊和俄乌资料写入现有 GeoAgent 快照链路。

**Architecture:** 采集器分成配置与主题门控、合规 HTTP 与页面解析、运行编排与输出三层。每个来源独立发现和采集，公共管线统一执行两阶段准入、去重、`geo.v6/1` 输出和逐来源状态报告；受限媒体只使用公开元数据。

**Tech Stack:** Python 3 标准库、JSON、HTMLParser、urllib、现有 `geo.v6/1` 适配器与采集管线、pytest。

**Spec:** `docs/superpowers/specs/2026-10-31-多源地缘新闻采集器设计.md`

## Global Constraints

- 采集器 ID 固定为 `geopolitical-source-monitor`，输出类型固定为 `geo-v6`。
- 本次只支持 `usiran` 与 `ukraine`，不得采集或输出台海主题。
- 不破解验证码、不伪造登录、不绕过付费墙、不使用代理池规避封禁。
- 受限来源仅保存公开标题、摘要、发布时间和原始链接，`content_access` 必须反映实际可见范围。
- 所有凭据只能通过环境变量读取，不得进入配置、日志、归档或 Git。
- 官方声明只能证明发布主体作出声明，不得自动标记为独立核验事实。
- 不修改或覆盖当前工作区中会晤日历、中文化进度等无关未提交改动。

## Review Focus

- HTTP 200 但返回登录页、挑战页或空正文时，应记录受限或解析失败，不能算作全文成功；Task 2 覆盖。
- 同一报道经不同栏目 URL、跟踪参数或镜像发现时，应归并并保留别名；Task 3 覆盖。
- 标题只出现“美国、俄罗斯、以色列”等宽词时不得准入；Task 1 覆盖。
- 单个来源出现 403、429、超时或结构变化时，其他来源仍应产出且运行状态为部分完成；Task 3 覆盖。
- 历史累积文件包含旧规则污染记录时，应按当前规则重新复核后再保留；Task 3 覆盖。

**Interfaces:**

- Produces: `PolicyHttpClient.fetch(url: str, source: dict[str, Any]) -> FetchResult`

- [ ] **Step 1: 写请求策略失败测试**

使用假 HTTP 传输断言：禁止域名被拒绝；robots 禁止路径不请求；429 只有限重试；401/403 不重试；ETag 与 Last-Modified 写入后续请求；密钥不会出现在错误字符串。

- [ ] **Step 2: 写页面解析失败测试**

使用 fixture 断言 JSON-LD、OpenGraph、普通列表链接均能提取；登录页、挑战页、HTTP 200 空正文分别返回 `restricted_metadata_only` 或 `parse_error`；`metadata_only` 来源不请求受限正文。

- [ ] **Step 4: 实现 `PolicyHttpClient` 与解析接口**

仅使用标准库；每域名独立限速；缓存 robots、ETag 和 Last-Modified；对 429/502/503 做有限指数退避；识别常见登录、订阅和挑战页文本。候选 URL 必须通过 `allowed_hosts` 校验并移除跟踪参数。
