# G20 全球高层会晤日历扩展实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将会晤日历扩展为覆盖全部 G20 成员、欧盟及主要国际组织的全球高层外交日历，并清楚区分官方确认、媒体披露和待核验线索。

**Architecture:** 保留现有会晤事件状态机和冻结快照链路，将人物/国家/来源/查询拆入配置目录；新增通用官方页面适配器和确认等级策略。采集器输出统一结构化事件，后端负责冻结、筛选和导出，前端只消费结构化字段并展示覆盖状态。

**Tech Stack:** Python 3、标准库网络与 HTML/XML 解析、FastAPI、PostgreSQL 冻结快照、React、TypeScript、Node test、pytest。

**Spec:** `docs/superpowers/specs/2026-11-01-G20全球会晤日历扩展设计.md`

## Global Constraints

- 文档、页面标签、错误说明和新增业务字段说明全部使用中文。
- 未来 30 天是主要展示窗口；保留过去 21 天和未来 120 天事件。
- Google News 只用于发现，不得单独把事件提升为官方确认。
- 计划会晤地点不是人物实时位置。
- 一般新闻、普通表态和没有明确外交活动动作的内容不得进入日历。
- 单个来源失败不得中断整轮采集；必须保存来源级失败原因和覆盖状态。
- 不新增必须付费的运行依赖；凭据不得写入代码、配置样例或 Git。

## Review Focus

- 官方页面只返回相对链接、重定向链接或混合编码时，仍应提取规范链接并保存原始来源；由任务 2 的适配器测试覆盖。
- “没有计划会面”“拒绝出席”和历史背景中的 `met` 不得生成未来事件；由任务 3 的准入测试覆盖。
- 同源转载不得增加独立确认数，低等级来源不得覆盖官方日期、地点或状态；由任务 3 的确认策略测试覆盖。
- 某个国家源全部失败与已成功采集但无日程必须显示不同覆盖状态；由任务 4、5 的 API 与页面测试覆盖。
- 取消、推迟或否认记录必须更新已有事件而不是生成矛盾重复项；由任务 3 的生命周期回归测试覆盖。
