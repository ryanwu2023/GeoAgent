# 清洗、导入与展示数据链路

## 1. 处理链路

```text
采集器原始输出
  -> backend.paths 选择 CRAWLER_ROOT 或 demo 回退
  -> backend.adapters.load_bundle()
  -> normalize()：字段、日期、URL、来源、主题、维度
  -> merge()：按清洗后的记录 ID 合并，保留 raw_refs / adapters
  -> finance_adapter / taco_adapter / report_adapter
  -> backend.store.save_snapshot()
  -> FastAPI workspace / evidence
  -> React 地图与证据台账
```

## 2. 当前清洗行为

`backend/adapters.py` 当前执行这些操作：

- 读取 `ALL-records.jsonl`；缺少时按规则回退 `LATEST-records.jsonl`；
- 识别 `geo-v6.json`、金融序列、TACO 和报告适配器；
- 清洗 URL，去除跟踪参数和凭据型地址；
- 统一标题、摘要、来源、时间、主题、维度和验证字段；
- 对坏 JSON 行、非法字段和不合规协议保留错误信息；
- 相同记录 ID 合并时保留多个采集器、原始归档引用和维度候选；
- 记录 `raw_records`、`invalid_records`、`duplicates_merged`、`unique_records` 清洗计数；
- 对相同 `upstream_extractions` 做重复抑制；
- 原始输入按内容归档，不修改冻结快照中的原文。

当前去重主要是“清洗后的 URL/记录 ID 去重”。不同网址的转载、标题轻微变化或同一事件多来源不会自动合成一个事实；这是有意保留证据出处的边界。

## 3. 展示层的两个投影

### 地图和工作区投影

`GET /api/workspace` 提供地图、指标、资产、情景、来源和统计信息。当前 `records` 只提供地图与点位联动需要的轻量字段，不应重新放入正文、原文或抽取 payload。

地图记录的点位精度可能是 `explicit`、`area` 或 `mention`。地点是文章关联信息，不等于实时部署位置。

### 证据台账投影

`GET /api/evidence` 提供服务端分页和搜索：

```text
/api/evidence
  ?snapshot_id=<快照>
  &topic=usiran|ukraine|all
  &dimension=<可选维度>
  &start=YYYY-MM-DD
  &end=YYYY-MM-DD
  &q=<关键词>
  &offset=0
  &limit=30
```

响应字段：

```json
{
  "records": [],
  "total": 0,
  "offset": 0,
  "limit": 30,
  "has_more": false
}
```

完整证据继续通过 `/api/evidence/{id}?snapshot_id=<快照>` 按需读取。这样列表搜索不必把全部正文和详情传进浏览器。

## 4. 当前性能边界

分页已经降低了列表网络传输和浏览器全量过滤成本，但后端搜索目前仍在内存快照上做线性扫描。真实数据量增加后，下一步应：

1. 在导入时生成规范化的搜索字段和展示索引；
2. 用 SQLite FTS5 或等价索引实现标题、摘要、来源搜索；
3. 为地图单独提供最小点位接口，必要时按视窗或缩放级别聚合；
4. 记录工作区、证据分页和搜索接口的响应大小、耗时和数据库扫描量。

不要因为 Demo 的 948 条记录响应正常，就认为完整抓取数据量下没有问题。

## 5. 数据质量和研究边界

- 关键词主题匹配是候选筛选，不是语义核验。
- 来源等级和文章存在不等于陈述已经证实。
- `pledge`、拨款、交付和实际消耗不能合并成一个援助事实。
- 价格、收益率或通行量与事件同时变化，不自动构成冲突因果关系。
- 缺失值保留 `null`，不能填零；未知时间不能用导入时间冒充发布时间。
- 中文翻译是阅读层，原文、原链接和引用必须保留。
