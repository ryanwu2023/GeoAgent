# 代码目录与采集器清单

## 目录责任

| 路径 | 责任 | 是否提交运行数据 |
|---|---|---|
| `collectors/collectors.json` | 唯一注册表：ID、中文名、入口、主题、输出类型、自检参数、启用状态 | 只提交注册配置 |
| `collectors/<id>/` | 单个采集器的源码、配置、项目 README 和本地脚本 | 不提交 `output/` 运行产物 |
| `scripts/collect.py` | 推荐的统一运行入口；选择采集器、隔离子进程、同步输出、写运行报告 | 报告写入 `data/collection-runs/` |
| `scripts/refresh_crawlers.py` | 有限并发的旧批量刷新流程，依赖采集器内部 `tools/` 和分组定义 | 运行日志写入 `data/collection-runs/` |
| `scripts/integrate_collectors.py` | 从外部采集器目录迁入源码和输出的迁移工具 | 不用于日常抓取 |
| `backend/paths.py` | 解析源码根、输出根和 `CRAWLER_ROOT` 覆盖 | 不读个人绝对路径 |
| `backend/adapters.py` | 读取 JSONL、`geo-v6.json`、金融、TACO 和报告，完成归一化与快照导入 | 原始输入归档到 `data/archive/` |
| `scripts/audit_crawlers.py` | 基于现有输出和快照做只读质量审查，不重新抓取 | 报告可写到 `docs/` |
| `scripts/verify_latest_requests.py` | 浏览器界面回归检查，不是抓取器 | 截图/结果写入 QA 目录 |

## 单个采集器的标准结构

```text
collectors/<id>/
  README.md       信源、口径、参数、已知偏差、合规边界
  <entrypoint>    注册表中的入口脚本
  config.json     可选：信源、词表、维度和阈值
  run.bat         Windows 快捷入口；以 README 为准
  output/         本地运行产物，不提交
  tools/          可选：verify、probe、audit 等项目级工具
```

不同采集器的参数不能假设一致。统一入口只负责选择和隔离进程；具体参数、自检数量、回源核对方式必须看该采集器自己的 README。

## 维护原则

- 修改入口文件名、输出文件名或输出字段时，先同步更新注册表和本目录清单。
- `run.bat` 只是快捷方式，跨平台维护以 Python 入口脚本为准。
- `output/` 中的 `LATEST-*` 是滚动展示材料，`ALL-records.jsonl` 是累积结构化记录；它们不能互换语义。
- `geo-v6.json` 走统一协议；字段要求见 [`docs/adapter-contract.md`](../adapter-contract.md)。
- 金融序列、TACO 和军费指标有各自适配器，不能把一条新闻记录当成量化指标。
