# 新增采集器与变更检查清单

## 新增采集器

### 目录和代码

- [ ] 创建 `collectors/<id>/`，ID 使用小写连字符，和注册表唯一。
- [ ] 放置一个可直接运行的 Python 入口脚本。
- [ ] 添加项目 README，写清楚信源、口径、参数、输出、已知偏差和合规边界。
- [ ] 需要时添加 `config.json`、`run.bat`、离线 fixture 和项目级验证脚本。
- [ ] 不提交密码、API Key、个人绝对路径、网页缓存、完整运行历史或 `__pycache__`。

### 注册表

在 [`collectors/collectors.json`](../../collectors/collectors.json) 增加：

```json
{
  "id": "example-monitor",
  "name_zh": "示例监测",
  "topics": ["usiran"],
  "entrypoint": "example_monitor.py",
  "selftest_args": ["--selftest"],
  "output_kind": "records-jsonl",
  "enabled": true
}
```

`output_kind` 必须和实际输出匹配：

- `records-jsonl`：`ALL-records.jsonl` 或 `LATEST-records.jsonl`；
- `records-and-metrics`：记录和指标文件；
- `geo-v6`：`output/geo-v6.json`；
- `finance-series`：由金融适配器读取的序列；
- `taco`：由 TACO 适配器读取的结构化输出。

### 输出协议

普通记录至少提供 `id`、`title`、`summary`、`link`。主题和维度应使用项目支持的枚举。结构化扩展使用 `geo.v6/1`，完整字段见 [`docs/adapter-contract.md`](../adapter-contract.md)。

每条记录尽量保留：

```text
source_id / source_name / publisher / tier
published / fetched_at / first_seen / event_at
verification / original_url / topics / dimensions
```

未知字段保持空值或缺省，不编造时间、地点和数值。

## 修改现有采集器

- [ ] 先阅读该采集器 README 和配置，确认修改的是信源、筛选、去重还是输出口径。
- [ ] 保持原始来源 URL、采集时间和失败原因可追溯。
- [ ] 变更字段时同步检查 `backend/adapters.py`、适配器和 `docs/adapter-contract.md`。
- [ ] 变更指标单位、频率或公式时使用新指标 ID，保留旧口径的历史可追溯性。
- [ ] 增加一个离线 fixture 或自检断言覆盖修改点。
- [ ] 不用更宽的关键词掩盖数据缺口；先记录误命中样本和过滤原因。

## 运行前检查

```bash
.venv/bin/python scripts/collect.py --list
.venv/bin/python scripts/collect.py --id <id> --verify-only
```

然后再运行真实抓取：

```bash
.venv/bin/python scripts/collect.py --id <id> --timeout 900
```

检查：

- [ ] 进程退出码为 0；
- [ ] `data/collection-runs/<timestamp>/results.json` 有记录；
- [ ] 输出文件位于预期目录；
- [ ] 文件不是空文件或半成品；
- [ ] `_fetch_stats.json` / `_source_status.json` 与 stdout/stderr 一致；
- [ ] 失败源、无数据源和被筛选记录有明确状态。

## 导入前检查

```bash
curl -s http://127.0.0.1:8000/api/status
curl -X POST http://127.0.0.1:8000/api/import
.venv/bin/python scripts/audit_crawlers.py
```

- [ ] 快照记录数、指标数和错误数符合预期；
- [ ] 清洗计数能解释原始行数、坏行、重复和最终记录数；
- [ ] 主题、维度和来源数量没有异常跳变；
- [ ] 关键时间、单位、空值和引用保持原始含义；
- [ ] 原始文件已归档，旧快照没有被覆盖。

## 提交前检查

```bash
git diff --check
.venv/bin/python -m pytest -q
npm run build
git status --short
```

提交时只暂存对应采集器、注册表、测试和说明文件。不要使用 `git add .` 把 `.env`、`data/` 或本地报告一起提交。

## 质量结论的写法

报告必须区分：

```text
代码自检通过
请求/来源状态
筛选后是否有记录
字段清洗和去重结果
指标回源对账结果
人工核验范围
事实与因果判断的限制
```

“采集器退出码为 0”“快照导入成功”“页面展示正常”分别是不同证据层，不能合并成“数据已验证”。
