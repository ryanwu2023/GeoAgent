# 网页用户管理

## 需求

- 只有管理员能创建用户；除用户管理外，所有用户的研究功能完全相同。
- 创建时可以不填密码，此时初始密码与账号相同。
- 管理员可直接修改任一普通用户的密码，不需要知道原密码；新密码留空则重置为与账号相同。
- 管理员可删除普通用户（逻辑删除），删除后同名账号可重新创建。
- 修改密码或删除用户后，该用户已有的登录会话立即失效。
- 在 GeoAgent 创建的用户同时在 PiChat 中存在：创建时同步物化 PiChat 嵌入影子用户，PiChat 失败则整条用户不创建。

不做：用户自助改密、角色分级、页面上创建或修改管理员。

## 账号来源与权限

| 账号类型 | 来源 | 能力 |
| --- | --- | --- |
| 管理员 | `GEO_WEB_AUTH_FILE` 挂载的 htpasswd 文件（SHA512-crypt），与原登录方式相同 | 全部研究功能 + 用户管理 |
| 普通用户 | PostgreSQL `web_users` 表，由管理员在页面创建 | 全部研究功能，不能访问用户管理 |

- 管理员账号只能通过部署配置（Sealos Secret / 内网 auth 文件）增删改；页面上不能修改或删除，普通用户也不能取与管理员相同的账号名。
- 未启用网页登录（`GEO_WEB_AUTH_ENABLED=false`）时用户管理接口返回 404。
- 密码只保存 SHA512-crypt 哈希（5000 轮，与 htpasswd 文件一致），从不保存或回显明文。

## PiChat 同步

PiChat 对接入产品的用户采用“嵌入影子用户”模型（见 pi-chat-server `docs/architecture/auth-and-identity.md` §5）：产品服务端用 `pk-` 应用 Key（scope `embed:identity`）调用 `POST /api/v1/embed/identity`，PiChat 按（应用, productUserId/手机号）物化或复用一个 `userType: embed` 的用户。GeoAgent 沿用右侧面板已在使用的这一接口，不调用 PiChat 管理端 `/admin/users`，也不保存 PiChat 管理员凭据。

创建流程：

1. 生成 `product_user_id = geo-<32位随机十六进制>`；手机号取管理员填写值（大陆手机号规范为 `+86…`，其他须 E.164），未填则按 `product_user_id` 哈希生成 `+999` 开头的 14 位占位号码（+999 为未分配国家码，不会与真实号码冲突）。
2. 在数据库事务内插入用户行（锁住账号与手机号唯一性），然后同步调用 PiChat 嵌入身份接口，`displayName` 为 GeoAgent 账号。
3. PiChat 返回 `ok` 且带 `userId` 时写入 `pichat_user_id` 并提交；未配置应用 Key（503）、网络失败、HTTP 错误或 `ok:false`（502）时回滚，两边都不留下用户。401/403 不回显上游内容。

之后该用户打开右侧智能问答时，`/api/pichat/embed-identity` 用其自己的 `product_user_id`、手机号和账号名换取面板令牌，会话与额度在 PiChat 中按人隔离。管理员账号与未开启登录的本地使用仍共用“连接配置”里的产品用户 ID 与手机号。

边界：

- 改密只影响 GeoAgent 登录，PiChat 影子用户没有密码，无需同步。
- 删除只在 GeoAgent 逻辑删除；PiChat 影子用户与绑定保留（嵌入接口无停用能力），GeoAgent 不再为其签发面板令牌，已签发的令牌最长 1 小时后失效。
- 同名重建会生成新的 `product_user_id` 与占位号码，在 PiChat 中是新用户，看不到被删除用户的历史会话。若管理员复用被删用户的真实手机号，PiChat 会因手机号已绑定旧用户返回别名冲突，创建失败。
- 多个 GeoAgent 部署（如 Sealos 与内网）共用同一个 PiChat 应用时，随机 `product_user_id` 保证互不冲突；同一真实手机号只能在其中一处使用。

## 接口

均在 `/api/auth` 下，需已登录的管理员会话；写操作还需同源 `Origin` 与 `X-GeoAgent-Login: 1` 请求头（与登录接口相同的防跨站约束）。

| 方法与路径 | 请求体 | 说明 |
| --- | --- | --- |
| `GET /users` | — | 返回 `{admins: [账号], users: [{username, phone, pichat_user_id, created_by, created_at, updated_by, updated_at}]}`，不含已删除用户 |
| `POST /users` | `{username, password?, phone?}` | 创建用户并同步 PiChat；201 返回 `{username, default_password, phone_generated, pichat_user_id}`。账号须为 2-64 位字母、数字或 `_.@-` |
| `PUT /users/{username}/password` | `{password?}` | 管理员直接改密，无需原密码；同时清除该用户全部会话 |
| `DELETE /users/{username}` | — | 逻辑删除并清除会话 |

错误：未登录 401；非管理员或缺少防跨站头 403；用户不存在 404；账号或手机号已存在、试图修改管理员 409；账号或手机号格式不符 422；未配置 PiChat 应用 Key 503；PiChat 不可达或拒绝 502。

`GET /api/auth/session` 与 `POST /api/auth/login` 的返回增加 `is_admin`，前端据此在页头显示“用户管理”按钮。

## 界面

页头“用户管理”按钮（仅管理员可见）打开弹窗：创建用户表单（账号、密码、选填手机号）、管理员与普通用户列表（显示手机号或“占位手机号”、PiChat 用户 ID），普通用户行可修改密码或删除（删除前确认）。

## 数据

新增表 `web_users`，字段与索引见 [数据字典](database/data-dictionary.md#web_users)。表随 `backend/schema.sql` 在应用启动时以 `CREATE TABLE IF NOT EXISTS` 创建，无需单独迁移；回滚旧版本时该表保留但不再被读取，此前创建的普通用户将无法登录。
