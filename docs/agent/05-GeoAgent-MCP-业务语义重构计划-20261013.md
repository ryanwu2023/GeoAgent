## 1. 目标与边界

**Agent 调用 Tool，是为了让用户通过 Agent 了解、分析其在业务看板上可见的数据。**

不是简单开放数据库字段，也不是将 REST 接口逐个包装成 MCP。用户用业务语言提问，Agent 应能理解问题、选对工具、保持看板范围，并基于真实返回说明数据含义、变化、证据、条件和缺口。

职责划分：

- 看板与共享业务层：定义指标、统计范围、计算方法、展示解释、证据状态与规则版本，是同口径的依据。
- MCP Tool：提供可发现的业务能力及自解释参数，返回有范围、有语义、有来源、有边界的数据；程序负责确定性计算。
- Agent：理解用户意图、组织工具调用、综合解释和追问，区分事实、规则与推断；不能靠猜字段或臆测补齐语义。
- MCP 工作台：检查原始工具契约、真实返回和调用记录；不代表 PiChat 最终加工后的模型上下文，也不能替代嵌入问答验收。

保留现有嵌入对话框，不重建自有聊天 UI。本计划不包含采集重跑、生产凭证变更或自动发布。管理员工作台免填 MCP Key 与对外 MCP Bearer 鉴权保持分离。

## 3. 菜单到业务能力的目标映射

工具名为设计候选，不是已存在接口；实现前在契约评审中冻结，避免无必要的工具膨胀。

| 看板菜单 | 用户问题示例 | 目标能力与调用路径 |
|---|---|---|
| 风险监测 | 当前升级线索有多少？主要是什么事件、哪些地区？ | 当前上下文 → 风险概览/分组 → 对应证据；分类采用看板同一投影 |
| 证据台账 | 这条报道为什么归为升级？是否核验过？ | 同口径检索 → 证据详情 → 分类及复核依据、来源与时间 |
| 情景推演 | 当前判断有哪些反证？升级条件满足了吗？ | 情景规则 → 候选材料 → 条件映射与核验状态；未知不能回答为没有 |
| 数据源 | 哪些来源失败？哪个维度缺数据？ | 快照来源/项目健康 → 覆盖与时间缺口；需要当前状态时另读采集工具 |
| 采集管线监控 | 最近一批完成了吗？哪些来源失败？ | 批次发现 → 批次详情/来源事件；明确日志边界与状态时间 |
| 智能问答 | 还缺什么数据？ | 按指标、证据、覆盖、时效分维度综合；不是仅复述一条通用免责声明 |
| 量化指标 | 本周哪些指标发生变化？美债变化意味着什么？ | 指标发现 → 程序计算区间变化 → 指标定义、作用机制、质量和边界 |
| 资产关联 | 对信用债有什么影响？依据是什么？ | 五类资产概览 → 指定资产详情 → 市场观测与条件路径、候选证据、反证及缺口 |
| 研究简报 | 上份简报与这份有何变化？ | 档案列表 → 两份正文/结构化比较；保留各自快照和生成时间 |

## 4. 工具契约与返回设计原则

### 4.1 发现与输入

- description 说明“回答什么问题、何时使用、与相邻工具区别、何时不适用”，避免只有技术实现名或堆叠历史错误提醒。
- 每个参数必须有业务 description。主题、维度提供中文名与机器值映射；series/record_id/snapshot_id 说明从何工具取得。
- 日期明确格式、包含边界、所筛选时间字段和时区。记录发布时间与指标观测日不得混称。
- 当前看板上下文至少包含 snapshot_id、topic、dimension、start/end；地图事件/地区筛选及选中证据等需盘点后明确是否传入。
- 用户显式范围优先于当前面板范围，面板范围优先于默认值；覆盖时回显差异。上下文缺失时发现或澄清，不能静默切到 latest/all。
- 限额明确是结果项、观测点还是正文长度；提供总数、截断标志和下一步读取方式。非法日期/范围在服务端验证。

### 4.2 返回给 Agent 的语义

保留机器可读 JSON；不把“自然语言化”误当“语义化”。每类结果按需包含：

| 层次 | 应表达的内容 |
|---|---|
| 上下文 | 实际快照、主题/维度/日期、读取时点、快照时间、规则版本 |
| 观测事实 | 数值、单位、观测日期、前值日期、变化值及程序计算依据 |
| 业务定义 | 中文名称、指标含义、统计对象、频率、scope、method、comparison_step |
| 质量 | 有效零值、缺失、隔离、滞后、未评估、截断分别表达；提供原因 |
| 解释规则 | 如何看变化、可能作用机制、成立条件、反向条件、适用范围 |
| 证据 | 可追溯 ID、来源、发布/采集时间、核验状态、与结论关系 |
| 认知边界 | 已观测/规则条件/模型推断/未知分层；单方通报不等于独立核实 |

概览先给能回答核心问题的有限结果，详情按需读取。不在每条响应重复全部资产、情景和长篇提醒。未配置的解释明确为待补充，不套用别的指标规则。

### 4.3 不应新增的“能力”

- 不让 Tool 生成无依据的因果归因或情景概率。
- 不把静态失效条件包装成已发生反证。
- 不把候选维度覆盖当作完整数据覆盖。
- 不因 limited/empty/not_evaluated 推断整个快照不存在材料。
- 不把 UI 格式化数值直接代替原始值；原始单位与展示单位明确可转换。

## 5. 实施阶段与退出条件

### R0：菜单盘点与契约冻结

- 逐菜单列出字段、筛选、计算、解释、详情和来源路径，形成“看板字段 → 业务函数 → Tool字段 → 测试”矩阵。
- 在固定工作快照上保存基线，标注全量/抽样、不同口径与缺失能力。
- 冻结工具职责、上下文优先级和返回示例；把S01—S12映射到实施账本任务。
- 退出：所有可见业务数据均有目标读取路径或明确的不支持说明；没有把页面像素、管理凭证等当作研究数据。

### R1：共享业务语义与上下文（P0前置）

- 抽取指标定义与解释的单一来源，供看板和 MCP 使用，避免前后端各维护一份。
- 统一证据检索/展示分类/复核投影，抽取计数范围与时间规则。
- 补工具及参数业务描述、字典发现、当前面板上下文传递与实际范围回显。
- 增量兼容现有工具；破坏性变更明确版本和迁移，不突然删除生产 Agent 已使用字段。
- 退出：同一输入范围的核心字段与看板一致，所有参数可理解；快照/主题切换不会沿用错误上下文。

### R2：语义返回与缺失业务能力

- 优先补指标语义、程序计算周变化、证据—条件映射及未知状态；再补数据源健康、资产按需详情和精简概览。
- 根据盘点补批次发现/历史比较、简报比较，不重复包装已有能力。
- 工作台清楚展示原始 MCP 契约和真实返回；独立管理口令移除已作为后续用户变更本地完成，发布状态单独验收。
- 退出：S01—S12逐项实现或经明确决策延期；真实返回可独立解释范围与含义，限额不会隐藏关键状态而不提示。

### R3：自动化与工作台验收

- 增契约测试：参数 description/合法值发现、范围校验、分页、空结果、未知、零值、隔离、单位、舍入与截断。
- 增共享业务层对照测试：风险计数、证据分类、来源健康、指标解释、情景和资产路径。
- 工作台实际执行每类工具，检查搜索、参数、成功/失败返回及调用记录；保留公开 MCP 的鉴权回归。
- 退出：全量测试与构建通过，差异有解释，工作台成功不冒充 Agent理解通过。

### R4：嵌入 Agent 自然问答验收

- 先在本地项目嵌入面板验收，不在 PiChat 普通聊天页替代产品现场。
- 独立新会话输入自然问题，不提供预期答案、内部工具名或字段名，验证 Agent 自主选工具。
- 对照同快照同筛选看板、实际调用参数、工具回执和最终回答，分别判断取数正确、口径正确、解释正确。
- 每个菜单至少3个自然用例，另加跨菜单、上下文切换与反例；原有业务用例保留并修订，不能以纠错追问通过替代首问稳定性。
- 退出：全部P0场景独立首问通过；数值、来源、范围、时间、规则/事实分层无关键错误。未通过项明确保留，不能由通过率掩盖。
- 外网发布需后续明确执行发布，再在外网重复关键验收；本地通过不等于已发布。

## 6. 首批必须覆盖的验收场景

| 场景 | 必核对点 |
|---|---|
| 本周哪些指标发生变化？ | 快照相对周、首末观测、频率/比较步长、程序计算、单位，不把单期变化冒充整周 |
| 当前判断有哪些反证？ | 条件与证据区分；未评估＝未知，不是没有；正文和标题一致 |
| 还缺什么数据？ | 指标/证据/覆盖/时效四类；有效零值、隔离、统计排除不误报缺失 |
| 为什么看板2301，快照4384？ | 同一快照的主题范围与全量范围解释，而非断言数据错误 |
| 美债收益率上升意味着债券收益增加吗？ | 收益率与持有期回报区别；期限、单位和条件机制来自共享定义 |
| 某条新闻为什么标为升级相关？ | 自动分类/人工复核及依据与看板匹配，不只复述文章 |
| 哪些来源失败，影响哪些维度？ | 快照来源统计与live批次区分；不足以判断影响时明确缺映射证据 |
| 对信用债有什么影响？ | 相同筛选、信用利差/国债区别、条件路径及数据缺口；不得归因冲突 |
| 两份简报判断变化了吗？ | 两份档案及快照、生成时间、实际内容差异，不能编造历史结论 |
| 切到俄乌/历史快照后追问“当前呢？” | Agent获得新的上下文；不沿用美伊或latest答案 |

每条记录：用例ID、页面基线、自然输入、实际工具/参数、回执时间与ID、关键返回、回答摘录、判定、缺陷、修复及复测。截图/回执不包含凭证；模型自行声称调用次数不替代实际记录。
