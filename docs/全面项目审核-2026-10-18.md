## 阻断公开生产交付的问题

1. **外部模型不可用。** 当前配置为 `deepseek-v4.1-flash`，模型健康检查返回 HTTP 502。页面可保留本地检索证据，但模型总结、页面综合判断和生成式简报会降级。
2. **数据不是当天快照。** 10 月 18 日审核时，最新完整采集和快照仍停留在 10 月 16 日。应先确认统一采集任务的日程、主机唤醒和失败通知，再把“每日简报”用于盘前决策。
3. **外部 MCP TLS 校验被关闭。** `haifutong` 使用 HTTPS，但 `verify_tls=false`。这会削弱服务器身份校验；应安装正确证书链并恢复校验。
4. **开源许可证未确定。** 仓库计划公开到 GitHub 时，需由所有者选择许可证，并确认 ICE、Yahoo、研报和新闻内容的再分发边界。

## 高优先级改进

### 数据与研究质量

- 来源审查发现 32 条记录的发布时间晚于采集时间超过 5 分钟，9 个来源没有 HTTP 状态，另有 1 个 403、1 个 404。需要修复时区、发布日期提取和来源健康重试。
- 仍有 168 条资讯待中文化；另有西里尔文、波斯语等多语种记录，应按语言路由，不应统一套用英中翻译。
- 民调、布伦特波动率和部分代理指标仍要强化结构化口径。指标页面应继续显示调查机构、样本、调查区间、序列变换和不可比原因。
- 资产方向仍依赖“新闻事实—宏观传导—市场验证”三层证据。应优先补齐原油供应/运输、欧洲天然气库存、俄财政、乌外部收支、援助实际拨款的稳定历史序列。

### 性能与存储

- 非地图工作台冷请求约 0.9 秒、0.96 MB；地图数据约 6 MB、冷请求约 1.7 秒。下一步应把指标、来源、资产和情景拆成独立接口，并为地图增加服务端按区域/缩放聚合。
- 每个不可变快照保存完整 JSON，数据库已接近 900 MB。建议迁移为规范化记录/观测表加快照成员表，快照只保存成员 ID、版本和分析元数据。
- 主包约 581 KB，deck.gl 约 880 KB，MapLibre 约 1.04 MB（压缩前）。地图已懒加载；其余页面可继续按路由拆包。

### 架构与运维

- `src/App.tsx`、`backend/app.py`、`backend/research.py` 仍承担过多职责。建议按工作台、证据、地图、简报、问答和管理端拆分路由与状态。
- 多个采集器存在重复的网络、重试、输出和来源状态逻辑。应收敛到共享采集 SDK，并对超时、429、403、解析为空和旧文件回退使用统一事件码。
- 公网部署依赖网关 Basic Auth；应用内管理接口没有单独的角色权限。必须保证后端端口不直接暴露，并为 MCP 配置、采集运行和人工研判增加审计身份。
- 浏览器验收依赖本机 Playwright 与 Edge，但开发依赖没有独立锁定。建议增加 `requirements-dev.txt` 或统一的 QA 容器。
