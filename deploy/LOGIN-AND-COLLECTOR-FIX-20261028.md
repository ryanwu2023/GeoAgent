## 代码修复边界

- 代理绕行限定在已核实的国内采集器子进程；不改变其他应用或境外源的出口。
- 托管环境的两个大型 RSS 采集器最多 3 路并发；保留来源状态与错误，不关闭 TLS 校验。
- 在清理失败暂存目录前，将有大小上限且脱敏的来源诊断写入结果；归档不再用上一轮成功状态替代本轮失败证据。
- 账号缺密钥继续明确失败，退出码/来源状态不改成成功。
- “允许部分成功数据导入”是独立业务策略，需要按用户选择配置；本修复不偷偷放开门禁。

## 独立登录页面

- 保留原有 Sealos `geoagent-web-auth` Secret 内的账号及 SHA512-crypt 密码哈希，不更换密码。
- 浏览器访问 `/login` 输入账号密码；业务 API 在后端强制校验会话，失效返回 401 JSON，不再触发 Basic Auth 弹层。
- HttpOnly、Secure、SameSite Cookie；12 小时有效；PostgreSQL 仅保存令牌哈希；退出登录、密码变化使原会话失效。
- 登录限速及跨站请求检查；MCP 仍独立使用 Bearer Key，不接受网页登录 Cookie 代替 Key。
- `/readyz` 检查数据库和登录配置；健康探针不访问受保护的业务接口。

## 发布与回滚

新应用镜像、应用认证 Secret 挂载、`/readyz` 探针及版本化网关 ConfigMap 必须在同一次 Pod 模板变更中切换。禁止先在旧网关关闭 Basic Auth、再慢慢更新应用，否则旧应用会暂时失去保护。

回滚到改版前镜像时，要一并恢复发布前保存的 Pod 模板（包括旧 Basic Auth 网关）。不能只回滚镜像却保留无 Basic Auth 的新网关。CI 已拒绝在新网关后面直接回退到不含 `backend.web_auth` 的旧镜像。
