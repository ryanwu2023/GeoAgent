# HFT 内网部署问题记录

2026-11-03 至 2026-11-04 部署 GeoAgent（172.16.91.120）与 PiChat（172.16.91.119）时遇到的问题。截图在 `images/`，脚本在 `scripts/`。

| # | 环节 | 现象 | 原因 | 解决 |
|---|---|---|---|---|
| 1 | 远程接入 | 堡垒机 SSH 2222 端口输入 OTP 一直提示无效 | 未查明（网页登录同一 OTP 有效） | 改用堡垒机网页 Web 终端 |
| 2 | Web 终端 | 连接 .119 时跳到客户端下载页 | 连接方式被选成“客户端” | 连接对话框选 Web → Web CLI，见 `images/04`、`images/05` |
| 3 | Web 终端 | 命令只输入未执行一段时间后会话断开 | 堡垒机空闲自动登出（auto-logout） | 重新点资产连接；输入命令后立即回车 |
| 4 | 文件上传 | 上传后在服务器找不到文件 | 批量传输时没勾选目标服务器或选错 | 左侧资产树勾选目标服务器，用户填 hfttest，文件落在 `/tmp/` |
| 5 | 文件上传 | 进度长时间停在 99% | 浏览器已传完，堡垒机仍在转发到服务器；814MB 约 15 分钟 | 等到出现“状态: 成功”；不要关闭页面 |
| 6 | 文件上传 | 单文件限制 200MB | 堡垒机批量传输限制 | `split -b 180m` 分片，服务器上 `cat` 合并并用 `sha256sum -c` 校验 |
| 7 | 镜像构建 | Mac 上 x86 构建 PiChat 在 pnpm install 后崩溃（uv__io_poll Assertion） | QEMU 模拟 x86 的已知问题 | 新建 Colima Rosetta 虚拟机构建：`colima start x86build --vm-type vz --vz-rosetta`，构建时用 `docker --context colima-x86build`（注意：start 会切换默认 context，用 `docker context use colima` 切回） |
| 8 | 镜像导入 | `image not known` / 名字对不上（出现两次） | `podman load` 单镜像加 `docker.io/library/`，多镜像加 `localhost/` 前缀 | 脚本按 `名字:标签` 后缀匹配实际导入名，见 `images/16`；Docker `docker load` 保留原名 |
| 9 | PiChat 数据库 | PostgreSQL 容器启动即退出，`mkdir /var/lib/postgresql: Permission denied` | 宿主目录 root 700，镜像以 postgres(uid 999) 建目录 | `chown 999:999 /srv/pichat/postgres`，见 `images/13` |
| 10 | PiChat 服务 | Podman 下 api 启动失败 `unknown mount option "uid=1000"` | Podman 4.9 tmpfs 不支持 uid 参数 | 改 `mode=1777`（已迁 Docker，Docker 支持 uid），见 `images/14` |
| 11 | GeoAgent 验证 | curl 登录返回 405/403 | 登录接口是 `/api/auth/login`，且需请求头 `X-GeoAgent-Login: 1` 与匹配的 `Origin` | 按正确接口和请求头验证，见 `images/12` |
| 12 | Docker 安装 | `containerd.io conflicts with runc` | RHEL 8 的 Podman 依赖 runc，与 Docker 冲突 | `dnf install --allowerasing`，会卸载 Podman；先停 Podman 服务、迁移到 Docker |
| 13 | PiChat 沙箱 | api 日志 `docker 不可达 spawn docker ENOENT` | app 镜像不含 docker 命令 | 所有平台服务改用 runner 镜像（= app + docker CLI），与 PiChat 本地部署一致 |
| 14 | PiChat 沙箱 | runner 健康检查启动后短时间返回 503 | 启动中，尚未就绪 | 等 30–60 秒再查 `curl 127.0.0.1:8082/healthz` 应为 `ready` |
| 15 | 网络 | Mac 通过 VPN 访问不到 .119:8080 / .120:8000 | VPN 只放通堡垒机 | 需海富通 IT 开通 VPN 路由或堡垒机 Web 资产 |
| 16 | 网络 | 服务器访问百度、阿里云、OpenAI 都不通，DNS 正常 | 网关封出网 | 需海富通 IT 提供出网代理 / 白名单 / 内网模型 |
| 17 | 文件上传 | 2.5GB 一次传输约 30 分钟后失败，浏览器显示 `ERR_NETWORK_CHANGED`，服务器上一个文件都没有 | 上传期间本机网络变化（VPN 重连 / Wi-Fi / 代理切换），整批作废 | 每批控制在约 900MB（5 片）以内；上传期间不切换网络；失败后整批重传 |
| 18 | 网络 | 2026-11-04 复测：.119/.120 已能访问国内站点（百度、阿里云、阿里云 ACR、DeepSeek、通义 DashScope、Kimi、智谱、清华 PyPI、npmmirror）；OpenAI、Docker Hub 不通，Anthropic 403；luozi-chat.lhotsetech.com 不通 | 海富通已放开国内出网 | 镜像可改走阿里云 ACR 拉取；模型可用国内厂商 API |
| 19 | PiChat 管理台 | 表单填到一半跳回“系统就绪度”页，已填内容丢失 | 管理会话空闲 5 分钟（或满 15 分钟）自动锁定 | 先准备好 Key/Token 再开表单，5 分钟内填完保存 |
| 20 | 嵌入应用 | 入口绑定的 Agent 被保存成“研报合规审计” | 下拉框点击错位，选中了别的 Agent | 保存后点“编辑”核对入口 Agent，应为“GeoAgent 地缘数据分析助手” |

| 22 | MCP 连接 | 健康检查默认 `/health`，GeoAgent 无此路径 | GeoAgent 健康检查路径是 `/healthz` | 健康检查地址填 `http://172.16.91.120:8000/healthz` |
